# 実装可能なソルバー仕様

作るものは実装を拘束する決定と確認方法。要望のQA、採用文献名、API名、図の存在だけで実装可能とは判定しない。

## 欠落を洗い出す

1. 要求する観測量から逆向きに、回復→確定状態→離散残差→未知量／拘束→物理モデル→入力をたどる。
2. 逆に入力から、幾何・材料→組立→求解→確定→出力／保存へ値と単位を流す。二つの経路が同じ定義でつながるか確認する。
3. 各境界で、何を固定し何が変わるか、どの微分・履歴・ID・所有者・失敗状態が必要かを問う。[仕様の導出](references/specification-discovery.md)で力学・数値・運用の抜けを探す。
4. 正常系だけでなく、ゼロ次元、無荷重、剛体運動、薄肉、歪み、接合、非零平衡、失敗・中断・再開を通し、未定義項目を抽出する。全案件に全項目を強制せず、適用しない理由を記録する。

## 閉じる順序

系全体の数学的問題→結合した離散式・時刻表→主要処理契約→不変条件と参照→数値表現・資源→実装パッケージの依存閉包。独立な項目は一緒に決める。時間法・荷重微分・後流更新・線形化のように相互依存する選定を別々に確定しない。

候補の数学的成立自体が未確認なら、決定的な限定試作を先に行う。一方、採用式・入力・比較方法が固定できた部品の全製品試験を別言語で先に完了する必要はない。

## 契約を記述する

各主要処理に責任、式、配列shape／成分順／単位／基底／時刻、事前条件、必要微分、所有権・可変性・寿命、cache世代、成功・失敗保証、精度、資源、対応ケースを付ける。

高精度内部解と消費側の表現、物理微分と算法微分、元系と縮約系、局所空間と共有後の空間を別の名前で識別する。参照の保持方式から製品の大域密行列を必須にしない。

## 開始判定と引継ぎ

[開始判定・引継ぎ](references/handoff-and-gates.md)を使い、対象パッケージごとに依存を閉じる。方程式・未知量・時刻・返却値を実装者が選び直す穴があれば、その部分は保留する。判定には確認した証拠と未確認範囲を付ける。

開始可能、実装済み、数値認定、実験妥当性、実務受入は別状態。計画の要求対応表とハッシュ監査が通ることは、仕様内容の妥当性や製品性能の証明ではない。

ユーザーが決めた品質・範囲は維持する。内部型の名前や工程の細分化を公開API制約にせず、対象プロジェクトの言語・要素・閾値をこのskillから推測しない。
