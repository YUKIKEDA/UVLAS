# 実装者への引継ぎと開始条件

## パッケージごとに判定する

次の内容が対象処理と接続先について揃うことを確認する。

1. 全体系での責任と、対象に含む式・未知量・必要微分。
2. 単位・符号・配置・時刻・境界・初期化に実装者の推測が要らない。
3. 具体的な入力／返却のshape・所有権・寿命・可変性・失敗保証。
4. 予測・評価・反復・受理・棄却・再開、cache更新の順序。
5. 再構成できる入力、独立参照またはその構成法、観測・事前閾値。
6. 数値依存・系の性質・容量と、方式採否に必要な限定試作。
7. 要求→採用式→処理→不変条件→ケースの意味の一致。
8. 未解決事項の影響範囲と、その影響を受ける処理を止める位置。

マッピングの全行が埋まっていても、観測と参照・閾値が違えば不合格。ファイルの存在・hash・コード内の`passed=true`を上記の判定の代わりにしない。

## 引継ぎの最小形

```text
対象・対象外:
依存するユーザー決定／採用仕様の版・優先関係:
実装する残差／運動学／状態更新:
入力・出力・必要微分・型と単位:
時刻・履歴・トポロジー・親世代:
不変条件と失敗時に保持する状態:
精度の保持／返却／消費者・資源:
入力fixture・独立参照・評価・閾値:
設計実験の成立範囲と製品への移植で新たに確認すること:
残課題・禁止する近道・完了gate:
```

入力fixtureを「この論文の例」「適当な翼」で済ませない。凍結した構成関数を参照する場合も、関数名・引数・依存版・期待観測が追跡でき、旧成果物を上書きせず再生成できる手順を渡す。旧resultをそのまま製品testの合格結果にコピーしない。

## 状態を直交させる

| 軸 | 記録例 |
|---|---|
| 設計 | 草案／候補／採用、適用／拒否条件 |
| 実装 | 未着手／移植中／対象経路を検査済み |
| 数値 | Computed／収束／数値誤差認定／未解決 |
| 参照 | 入手可能／版照合／精度または測定不確かさ認定 |
| 実務 | 対象用途・条件・量ごとの受入／保留 |

用途を持たない単一の「完了」を避ける。最初のパッケージの開始許可を、全ソルバーの実装完了・性能成立・実務適用許可へ拡張しない。

## 見積もりと実装後gate

製品規模の測定を全て実装前に要求しないが、支配項を見落とさない。束縛panelだけでなく後流状態、疎LU fill、全履歴、Arnoldi basis、一時配列、精度fallback、出力／checkpoint、速度探索と再試行を積み上げる。

合成疎行列の10万未知量と、実部材・拘束の10万自由度は別の費用。単一LUの時間から全探索時間を断定しない。未実装の高速化の利益を計画へ先取りしない。成立性が最初の対象に影響するなら、該当する技術試作を前倒しし、影響しない未受入は明示的な後続gateに置く。

引継ぎ後は実装担当がコードを、レビュー担当が仕様との一致と証拠を確認する。仕様自体の矛盾が見つかった場合は仕様欠陥として記録し、相反する条項のどちらかを実装者が黙って選ばない。
