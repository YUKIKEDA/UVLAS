# 0003: R&Dの記録を系統別に並べ、参照を再発行する

- Status: Accepted
- Date: 2026-11-11
- Issue: #1

## Context

実装前のR&Dは、設計メモ165件を `docs/` に、検証記録1,174件を `docs/verification/` に、実験ファイル861件を `tools/design-experiments/` に、それぞれ一つの平坦なディレクトリへ置いていた。採用仕様と不採用候補の経緯が混ざり、製品開発で読むべきものが分からなかった。

記録は互いをリポジトリ相対パスとSHA-256で引用していた。マニフェスト740件のうち396件が他のマニフェストを引用し、連鎖は最大34段。スクリプト842本のうち524本が記録のパスを直に書き、664本が同じディレクトリの別スクリプトをimportしていた。ファイルを動かすと、これらが連鎖して壊れる構造だった。

## Decision

全ファイルを系統別に物理的に並べ直し、参照を再発行する。

- 並べ直す前の状態を、改行変換なしでcommitし、タグ `rd-baseline-2026-11-06` を付ける。旧マニフェストは、このタグで元のパスのまま検証できる。
- 再配置は、ベースラインの純粋な関数として行う（[tools/rd/reorganize.py](../../tools/rd/reorganize.py)）。行き先は [relocation_plan.py](../../tools/rd/relocation_plan.py) の規則が決める。書き換えるのは、リンク先、リポジトリ相対パスの文字列、スクリプトのルートとディレクトリの式、書き換えたファイルを指すSHA-256だけ。
- 製品開発でいま使う文書（要求、採用仕様、開始審査）は `docs/` へ、R&Dの経緯と、役目を終えた計画・台帳は `rd/` へ置く。
- スクリプトは、記録や他のスクリプトを [rd/rd_paths.py](../../rd/rd_paths.py) を通して名前で探す。以後の移動でスクリプトを直す必要はない。
- 新しく作る記録は、対象をIDとSHA-256で指す。パスは手がかりとして添えるだけにする。

## Consequences

- 現在のツリーは、ベースラインに再配置ツールを適用した結果とバイト一致する。`reorganize.py verify --rev HEAD` で再現できる。比較の対象は再配置ツールが書く2,238ファイルで、手で維持する4ページと、動かしていない製品ファイルは対象外。
- ベースラインの2,253ファイルのほぼ全てを移動し、内容を書き換えたものが多い。書き換えたファイルのSHA-256は、ベースラインのものと異なる。同一性の根拠は、ベースラインのタグと再配置ツールの組である。
- 配置の変更は `relocation_plan.py` の変更と `reorganize.py reissue` で行う。実装前の計画と台帳を `rd/planning/` へ移したのも、この方法による。
- 書き換え後のスクリプトを、全て再実行して確かめてはいない。確かめた範囲は [rd/README.md](../../rd/README.md) に書く。
- `build/` にあるコピーを指すハッシュは書き換えていない。そこにあるファイルのバイトは変わっていないため。
- README等の現状表示を書き換える `close_*`、`sync_*` のスクリプトは、過去の一回限りの操作の記録として残す。再実行しない。
