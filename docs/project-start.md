## 1. 目的と既存資料の位置づけ

目的は、実務で利用できる品質のUVLM–ANCFシェル連成ソルバーを開発すること。

「実務で利用できる品質」は、対象業務、解析対象、使用条件、予測対象量、必要精度、誤判断の影響、運用条件と、それを裏付ける検証・妥当性確認の証拠によって具体化する。現時点で実務利用可能な状態にあることを意味しない。期限や工数に収まらない場合は、品質基準を黙って下げず、用途・機能範囲・期限を明示的に見直す。

既存の `uvlm-ancf-oss-development-plan.md` と `uvlm-ancf-software-design.md` は技術的な検討材料として保持する。本書は製品目的と意思決定の履歴を記録する。両文書の全提案を採用したことにはしない。

## 2. 初回実務適用の方針

最初の作業は連成系全体の問題定義と実装前設計。剛体矩形翼の定常VLMは検証ケース候補であり、設計が閉じる前に最初の実装対象へ固定しない。最初の実装パッケージは必要な設計と検証仕様を揃えてから選定する。

### 初回実務適用と内部マイルストーンの区別（確定）

- 初回の実務適用には、静的双方向連成、小振幅非定常応答、フラッタ予測を含める。
- 内部マイルストーンは分割するが、部分機能の完成を理由に公開リリースしない。公開APIの互換性維持を早期に課さず、内部APIは開発中に改訂できるものとする。
- 対応範囲は矩形平板に限定しない。後退・テーパ、複合材、初期曲面、弾性支持等を含む実務対象を要求として具体化する。個々のモデルの詳細・適用限界は未確定。
- 矩形平板は基本的な検証ケースとして使用できるが、製品の実務適用範囲をそれだけで代表させない。
- 初回公開の配布形態はQ26でソース・両OSのCLI・Python wheelに確定。具体的なAPI、対応版、入力形式の安定性方針は設計で定める。
- 構造モデルは、等価剛性・質量を持つ単一シェル面と、外板・桁・リブを組み合わせるシェル構造の両方に対応する（Q6 C）。等価特性の同定・変換機能を内蔵するかは別途決定する。
- 材料は等方弾性と積層複合材の弾性を対象とする（Q7 B）。損傷・塑性等の材料非線形は初回必須範囲に含めない。幾何学的非線形とは区別する。
- 支持条件は完全固定、指定変位・運動、弾性支持、減衰支持を対象とする（Q8 B）。ヒンジ・関節・自由飛行は初回必須範囲に含めない。
- パラメトリック翼生成と外部格子読込みの両方を提供する（Q9 C）。CAD読込み・自動格子生成を要求したことにはしない。
- 検証資源はインターネットで入手可能な公開資料・データと比較コードを基本とする（Q10 A,B）。手元の試験設備、非公開実験データ、外部専門家レビューを利用可能とは仮定しない。公開実験データを用いた妥当性確認の候補を調査する。
- 空力の初回適用範囲は低速・非圧縮・付着流とする（Q11 A）。圧縮性補正、遷音速、剥離の予測は初回必須に含めない。
- 大変形した平衡周りのフラッタと非線形過渡応答を必須にする（Q12 B）。LCOの振幅・周波数の定量予測は初回必須に含めない。
- 利用経路はCLI・ファイル入出力と、Pythonからのケース構築・実行・結果取得とする（Q13 B）。専用GUIは初回必須に含めない。
- 性能設計は単一PC・CPU・メモリ32〜64GB程度を基準とする（Q14 A）。GPU・クラスタは必須にしない。これは開発・計測の基準であり、任意のモデルが同環境で計算できる保証ではない。
- 複数揚力面と各後流、それらの相互干渉に対応する（Q15 B）。胴体・ナセル等の厚みのある物体の空力干渉は初回必須に含めない。
- 励振入力は初期変位・速度、指定運動、突風、時間依存外力とする（Q16 B）。利用者作成の時系列読込みを含め、確率的乱流の生成・統計評価の内蔵は初回必須に含めない。
- 構造出力は変位・反力・断面力・振動特性に加え、ひずみ・応力・積層各層の材料軸成分を含める（Q17 B）。破損指標・余裕率の内蔵は初回必須に含めない。
- 代表的な実務モデルの性能目標は、全揚力面合計で空力約5,000パネル（後流を除く）、拘束適用後の構造約10万自由度とする（Q18 B）。
- 同モデルに対する複数風速での平衡計算・安定性評価を含むフラッタ速度探索全体を、一晩8〜12時間程度で完了することを目標にする（Q19 B）。探索点数・精度・後流保持等を固定した性能試験仕様に具体化し、時間のために精度・収束を緩めない。

旧L0〜L6の小規模VLM中心の工程案は、連成系の設計依存と実装開始条件が不足していたため置き換えた。現在の段階・成果物・完了条件は実装前設計計画P0〜P4に集約する。

実験を使わない段階では、数式・離散化の実装確認や計算解の検証として報告する。実験妥当性確認を完了したとは記載しない。合否許容差の具体値は、対象条件と参照の品質を確認してから設定する。

Grillは機能範囲の回答だけで終了したとは扱わない。言語標準、外部格子形式、ソースコードのライセンス方針はQ20〜Q22で確定した。対応環境・形式の詳細、配布、用途別の精度・受入条件は引き続き具体化する。ユーザー判断が必要な項目は選択肢・推奨理由・メリット・デメリットをチャット本文にまとめ、調査を要する技術方式は根拠付きの設計案として提示する。T01の実装は、これら全項目の確定を意味しない。

技術担当側で候補・根拠を用意する項目：定常VLM定式化、独立参照、初期ケース、数値依存、入出力形式、テスト階層、CI構成。これらを理由なくユーザーの選択問題にはしない。候補の比較と推奨を提示し、対象実務の要求・制約への適合を確認して確定する。

ANCF要素、動的積分、荷重・後流・連成反復・安定性の詳細は設計決定台帳の依存・共同決定群として具体化する。接続先に影響する設計を、個別実装時の判断へ残さない。
