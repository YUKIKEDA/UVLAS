# ソルバー開発知識の入口

この一式は、今回のR&D・設計試作で得た知識を別の実装者・レビュー担当・別プロジェクトで再利用するためのもの。製品本体は別の担当者が実装し、アシスタントは依頼に応じてレビューする。

## 使い分け

| 使う場面 | 再利用するSkill | 主に残した手順 |
|---|---|---|
| 候補の採否が決まらない、検証が長引く | [solver-rd](../../tools/skills/solver-rd/SKILL.md) | 仮説と反例、保存データの再利用、識別実験、未達の分類、研究の終了条件 |
| 要求は合意したが実装仕様が足りない | [solver-design-contracts](../../tools/skills/solver-design-contracts/SKILL.md) | 観測量からの逆算、値の順方向追跡、離散式と時刻・I/F・不変条件・ケース、開始判定と引継ぎ |
| 製品実装・変更・完了主張をレビューする | [solver-implementation-review](../../tools/skills/solver-implementation-review/SKILL.md) | 元系と実消費値、全必要微分・履歴、独立参照、再開・性能、仕様欠陥と実装欠陥の区別 |

各Skillは自己完結したフォルダで、必要な詳細だけreferencesから読む。特定のrepoパス・UVLM／ANCF・言語・許容差・数値依存版を汎用Skillの前提にしない。`tools/skills`が版管理・再配布用の正本。個人用Skillsに配置するコピーも、この正本から同期する。別のエージェントでもMarkdownの手順とRulesを読んで使える。

## 常設Rulesとプロジェクト固有の正本

[SE-01〜14](solver-engineering-rules.md)は品質判断の境界を定める。[UVLASレビュー・プロファイル](uvlas-review-profile.md)が採用仕様・追加規約・ユーザー決定への入口。[AGENTS.md](../../AGENTS.md)から開発・レビュー時に参照する。

[知見と根拠](lessons-and-evidence.md)は、進め方の改善点7件と技術的知見22件を、既存の記録へ対応付けている。成功した手順だけでなく、過早な開始宣言、核心の後回し、現在地の不整合、事前仕様不足、証拠の過大解釈も再発防止として残した。

## 維持方法

新しい失敗・仕様欠陥・レビュー指摘が得られたら、再現条件・根拠・適用範囲を先に記録する。そのうち将来の判断を変えるものだけをSkill／Rulesへ取り込む。単なる記述量の追加を改善としない。技術手順はSkill、常時の境界はRules、製品固有の数式・閾値は採用仕様に置き、正本を重複させない。

更新時はSkill Creatorのfrontmatter検査、ローカルリンク、添付スクリプトの挙動を確認する。今回の検証結果と配置先は[知識パッケージの検証記録](knowledge-validation.md)を参照。構文検査や自己点検を、独立した別エージェントによる行動評価と呼ばない。
