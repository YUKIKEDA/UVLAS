# IM00-2の寸法・資源計画の内部契約

対象はN4-02、Issue #6。既存のID・失敗契約を継承し、寸法計算、外部APIへの変換、確保前照合を具体化する。物理式と受入基準は変えない。

## 決定と確認の対応

すべて整数の厳密比較とし、浮動小数点の許容差や微分は使わない。入力の配列は同期呼出し中だけ借用し、計算結果・失敗・確保した配列は値として返す。モデル、親状態、数値世代を変更しない。失敗には呼出側が指定した処理を保持する。

| 決定 | 入力と返却 | 規約・失敗 | 独立した確認 |
|---|---|---|---|
| IDと添字の分離 | 既存Identifier、Index | 物理・ファイルIDはuint64、Indexはint64。暗黙の相互変換なし | 既存の全ID対の型検査、正のコンパイル対照と8種類の混用のコンパイル失敗 |
| 寸法積 | 非負Index列 → Index | 空の列の積は1。いずれかが0なら積は0。負値はInvalidInput。int64上限超過はResourceExceeded | 既知の小整数、int64上端、平方数の境界、0の全位置、負値と0の併存 |
| バイト数 | 個数、要素バイト数 → size_t | 個数は非負、要素サイズは正。size_t上限超過はResourceExceeded | 既知の24 byte、size_t上端、乗算境界。大きな要求は算術だけを検査 |
| 32bit引数 | Indexまたは寸法列 → int32 | 個別値も積も縮小前に検査。負値はInvalidInput、上限超過はResourceExceeded | 0、2147483647、その次、46340²と46341² |
| 確保前照合 | ResourcePlan、個数 → 所有配列 | 必要バイト数を上限の残量と比較してから確保。超過はResourceExceeded | 小さい予算での累積超過、確保関数・構築回数の観測、ちょうど上限、0 byte |
| 失敗時の予約解放 | 確保・要素構築 → Failure | bad_allocはResourceExceeded、その他の構築例外はInvalidInput。失敗した要求自身は計上しない。内側で成功した要求は保持 | 両例外の注入、入れ子の成功・拒否、失敗後の確保と残量 |

## 空配列と外部API

寸法積は全成分の非負性を先に検査する。ゼロを含む有効な形状は、途中の積を作らず0を返す。これにより、空配列を表す寸法の並び順で成否が変わらない。0×0の系はこの段階で0要素・0 byteとして通る。空の線形系の求解そのものはIM00-6〜8で実装する。

32bitへの積変換は、積が引数となるAPIのためのもの。行数・列数を別々に渡す場合は、それぞれも個別変換で検査する。積が0だからといって32bitに収まらない軸を外部へ渡さない。

## ResourcePlanが計上するもの

一つの準備処理で必要な所有配列は同じResourcePlanを使う。上限は明示的なuint64のバイト数で、暗黙の無制限値は設けない。計上値は成功した配列の要素数×sizeof(T)の累積であり、確保前に必要量を確かめる。寸法・バイト数・累積加算で表現範囲を超える場合も、確保を行わず失敗する。

確保関数や要素コンストラクタが同じ計画へ再入する場合も、成功済みの計上値と処理中の予約の和を上限以下に保つ。要求を受け入れると、利用者のコードを呼ぶ前にそのpayloadを予約する。残量は成功済みの計上と処理中の全予約を差し引いた値とする。成功時は自身の予約を成功済みの計上へ移し、失敗時は自身の予約だけを解放する。内側の要求が成功してから外側が失敗した場合も、内側の成功の計上を過去の値へ戻さない。配列が例外処理中に破棄された場合も、累積計上を返金しない規約を守る。

PlannedBufferは固定長の値初期化済み配列を所有する。空配列には確保を行わず、移動元は空になる。コピーと外部からの拡張を許さない。返すspanは借用であり、所有者の移動・代入・破棄を越えて使わない。所有配列の寿命はResourcePlanの寿命に依存しない。

失敗やキャンセルで解放された配列を、別の準備計画の余裕として再使用することは、この型では行わない。配列を破棄しても計上を戻さず、計画全体が上限内かを保守的に検査する。新たな準備処理では新しい計画を作る。ResourcePlanをコピー・移動して予算を複製せず、同時には一つのスレッドだけが使う。計算の反復中に都度確保する設計には使わない。

計上対象は配列のpayloadのみ。アロケータの管理領域、配列cookie、ライブラリ内部の分解領域、プロセスの基礎メモリは別に見積もる。48GiBのプロセス上限をpayloadの上限と同一視しない。IM00-12でプロセス実測と計上値を並べ、各consumerが使う外部ライブラリの領域は対応パッケージの資源計画へ含める。

予算照合は残量との比較で行い、上限を超える和を先に計算しない。診断のrequiredは要求自身と、それ以前に成功・予約済みのpayloadの和、observedは要求を受け付けた時点の成功・予約済みpayload。要求後の和をuint64で表せない場合は資源欄を省略し、飽和した偽の数値を記録しない。上限自体はResourcePlanから取得する。

## 検証の範囲

巨大な配列は作らず、巨大寸法は検査付き算術か小さな予算で拒否させる。性能、物理ソルバーの精度、外部ライブラリのメモリ使用量、全実務ケースの受入を、この型の試験成功から主張しない。
