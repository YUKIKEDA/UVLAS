# 外部メッシュの対応表と元物理量の照合

設計審査 #333。双方が明示した材料・厚さの不一致をエラーとする利用者決定を前提に、版付き対応表と選択規則を定める。

[FD-03](case-schema-fields.md#fd-03-幾何と外部source) と [IO4-03・IO4-04](io-execution-adoption-specification.md#io4-03-nastran系の限定読込み) のインポーターは、認証済みの外部メッシュまたはデッキを、検査済みケース内の明示された物理定義に結び付ける。元入力とケースの双方が同じ物理量の材料または厚さを明示したときは照合し、不一致を入力エラーとする。照合のために元入力またはケースの値を書き換えない。

## 入力の組と所有

対応表は UTF-8 JSON。版を識別する `schema` を必須にし、同じオブジェクト内の重複キーと未知キーを拒否する。辞書の `Id<T>` と同じ十進文字列を使う。Nastranの識別子も十進文字列とし、対象カードの正値制約に従う。Gmshの物理タグはnative整数の正のint32、次元はnative整数0～2。型を跨いだ数値一致で名前空間を解決しない。

受渡しは `SchemaCase` と、その親の `SchemaIdentity` で取得した対応表スナップショットおよび元スナップショットの組。同じケースの Geometry の `FileRef` に対して `SourceId`、役割、元バイトのSHA-256を照合する。実体を開き直さない。ケース中の `Geometry` 参照はスコープを与える。外部Geometryのほかに明示済みのPG幾何がケース内にあり、対応先Shellがそれを参照する場合は、その参照を維持する。対応表とケースの名前空間は同じであり、対応表に別の材料・支持・接続レジストリを作らない。

対応表には外部ファイル参照を置かない。Gmshで別に供給する参照幾何は既存の `GeometryGmsh.reference` を通す。Nastranの `INCLUDE` は採用済みカード範囲の外にあり、対応表で新たに探索対象へ加えない。

## 外部面の対応

Gmshの `uvlas.gmsh-sidecar/1` は `schema`、`geometry`（対象のケースGeometry ID）、`length`（FD-01の長さ単位）、`shells`、`supports`、`joints` を持つ。面の各行は `physical`（`dimension` と `tag`）、`shell`（ケースShell ID）、`faces`（元面とPGチャートの対応）を持つ。面は次元2の物理グループとし、取得済み `$Entities` の所属を使って元の三角形・四角形のタグへ展開する。`$PhysicalNames` で識別しない。`supports` の各行は `physical` と `support` を持つ。`joints` の各行は `first`、`second` の二つの `physical` と `joint` を持つ。これらはケースの対象領域の出典を指定し、支持・接続の自由度や向きはFD-05の対象と選択の対応を準備で照合する。グループに属する要素が実際の面に接しているかも確認する。

同じ面の材料または厚さの情報が外部で独立に明示された場合は、`shells` の行に任意の `material_layers` と `full_thickness` を持たせる案を採る。`material_layers` は `layer` と `material` のIDの列で、ケース層順で同じ層・同じ材料参照を要求する。`full_thickness` はそのグループ全体に適用される正の長さである。MSH 4.1の現在の採用節には材料と厚さの数値欄がないため、物理名や未知の `$ElementData` に意味を付けない。Gmshの新しい材料定数のファイル形式を増やす必要はなく、材料の数値定義はケースのFD-04を使う。

Nastranの `uvlas.nastran-sidecar/1` は `schema`、`geometry`、`generator`（空でない元デッキ生成元）、`units`（FD-01の単位）、`shells`、`materials`、`beams`、`masses`、`supports`、`joints` を持つ。`shells` の各行は `element`（CTRIA3/CQUAD4のEID）、`shell`、`chart` を持つ。`materials` の各行は `mid`（MAT1/MAT8のMID）と `material`（ケースMaterial ID）を持つ。PIDの共用は面の所有を決めない。`GeometryNastran.dialect` が元カードの意味を決める。角度カードに明記された度の規約を `units.angle` によって変更しない。`beams` は CBEAM の `element` と `beam`、`masses` は CONM2 の `element` と `mass`、`joints` は RBE2 の `element` と `joint` を持つ。`supports` は採用したセット `set`、展開後の GRID の `grid` と `components`、対応先の `support` を明示する。複数セットやデッキの解析制御から採用セットを推定しない。ケースの支持運動、剛体接続の点とフレーム、梁・質量の物性はケースの対応先で保持し、同じ物理量として対応することを準備で照合する。

`components` は元の座標軸に従う1始まりの JSON 整数配列とする。1から6の範囲で一つ以上の成分を昇順に並べる。重複、範囲外、文字列、整数単体は拒否する。同じ `(set, grid)` の行は一つとし、元セットの SPC と SPC1 を展開してその GRID に適用した成分の和集合に完全一致することを要求する。対応する Case 支持成分は FD-05 と GRID の変位座標系に従って照合する。

対応の展開時に未定義、空の選択、重複、面の所有競合を検査する。同一シェルの複数の面は元の面の順序と向きを保持し、面の連結成分と自由境界の検査へ渡す。対応の成功が示すのはID、元面と検査した物理量の整合までである。参照曲面、一貫した材料軸、剛体仕事、独立荷重の反力・変位などのR-05受入は準備で検査する。


## 原要素から既存のPGチャートへの対応

元ファイルが離散化した面と、解析に使う連続面の関係を記録する。対応先は `Shell` からたどる既存の `Geometry.pg` であり、caseのチャート、法線、全厚、層区間を外部面で置き換えない。原要素ごとの `chart` に `vertices` と `orientation` を置く。`vertices` は元要素の節点順と同じ順序で、各節点の厳密な $(s,t)$ をFD-03のRationalで与える。`orientation` は `same` または `reversed`。三角形には3点のアフィン写像、四角形には4点の双一次写像を使う。元の四角形を暗黙に三角形へ分割しない。Gmshの各シェル行は同じ物理グループ内の `faces`（原 `element` タグと `chart`）を明示する。グループを複数のPGパッチに分ける場合も、面ごとの対応を記録する。Nastranのシェル行は明示 EID に対応する `chart` を持つ。

面の選択は重複も欠落もなく対象を覆い、各チャートに写した原面の内部も重複・欠落なく指定された活動領域を覆う。同じ面側で共有する元節点と辺は、原ID、向き、境界のパラメータを照合する。隣接パッチの座標は同一とは限らないため、別のチャートをまたぐ辺は既存の共通境界規約で検査する。材料・厚さの段差を持つ境界では両側を別に保持する。同じ座標の異なる元節点を近さで併合しない。

Gmsh では同じ `physical` を複数の `shells` 行に置ける。各行の `faces` はその物理グループに所属する元要素の非空部分集合とする。グループの被覆は行を集めて検査する。行間で要素タグが重複せず、全行の和集合が `$Entities` からの展開結果に等しくなければならない。各 PG 活動領域の被覆は、対応する Shell へ割り当てた全原面を使って検査する。

例えば物理グループ `{dimension: 2, tag: 7}` の展開結果が `{701, 702}` のとき、同じ `physical` を持つ二行で `701` を Shell `21`、`702` を Shell `22` へ割り当てられる。片方の行が空、`702` が欠落、`701` が両行に出現、または別グループの `703` が混入する割当は拒否する。

正則性、全域被覆、向き、境界、保持した元点の対応を検査する。平面のアフィン対応は元面とPG写像を同じ座標で表して厳密に検査できる。曲面や非平面四角形は同じ節点を持つだけでは同一と認定できない。利用する参照面と外部の離散面の関係はIO4-04の数値予算と独立観測で検査し、座標差・法線差・厚さを伴う物理量を報告する。合格した幾何の近似誤差を、材料・厚さの別宣言を見逃す許容差へ流用しない。

CaseのGmsh `ReferenceGeometry.fit` がある場合は、その距離・法線の許容値と変換観測を使う。曲面を供給するGmsh `supplied` またはNastranで厳密対応を証明できない場合は、対応表の任意の `conversion` に `distance_budget`、`normal_budget`、`conversion_observations` を明示する。型と正値条件はFD-03の同名欄を使う。距離はCaseの長さ単位、法線予算は無次元、観測はCaseの `Ref<Observation>` とする。Caseの `fit` と対応表の `conversion` の二重宣言を拒否する。`supplied` の参照ファイルとケースの既存PGがともにある場合は同じ参照領域を照合する。許容値と変換観測がなく、厳密対応も証明できなければ物理準備を成立させない。変換予算は面の写像を検査するために使い、既存PGは保持する。厳密に一致した面でも、質量・重心・慣性、剛体仕事、独立荷重、固有モードのR-05受入を維持する。

同じ参照領域を覆うと認定してから、全厚・層厚を共通チャートへ写す。区分一次同士では、両分割の正確な共通細分を作り、全片の頂点で厳密な差を零と照合する。双一次または他の採用形が含まれる場合は、同じ片・パラメータ上で表した差の係数などから全域の一致を検査できる場合に比較する。各片の片側値を保ち、段差の両値を別に比較する。法線が反向の場合は層順、材料軸、offsetと接続側を同じ変換で照合し、元値と変換の両方を記録する。同じ領域・層・式へ対応したことが証明できなければ比較の資格がない。

役割検査から返す所有記録は元要素、元節点順、Case ShellとPG、側と向き、出典を持つ。タグ対応の成功、チャート被覆、R-05の幾何・物理準備は別の結果段階とする。

## 材料と厚さの一致

材料のケースIDは名前空間付きで照合し、同じ数値の外部MIDとケースIDの偶然の一致を使わない。ケースShellの層が参照するMaterialと、外部の材料対応を、同じ対象・層・物理的意味で比較する。MAT1のE、G、ν、密度は、明示欄をケースの等方定義またはそこから一意に閉じる等方Gと照合する。MAT8の既知の面内定数、横せん断定数、密度は、対応する `orthotropic3d` の明示欄と照合する。E3や相反コンプライアンスの不足分を輸入側で推定しない。PCOMPの実現した層順と材料対応は、同じ法線・層順のケース定義で照合する。PSHELLの膜、曲げ、横せん断、連成の指定は各用途として保持し、等価性の判定に渡す。

厚さの比較は、同じ物理領域に対して明示した全厚または対応した層厚に限る。PGの `thickness.values` は物理全厚であり、参照長やζを掛けない。外部が全領域の一定全厚を定義し、同じ領域を表すケースの区分一次全厚がある場合は、その全頂点で厳密一致を要求する。角別の厚さや異なる分割で記述された変動厚さを照合する前に、外部面、物理点、法線、ケース厚さ場の対応を認定する。平均、部分的な頂点照合、近接座標で代用しない。

双方の明示された同一量はFD-01の厳密単位倍率を適用して比較する。正規化十進値をbinary64に丸めて比較したり、許容差を設けて別の宣言を受理したりしない。明示されていない欄と明示零を区別する。別の意味の欄（PSHELL繊維距離、シェルoffset、非構造質量等）は全厚や材料定数へ重ねない。明示値の対応が未認定なら一致の判定を返さない。

## 結果、診断、検証

結果は親識別、外部SourceId、両ダイジェスト、元の型付きID、ケースの対応先IDと、比較に使った出典を所有する。診断は対応表内の位置、判明した外部タグまたはカード内の位置、ケースの対象ID・資料所在を持つ。対応表や元ファイルの不整合は `PrepareModel / InvalidInput`、未対応表現や同一量の照合が成立しない形は `Unsupported`、資源上限は `ResourceExceeded`、取消は `Cancelled` とする。失敗で部分対応を公開しない。

対応表のバイト、JSON構造、対応宣言数、展開数、元タグ走査、厳密比較、診断、所有と一時領域を独立に制限する。配列は宣言順、同一Gmsh選択の展開は元要素タグ昇順とする。初出の不一致を報告し、診断枠不足で失敗理由は変えない。

試験では、疎なタグと同数値の別次元タグ、別のケースで同じID、未知の元タグ、重複対応、複数面と層順、元ファイルが失われた後の読取りを照合する。独立した有理数換算で mm/m の同値厚さと、一語丸めで隠れる不一致を作る。Gmsh側では明示された材料・全厚、Nastran側では対になるPSHELLまたはPCOMPとMAT1またはMAT8の明示欄を変え、同じエラーになることを確認する。ケースを未変更のまま再評価できることと、上限ちょうど・一件不足・取消を確認する。
