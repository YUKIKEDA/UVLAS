# Gmsh MSH 4.1 ASCII のメッシュ入力

IO4-04のメッシュ読取りは、取得時にダイジェストを照合した `gmsh-msh4.1-ascii` のスナップショットを入力とする。読取り後にパスを開き直さない。結果は宣言元、元のダイジェスト、メッシュのバイト列、解決済みのタグを所有する。座標、境界箱、パラメータ座標は元の十進字句を参照し、単位や丸めを導入しない。 [Gmsh 4.15.0 公式仕様の第10.1節](https://gmsh.info/doc/texinfo/gmsh.pdf)

| 節 | 保持するもの |
|---|---|
| `$MeshFormat` | 版4.1、ASCII、4または8のproducerサイズ。サイズ欄を座標精度に使わない |
| `$PhysicalNames` | 任意。次元とタグ、引用符内の元バイト列 |
| `$Entities` | 任意。次元とタグ、点座標または境界箱、同次元の物理グループ、下位次元の境界タグと向き |
| `$Nodes` | 必須。疎な正のタグ、所属、元の三座標。parametric指定時は次元数分の座標を追加 |
| `$Elements` | 必須。正のタグ、所属、点15・一次線1・一次三角形2・一次四辺形3と、元の節点順 |

繰り返した節のレコードも合わせて照合する。物理名・幾何実体は次元とタグ、節点・要素はタグの昇順で取り出せる。節点と要素のヘッダーについては、宣言した個数と最小・最大タグを各節内の実データと照合する。重複ID、未定義の節点、要素と所属の次元不一致を拒否する。`$Entities` がある場合は、所属と境界の実体も照合する。物理名と実体は独立した任意節である。実体がなければ所属キーまで保持し、物理グループの所属を補わない。

実体と物理グループのタグは、定義と参照の双方で正の32 bit符号付き整数の範囲を要求する。向き付き境界は符号を分け、絶対値を同じ範囲で検査する。節点・要素タグと接続が参照する節点タグは正の64 bit符号なし整数として保持する。

binary、別版、高次・体積要素、分割・ghost・周期および未対応節は `Unsupported` とする。破損した字句、要素数の食い違い、無効な参照は `InvalidInput` とする。字句エラーはバイト位置を、節全体を読んで確定したタグ不整合は末尾位置を診断に残す。

## 計画と失敗

1回目の走査で節の字句・個数・宣言範囲を検査する。元バイト列と5種類の固定配列の累積容量を同じ `ResourcePlan` に収めてから確保する。2回目はコピーした元バイト列から、予約した配列を埋める。元バイト列、字句の再読、コピー、ソートの比較、タグ解決を作業枠に含め、容量不足と取消を区別する。ソートの比較回数は使用する標準ライブラリに依存する。

節点・要素の上限は格納するレコードの総数に適用する。空ブロックのヘッダーも入力バイトと走査の作業枠に計上する。ブロック数から配列を確保する処理はない。

材料、部材、支持、接続、長さ単位、参照曲面はsidecarとケースの対応が必要である。この結果を外部モデルの準備成功へ変換するには、その対応の照合を通す。参照グラフ全体の完了には、他のroleも含めた依存宣言の検査が残る。
