# チェックポイントのマニフェストとチャンク集合

[IO4-06](io-execution-adoption-specification.md#io4-06-checkpoint) のファイル名、型、照合順を定める。準備済みモデルの指紋の生成と、J1のフィールドを各チャンクに割り当てる規則は、使用側の契約で定める。

## ファイル形式

`manifest.json` はBOMなしのUTF-8 JSONとし、最上位の4項目を必須とする。未知の項目、重複したJSONキー、文書末尾の余分な値を拒否する。

| 項目 | 内容 |
|---|---|
| `schema` | `"uvlas.checkpoint/1"` |
| `byte_order` | `"little"` |
| `fingerprints` | `model`、`basis`、`material`、`constraint`、`algorithm`、`precision`、`version` の7項目。各値はSHA-256の32バイトを64桁の小文字16進で表す。 |
| `chunks` | 1件以上のチャンク宣言の配列。各宣言は `name`、`dtype`、`shape`、`bytes`、`sha256` を持つ。 |

`name` は先頭がASCII小文字で、以降はASCII小文字、数字、ハイフン、アンダースコアを許す。長さは1～64バイト。ファイル名は `chunk-<name>.bin` に決まる。パス区切り、ドット、空白、大文字、制御文字をチャンク名として許さない。同じ名前を複数宣言できない。

`dtype` は `"f64"`、`"i64"`、`"u64"` のいずれか。`shape` の各軸は非負の64ビット符号付き整数の範囲とし、軸0個は要素1個、長さ0の軸を含む場合は要素0個とする。`bytes` は非負のJSON整数で、形状の積に8を掛けた値と等しい。`sha256` はチャンクのファイル全体を対象とし、指紋と同じ表記を使う。書出しはチャンクを名前順に並べる。読込みは文書の並び順にかかわらず同じ名前順で返す。

## 照合と所有

受信側は、現在の準備済みコンテキストから得た7項目を渡す。読込みは文書の構文、版、バイト順、照合用指紋を検査してからチャンク宣言を得る。名前、型、形状、長さと全体の上限を検査した宣言を独立して所有する。

復元時は、開いた確定ディレクトリを同じハンドルで上限付きで列挙し、`chunk-*.bin` の名前と宣言を突き合わせる。欠落、余剰、重複、宣言との名前不一致を拒否する。大文字小文字が異なるチャンク名も拒否する。各ファイルの長さとSHA-256を照合し、すべてを通過したときに型付きチャンク集合を返す。

未対応の版・バイト順・型と指紋の不一致は `CheckpointIncompatible`、宣言とデータの不整合は `CheckpointCorrupt`、上限超過は `ResourceExceeded` とする。取消と不成立で部分集合を返さない。JSONのバイト数・構造、宣言数、軸数、個別・総ペイロード、確保量、各確定ディレクトリの列挙件数には呼出し側の上限を使う。列挙件数にはマニフェストとチャンク以外の名前も含め、OSが返す `.` と `..` を除く。

## 確定ディレクトリ

確定名は `checkpoint-<番号>` とし、番号は先行ゼロのない符号なし64ビット十進整数で表す。0も使える。一時保存名はこの形式に含まれない。確定番号を指定して読む場合も、この形式のディレクトリに限り、配下のファイルは同じ開いたディレクトリを起点に取得する。

最新を探す場合は、呼出し側が選んだ親から上限付きで候補名を取得し、番号の降順にマニフェストとチャンクを照合する。破損または現在のコンテキストと非互換の候補は除き、予算切れや取消はその時点で返す。確定した各候補は独立して照合し、異なる番号からチャンクを混ぜない。
