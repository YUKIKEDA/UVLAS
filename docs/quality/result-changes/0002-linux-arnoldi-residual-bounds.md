`eigen-arnoldi` の実8次作用は、回転ブロックの解析根 ±4i と、二進係数の対角成分を持つ。明示したseed、尺度1、nev=2、ncv=8を使い、実返却pairを元作用で認定する。異なるOSの実測値が一致しないため、QA-07に従ってケース単位の認定を記録する。Windowsの既存基準は変更しない。

## 原因と変更範囲

保存する8量のうち6量はビット一致した。2個の固有値の実部・虚部4量と、それぞれの正規化上界2量である。異なるのは、各pairの原残差認定が返す保守的な上界2量だけである。

WindowsはMSVC 19.51と `/fp:strict`、LinuxはGCC 14.2と `-ffp-contract=off -fno-fast-math` で実行した。固定したEigen 5.0.1、Spectra 1.2.0、Boost 1.92.0を使う。QA作用・seed・数値式・要求予算は同じで、上界の差はこの実行環境間の比較で観測したものである。

原残差上界は、実際の返却vectorと元作用の両語から `assess_pair_metrics` が計算し、QA入口がその `Achieved.upper_bound` を保存する。固有vectorの成分自体はこの8量に含まれないため、上界の差を特定のvector成分や単独の数学関数の差へ帰属させない。両環境とも、実返却値に対する原残差認定と独立参照の数値試験を通過した。環境間で保守上界のビット一致を要求することや、上界を揃えるために値を丸めることはしない。

Windows基準の実行元はclean commit `c829cd28a9c56325efcdcc79848ea17409e24259`。Linuxはhead `dd10c0d4743825349929c20196d77338c44af30c` の実CIである。この間のArnoldi製品sourceの差分は、GCCのshadow警告を除くコンストラクタ引数名の変更だけで、初期化値・順序と数値処理は不変である。QA作用のsourceにも差分はない。

## 数値予算との比較

両OSで要求した原残差予算は1e-12である。Linuxの上界は4.373463352010216e-15、予算の0.4373463352010216%であり、予算を満たす。環境間の上界差は予算の0.05951321766890075%である。正規化の要求予算も1e-12で、両OSの同じ上界が合格した。

実返却固有値と解析根 ±4i との複素絶対差は、両OSとも約1.7837931047801417e-15である。この照合は固定した解析例の結果であり、一般の非正規問題に対する前進誤差の保証へ読み替えない。許容差・反復設定・微小成分・符号は変更していない。
