# IM-06 元面の正面積領域ごとに外部厚さを照合する

認証済みの Gmsh と Nastran の平面を、同じ Case が所有する PG に結び付ける。明示した厚さは、その元面が覆う領域で比較する。[FD-03 対応表の契約](../../specs/foundation/external-mesh-sidecar-contract.md)

## 共通細分の全頂点で厳密値を比べる

PG の活動三角形と元面の凸なチャート多角形を、被覆検査と共通の有理数クリップで交差させた。元面が四辺形なら元の四辺を使う。線や点で接するだけの交差は、厚さ照合の対象から外した。正面積の交差内では Case の厚さと一定の外部厚さの差がアフィンになるため、全頂点で差が零なら全域で一致する。結果は元要素、向き、厚さの出典、比較したチャート面積を所有する。

独立試験の単位正方形は、PG の対角線で異なる厚さの三角形に分かれる。片側の厚さは1 m。隣の三角形では、共有辺の1 mから反対側の頂点の2 mまで厚さが変わる。先の三角形だけに厚さ1 mを宣言すると一致し、比較したチャート面積は1/2だった。元面の向きだけを逆にしても同じ領域を照合した。別の対角線で張ると申告した面が変動厚まで覆うため、元要素と厚さが一致しない Case の三角形を報告した。実際に参照する Case 頂点の上限ちょうど、一件不足、別の PG、取消も検査した。

## Gmsh は物理グループ、PSHELL は PID ごとに処理する

Gmsh では同じ物理グループを複数行へ分けても、グループ全体に同じ明示全厚を適用する。片方の行にだけ指定しても両面を確認した。別グループに属する未宣言の面の厚さが変わっても、宣言済みの面は合格した。同じグループの値を250 mmと251 mmにすると、後の宣言を報告して対応を拒否した。

Nastran は同じ PID の SI 換算と材料照合を一度にまとめ、元 EID ごとに明示 T の領域を比べる。厚さ欄が空の別 PID では、その面に対する厚さ比較を求めなかった。同じ面の PSHELL に T を追加すると、区分一次の Case 厚さとの差を元の T 欄付きで検出した。実ファイルの試験は Case の単位と枠から所有 PG を作り、対応表、元メッシュ、Case の来歴を保ったまま比較した。

異なる PCOMP を同じ Case PG の部分領域へ割り当てる比較、角別厚さ、双一次の厚さ場は追加の照合を要する。

## 検証に使った構成

対象ソースは `8f3250760f34e247b66715560fa30fcc068f8f24`。Windows 11のMSVC 19.51.36260 DebugとRelease、Ubuntu 24.04のGCC 14.2.0 ReleaseおよびDebug（ASan・UBSan）で、`io.external_pg_regional_thickness`、`io.external_planar_pg`、`io.nastran_laminate_cards`、`io.reference_input` が各4件合格した。独立試験は59アサーション。実ファイルの対象ケースは751アサーションだった。

隔離コピーで正面積の条件を外すと、独立試験の成功対照2件が失敗した。ソースを戻すと59アサーションが再び合格した。
