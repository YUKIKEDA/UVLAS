# IM-06 認証済み対応表から元面と明示物性を照合する

Gmsh と MSC Nastran の版付き対応表を、検査済み Case の Shell と PG へ結び付ける。同じ物質座標へ写した平面が対象となる。面の全域が一致すれば、明示された材料と全厚を比較する。[FD-03・IO4-03・IO4-04 対応表](../../specs/foundation/external-mesh-sidecar-contract.md)

## 実ファイルを消した後も元の要素順を保持する

試験は一時ディレクトリに書いた Case を読み、対応表と MSH または BDF を各 FileRef の SHA-256 で照合する。対応表の閉じた JSON 検査を通し、対応表が子ファイルへの参照を持たないことを確認してから参照グラフを閉じる。元ファイルを削除した後は、同じ参照グラフが保持する認証済みバイトを使う。Case は同じ ID を持っていても、元バイトが異なると受け付けない。

Gmsh では物理タグ 7 を面と線の両方に割り当て、次元ごとに識別した。面の所属は元の `$Entities` から展開し、同じグループに属する二面を別の行に割り振った。面の不足、面の重複、別グループの面、存在しない次元の指定を変えると、それぞれ該当する行で拒否した。Nastran では元 EID と GRID の並びを保持し、SPC と SPC1 を含む SPCADD の成分を照合した。元集合の一成分を外した対応は拒否した。同じ SID の直接集合に別成分があるデッキでも、SPCADD の部員から得た成分だけを使った。

未知の欄、同じ形式の未対応版、分母が零のチャートを参照グラフに入れなかった。結び付けの処理では、展開面数と作業上限ちょうどの成功、一件不足の失敗、事前取消を検査した。

## 平面の全域対応を確認してから厚さと材料を比較する

二枚の三角形で単位正方形を覆う。平面 PG の値は $(s,t,0)$。元節点の位置を、対応する材料座標で照合した。Gmsh は mm、Case は m で座標と厚さを与え、同じ物理量を SI で照合した。Gmsh の `250` mm と Case の全頂点の `0.25` m は一致した。対応表の厚さを `250.0000000000000000001` mm に変えると、最初の Case 厚さ頂点との厳密な差を検出した。チャートも変えた試験では、物理量を比較する前に幾何の失敗を返した。

Nastran は同じ正方形を二枚の CTRIA3 で覆い、同じ PSHELL の全厚と MAT1 の明示欄を比較した。Case の E は `1` Pa で、デッキの E を `1.0000000000000000001` Pa に変えると元カードの欄を報告した。どちらの差も binary64 に丸めると消える。

曲面の変換予算と独立観測、全厚の宣言が領域の一部だけにある場合の共通細分、PCOMP の層厚と法線反転、支持・接続等の物理準備は後続の照合に残る。検証は非公開の C++ 入口で行った。

## 検証に使った構成

ソースは `62f7727108c0ed895fe9d27daa05b0b7f9de005d`。Windows 11 x64 の MSVC 19.51.36260 Release と、Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）で、`io.reference_input` と `io.nastran_laminate_cards` がそれぞれ合格した。新しい実ファイル試験は両環境で300アサーション。既存の材料・厚さ試験は7ケース、441アサーションだった。変更した翻訳単位は Linux のコンパイルデータベースで clang-tidy 21.1.1 を通した。統合側の MSVC Debug では標準ライブラリのイテレータ補助領域が計上済みの一時容量を超えたため、統合側で一時領域の確保方法を修正する。

先行のソース `7161c73bdce309b515fb1a8fbc9523f61eaa74b5` の隔離コピーで、材料と厚さの厳密比較を外した。Gmsh の厚さ差と Nastran の材料差を拒否する2アサーションが失敗した。比較を戻すと、実ファイル試験の300アサーションは再び合格した。
