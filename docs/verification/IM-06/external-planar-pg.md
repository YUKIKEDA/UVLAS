# IM-06 外部面と既存PG平面の厳密対応

`ExternalPlanarPg` は、Gmshの選択済み面または型付きNastranシェルを、呼出し側が指定した準備済みPGの活動領域へ照合する。元の要素・節点順、側と向き、座標の元バイト位置、SIの位置、厳密なチャート座標、元バイトとPGの識別情報を所有する。[IO4-03・IO4-04](../../specs/foundation/io-execution-adoption-specification.md#io4-03-nastran系の限定読込み)

## 全域照合

準備済みPGの高さが一次以下であることを先に確認する。面中央の写像 $F(s,t)=o+LQ(x_0+w s+a t,t,f(s,t))$ はアフィンである。外部の長さ単位を厳密倍率でSIへ移して、各原節点が宣言順の $F(s,t)$ と一致することを検査する。

三角形はアフィン写像で、四角形は元の四隅順の双一次写像で扱う。四隅でのヤコビアンの符号を同じ向きに揃えると、双一次写像の行列式は各変数の一次式であり、全域で正になる。正則な凸多角形の原面を保持し、面を追加の三角形へ分けない。

元面をPG共通分割の各三角形と厳密に交差させる。交差面積の合計が元面の面積と一致すれば、各元面は活動領域内にある。元面どうしの正面積の重複を排除し、すべての元面の面積の和を活動領域の面積と照合する。閉じた正面積の多角形が有限個であるため、この三条件で活動領域の閉包が覆われる。接する辺は重複面積を持たない。座標の一致による節点IDの併合は行わない。

## 独立対照

切断したチャートの四隅は $(0,0),(1,0),(1,1/2),(0,1)$。長さ2 m、原点$(1,2,3)$ m、巡回回転とスキューを持つ平面から、物理座標を $(3/2+s/4-t/4,5/2+4s-t/2,3+2t)$ m と独立に求めた。元から四角形のMSHとBDFをmmで書き、逆向きのGmshと正向きのNastranから同じ物理面を得た。両方の元ファイルの所有者と目的PGを離れた後も、各形式の元順と座標は保存された。

代わりの二三角形は共有辺を含めて同じ全域を覆う。一方、別の二三角形は面積 $1/4$ と $1/2$ を持ち、合計 $3/4$ が元の領域と同じでも内部が重なる。面積の和だけでこの入力を受理しないことを確認した。四隅がすべて活動領域に入っていても辺が凹部を横切る場合を拒否した。ほかに、部分的な被覆、チャート外、折り返した四角形、宣言順／向きの不正、binary64では隠れる節点位置のずれ、別ダイジェスト、容量と取消を照合した。曲面に足した $(s^2-s)/10000$ は四隅で消えるが、平面の証明では明示的に失敗した。

## 適用範囲

この検証時点のNastranアダプターは基本CartesianのGRID位置を用いた。有理数で正規化できるCORD2Rと非零ZOFFSへの拡張には別の検証記録がある。[Nastranの位置座標と平面オフセット](nastran-planar-placement.md)非基本の位置座標、物理offset、層と厚さの意味、いくつものチャートをまたぐ対応は準備の組み立て側で扱う。外部IDをケースのShellへつなぐ版付きsidecarは設計審査に従う。共通三角形との交差および元面対の走査は作業上限を持ち、実務サイズでの性能認定は後段で行う。

## 実行結果

ソース `72004c2cf8d21a43f13c20476b3e380325d9d028` をWindowsのMSVC 19.51.36260 DebugとUbuntu 24.04.5のGCC 14.2.0 Debug（ASan・UBSan）で実行した。`io.external_planar_pg`、`io.gmsh_surface_topology`、`io.nastran_shell_cards` の各3件が合格。新しい照合は両環境で2ケース・70アサーション、乱数種142。Linuxのclang-tidy 21.1.1 とclang-format 21.1.2を通過した。別の有理算術で、原寸4点、被覆、重複面積 $1/6$、凹部、曲率項を確認した。

Linuxの分離コピーで別IDの面どうしの重複を許すと、等面積の偽被覆が通り、対象ケースの19アサーション中1件が失敗した。原状へ戻して対象を再実行し、合格した。
