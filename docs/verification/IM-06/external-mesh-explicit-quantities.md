# IM-06 外部メッシュの明示物性とNastranデッキの所有

対象ソースは `ff5aeab178a215d34faaaf32bdb4cb689820f8b0`。外部メッシュ対応表の版と語形は別の採用審査で扱う。[対応表の設計案](../../specs/foundation/external-mesh-sidecar-contract.md)

## 材料と厚さ

認証済みの元デッキを既存インポーターで読み、MAT1・MAT8の明示欄とケースのFD-04材料を比較した。デッキは mm・t・s、ケースは m・kg・s を使った。別に計算した200 GPa、80 GPa、7850 kg/m³ と、MAT8の異なる3せん断定数を照合した。Eを `200000.0` MPa から `200000.00000000001` MPaに変えると、binary64へ丸めると見えなくなる差を元のE欄で拒否した。MAT8の横せん断の差は、G13に対応する元欄で拒否した。

同じ部材領域に宣言した一定全厚の比較では、`0.1` inと各頂点の`0.00254` mが一致した。最後の頂点だけ厳密値をずらすと、その頂点を報告した。同じ比較に実デッキの PSHELL のTを渡し、`2.54` mmを受理した。Tが異なる場合は元カード内の位置を保持した。角別厚さのある要素には一様全厚の判定を返さなかった。Linuxの分離コピーで最後の頂点を照合から除くと、対応する1ケースの6アサーション中1件が失敗した。原状へ戻した対象試験は合格した。

## 認証済みデッキの読取り

ネイティブのディレクトリから実デッキを取得し、既存の単独デッキ検査を通した。試験用グラフの残りの役割は既存のfixtureを使った。ディレクトリとファイルが消えた後、グラフの親・SourceId・役割から、同じダイジェストとバイト列で `NastranBulkDeck` を所有できた。グラフも破棄してから `GRID` の厳密座標と原宣言のJSON Pointerを読んだ。移動で渡す旧入口の回帰、別親・別role、所有に必要な容量ちょうどと1バイト不足も確認した。容量不足では新規計上の前に拒否した。

## 実行結果

Windows 11 x64 の MSVC 19.51.36260 Debug と Ubuntu 24.04.5 の GCC 14.2.0 Debug（ASan・UBSan）で、`io.nastran_bulk`、`io.nastran_laminate_cards`、`io.reference_input` が各3件合格した。材料と厚さを含む既存試験は7ケース・441アサーション、認証済みデッキの新しい回帰は各1ケース・39アサーションだった。各環境の生成ヘッダでソースのコミットと未変更状態を確認した。Linuxのコンパイルデータベースで、変更した製品と試験の翻訳単位に対するclang-tidy 21.1.1の検査も通過した。

面・層に書かれた外部値を選ぶ版付き対応表と、同じ物理領域を覆うことの認定は設計審査と後続の接続で扱う。
