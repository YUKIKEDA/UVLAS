# CLI と Python でケース検査と結果確認を共有する

IO4-01・IO4-02・IO4-05。CLI の `validate` と Python の `load_case`、`case_from_dict` は、同じ C++ のスキーマ検査と外部参照取得を使う。Python は検査済み入力と参照を所有し、CLI と Python の結果確認は照合できた `status.json` の元バイト列を返す。

## 入力の同一性と失敗

ユニコードのファイル名、CRLF を含む入力と結果、参照 SHA-256 の不一致、未対応の参照役割、解決済みケースの改変を照合した。辞書から生成した入力は Python の `Decimal` で独立に組み立てた JSON と SHA-256 が一致し、元の辞書を変更しても保持された同一性は変わらなかった。循環、非有限値、不正な Unicode、非対応の型を拒否した。辞書の符号化では、深さ、文字列と数値のバイト数、ノード数、生成バイト数の上限も検査した。参照グラフの取得順、共有先の再読込み防止、循環と深さ上限は、[参照グラフの検証](reference-graph.md)に記録した。

瞬時観測の時刻窓に `[float(2**63), 2**63]` を与えた。以前の最短十進表記では、同じ時刻の両端を不一致として拒否した。binary64 を厳密な有限十進数に展開すると検査が通った。`10**700` を含むケースは、Python の整数文字列上限を 640 桁に変更しても、ファイルと辞書の両経路で `Nonfinite` を返した。
