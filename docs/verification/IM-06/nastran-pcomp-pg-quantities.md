# IM-06 平面 PCOMP の層境界・厚さ・材料を Case と照合する

認証済みの PCOMP を、同じ平面領域を覆うと確認した Case の PG と照合する。結果は元の PID、MID、厚さと角度の欄、Case の層 ID、認定した物理層厚を保持する。[FD-03 対応表の契約](../../specs/foundation/external-mesh-sidecar-contract.md)

## 元の法線に合わせて層順と界面を反転する

PCOMP は元の法線に沿って底面から層を並べる。明示された Z0 を各層厚の総和 T に対する −T/2 と比較した。空欄の Z0 には同版の既定を使う。要素の ZOFFS は平面対応の検査で扱う。PG の法線が反対なら、元の上層を Case の下層として照合する。各界面は Case の物理座標 Hζ/2 と一致することを求めた。[MSC Nastran 2022.1 Quick Reference Guide、pp. 2764–2768](https://help-be.hexagonmi.com/bundle/MSC_Nastran_2022.1_Quick_Reference_Guide/raw/resource/enus/MSC_Nastran_2022.1_Quick_Reference_Guide.pdf)

元の100 mmと300 mmの二層は、正向きなら ζ=−1/2、反向きなら ζ=+1/2 に界面を持つ。全厚を保ったまま元の幅を101 mmと299 mmに変えると、最初の Case 層の界面で失敗した。SYM の100 mmと300 mmは中央面で鏡映しする。Case が中央面の両側を二層で指定する場合と、中央の600 mmを一層で指定する場合をそれぞれ照合した。厚さを継承する層には、実際に値を書いた元欄を記録した。

PG の区分一次全厚は、正面積の分割片が載る元の厚さ三角形で比較した。アフィンな全厚が正面積の領域で一定なら、その値は元三角形全体で一定になる。Case の活動領域を一枚の三角形に切り詰め、活動領域の外にしかない厚さ値を変えても照合は通った。同じ変更が活動領域にかかる場合は、元の厚さ頂点を報告した。

## 対応表の MID から既存 Case 材料へたどる

実ファイルから作った参照グラフを使い、二面の非対称積層を確認した。下層と上層は MAT1 と MAT8 で、元面の節点順を反転した試験では Case の層順も入れ替えた。元の MID を別の Case 材料へ関連付けると、対応表の行と Case の材料 ID を報告した。MAT8 の E1 に binary64 では消える差を加えると、元の E1 欄で不一致を検出した。

試験は一つの PCOMP が PG の全対象領域を持つ場合を扱った。複数の物性領域の個別照合、材料軸の物理方向、曲面変換、同じ3Dモデルとしての適格性は後続の準備に残る。IO4-03 の採用表に PCOMPG は含まれない。SMEAR など用途別の積層モードには、層の物理的な一致を返さない。[IO4-03 採用表](../../specs/foundation/io-execution-adoption-specification.md#io4-03-nastran)

## 検証に使った構成

ソースは `2e8a6059b31028fa9f2ed76ef37dc2084a85944e`。Windows 11 の MSVC 19.51.36260 Debug と Release、Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）で `io.nastran_laminate_cards` と `io.reference_input` を実行した。いずれも対象2件が合格した。層照合は269アサーション、実ファイルの対象ケースは448アサーションだった。照合の作業・頂点上限と取消を独立試験で確認した。

Linux の隔離コピーで層順反転を外すと、独立試験で2件、実ファイル試験で4件のアサーションが失敗した。元コードへ戻すと269件と448件に復帰した。変更した製品・試験の翻訳単位は clang-tidy 21.1.1 を通過した。
