# IM-06 各 PCOMP を元面が覆う範囲で照合する

認証済みの Nastran 面から、PCOMP が記述する総厚・層区間・材料を、同じ Case が所有する平面 PG と照合する。一つの Shell に複数の PID があっても、各面は元 EID が参照する PID と法線の向きで評価する。[FD-03 対応表の契約](../../specs/foundation/external-mesh-sidecar-contract.md)

## 総厚と層界面を同じ領域で認定する

PCOMP の宣言から、元の層順で SI の層厚を求める。元法線が Case と反対向きなら、既存の層区間照合に従って順序と区間の符号を反転する。Z0 は空欄または総厚の −1/2 を許す。この中心面から測った各界面を Case の正規化層区間に合わせ、同じ層を参照する MAT1・MAT8 の明示定数を照合する。この処理は PID と法線の向きの組ごとに一度行う。

総厚は面ごとに、その面と Case の厚さ三角形が面積を持って重なる範囲で比較する。一定の総厚と Case のアフィンな全厚との差を共通細分の全頂点で確かめる。総厚と正規化層区間の両方が一致すれば、そこで Case の層厚と外部の層厚が一致する。結果は元 EID・元面のチャート・照合した総チャート面積・PID と、PID・向きごとの元欄と Case 層を所有する。不一致時は元面と Case の厚さ三角形を報告する。隣接 PSHELL の厚さも明示されていれば同じ共通細分で確認し、空欄ならその範囲の厚さは比較しない。

## 同じ総厚で界面が違う場合も検出する

実デッキの二つの三角形が PID 90 と 92 をそれぞれ参照し、どちらも 1/16 m と 3/16 m の二層を持つとき、二つの断面と二つの照合領域を所有する。PID 92 だけを 1/8 m と 3/8 m に変えると、層の比は同じでも総厚が増える。元 EID 701、PID 92、比較した Case 厚さ三角形を報告した。PID 92 を 1/8 m の二層にすると総厚は元に戻るが、界面がずれるため元の層厚欄と Case 層を報告した。

別の実デッキでは、PCOMP が厚さ1/4 mの領域を覆い、隣り合う厚さ未宣言の PSHELL の範囲だけで Case の厚さを変化させた。PCOMP の厚さ照合は元面一枚に限って成立した。

適用範囲は既存の平面対応と採用 PCOMP の層表現である。元の ply 角を保持し、材料軸の方向や変換後の独立観測は R-05 の受入で扱う。

## 検証に使った構成

対象ソースは `2f498d9698fa31823058402029bd523a650d9d87`。Windows 11 の MSVC 19.51.36260 Debug と Release、Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）で、`io.external_pg_regional_thickness`、`io.external_planar_pg`、`io.nastran_laminate_cards`、`io.reference_input` が各4件合格した。各構成で、領域厚さの独立試験は111アサーション、実ファイルの対応表試験は1117アサーションだった。

隔離コピーで PID 92 の総厚を比較対象から外すと、総厚が異なる負対照を誤って受理した。元へ戻すと、実ファイルの対応表試験の1117アサーションが再び合格した。変更した翻訳単位の clang-tidy と clang-format 21.1.2 も通過した。
