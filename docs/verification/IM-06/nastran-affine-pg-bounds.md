# IM-06 Nastran 面とPGの全域誤差上界

対象ソースは **92ad8ab064bd68ee499d9075cb9f81c5af7147e8**。[IO4-03とIO4-04](../../specs/foundation/io-execution-adoption-specification.md#io4-03-nastran系の限定読込み) の型付きデッキと既存のアフィンPGを結び、宣言した同じ材料座標における距離と向き付き単位法線の差の上界を、有向丸めで求める。距離はメートル、法線差は無次元の $\lVert n_{\mathrm{src}}-n_{\mathrm{PG}}\rVert_2$ とする。

## 全域の保証と元欄

三角形の元節点は任意の採用CPで基本Cartesianへ移す。四角形は4点が同じ長方形CPに属し、その元十進位置の三重積が厳密に零であるときに扱う。長方形CPから基本系への剛体変換はこの判定を保存する。そのうえで元リングの4隅の符号付きヤコビアンを検査する。双線形写像の二つの接ベクトルの外積では混合項が消えるため、符号付きヤコビアンはアフィンとなり、4隅の値で内部の正値を保証できる。共面の証拠がない四角形、非平面四角形、曲がったPGには別の検証が必要になる。

ZOFFSは元の節点順で決まる単位法線に沿って、符号付き距離として一度適用する。宣言した対応が逆順の場合はPGと比較する法線だけを反転する。向きが同じ側にあることを内積の正の下界で確認する。結果は元の参照位置、ハッシュ、要素欄、CPとGRIDの各座標欄、ZOFFSとその元位置、既存PGの指紋を持つ。

三角形は重心補間、四角形は元の四隅を使う双線形補間とする。四角形を二つの三角形に分けない。PGの物理位置はチャート上でアフィンであり、同じ補間の重みでPG側の点を表せる。どのパラメータでも重みは非負で総和は1なので、位置差のユークリッドノルムは隅の上界の最大値以下となる。元面とPG面はともに平面であり、各面の法線は一定である。元リングから作った有向法線の比較が面全域に適用できる。元面に対応させたチャートの領域・重複・全域被覆には既存の有理検査を使う。

対応の元節点とチャート頂点は面どうしでも照合する。準備結果は元入力を借用せず、失敗時は未公開payloadを解放する。成功した確保はResourcePlanの累積に残す。

## 独立対照と残る受入

試験の平坦PGは $(s,t,0)$ とし、非有理なCORD2Rで元の四角形を45度傾ける。元の+0.5 mのZOFFSを入れた位置は $((s+1/2)/\sqrt2,t,(1/2-s)/\sqrt2)$ になる。距離の最大値は0.5 m、法線差の二乗は $2-\sqrt2$ と別計算し、双方の上界を有理比較で照合した。逆リングでZOFFSの符号も反転した対照、リングだけを逆にした対照、同じ領域を覆う二つの三角形、被覆不足、共面を外した第4点、作業上限を実デッキから検査した。

これは幾何の誤差報告であり、[厳密平面照合](external-planar-pg.md) とは入口と結果の型を分けた。材料・全厚・外部接続も含む変換の受入には、[FD-03の予算と独立観測](../../specs/foundation/case-schema-fields.md#fd-03-幾何と外部source) を別に照合する必要がある。外部面の非局所自己交差や、面間の法線・offsetによる継ぎ目の物理適格性はこの上界で認定しない。

## 実行結果

固定ソースの刻印と変更なしの状態を照合した。MSVC 19.51.36260 DebugとUbuntu 24.04.5のGCC 14.2.0 Debug（ASan・UBSan）で io.external_planar_pg、io.nastran_coordinate_cards、io.nastran_shell_cards の各3件が合格した。平面の主試験は両環境で5ケース・139アサーション。Linuxのclang-tidyとWindowsのclang-format 22.1.3を通過した。

Linuxの分離コピーでZOFFSの移動方向だけを反転すると、距離に関する2アサーションが失敗した。元の式に戻して、平面試験の5ケース・139アサーションが再び合格した。
