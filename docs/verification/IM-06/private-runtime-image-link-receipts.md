# 配置の前と移設の後に拡張の来歴を照合する

Windows と Linux の Release ビルドで、[リンク時の記録から照合用ファイルを作る処理](runtime-artifact-link-receipts.md)を取り込んだ。
同じビルドから作った二つの配置は43ファイルが一致した。別ディレクトリへ移しても CLI が起動し、通常の site-packages から拡張を読み込んで所有権試験10件が通った。

## 同名の拡張と旧コミットの記録を拒否した

別の拡張へ差し替えると、`stage` は CMake を呼ぶ前に終了した。配置先と一時ディレクトリは残らなかった。
移設先で拡張を替え、インベントリの SHA-256 を更新しても、`verify` は生成元の記録との差を検出した。
Windows では別の実 Release ビルドから得た同名の `.pyd`、Linux では印を追加した同名の `.so` を対照に使った。どちらも単独でインポートできることを先に確認した。

いずれの環境でも、拡張の更新時刻を維持して差し替えると、照合用ファイルの再生成にも失敗した。
親ブランチで実際にリンクした拡張と記録の組み合わせも、コミットが異なるため拒否した。Linux では拡張のバイト列が一致していても旧コミットの記録を拒否した。
正規に再リンクしてから [配置と移設の手順](private-runtime-image-producer-review.md)を再実行し、生成した記録を配置と移設で共通に使った。

対象のコミットと実行結果は[検証記録](im06-private-runtime-image-link-receipts.json)にまとめた。
