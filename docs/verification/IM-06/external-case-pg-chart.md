# IM-06 外部メッシュの照合から構造チャートの組立てまで

認証済みの Gmsh または Nastran の対応表から Shell を照合し、照合した PG 参照をそのまま構造チャートへ移す。対応表にない Shell は Case の幾何から準備する。外部面の来歴と構造チャートを一つの結果が所有する。Gmsh の支持と接着接続では、名前付き境界を覆う元線、その元線に接する元面、照合した PG 参照の識別を保持する。

## 同じ支持を持つケースを三つの入口で準備する

一辺 2 m、全厚 1/4 m の平板を、Case のみ、実 MSH 4.1 ASCII と対応表、実 BDF と対応表の三つの入口で準備した。外部ファイルは同じ Shell に対応する。チャートと基底の識別、積分点数が三つの入口で一致した。構造チャートに残した全厚支持の元の行には、平板の基準座標を代入して全成分の厳密残差がゼロになることを確認した。外部面の照合とチャート準備を別々に実行した場合と累積の確保量も比較し、同じ参照を二度準備した場合を試験で検出する。

支持線を別の外周に変えた Gmsh 入力は元要素 501、PSHELL の厚さが異なる Nastran 入力は元面 701 を示して拒否した。どちらも同じ Case を使って正常入力を続けて準備できた。キャンセル済みの要求と対応表の件数上限を超える要求は、空の資源計画でも定められた理由で失敗した。

## Gmsh の元線から二つの Shell の全厚拘束を組み立てる

全厚 1/4 m の単位正方形の Shell を世界座標の $x=1$ m で接着した。物理位置が一致する解析式から、左 Shell の $(1,\eta,\zeta)$ と右 Shell の $(0,\eta,\zeta)$ を対応させた。対応表で左の元線 501 を元面 701 に、右の元線 502 を元面 702 に結び付けた。接着境界の両側の元線と元面が、組み立てた Shell と同じ PG 参照を指すことを確認した。全厚接着と外周支持を持つ構造チャートには、両 Shell の基準座標を代入して元の拘束行すべての厳密残差がゼロになることを確認した。境界グループの左右を入れ替えた入力は、先に調べる左側で元線 502 と接続先の不一致を報告した。

## 検証範囲

平面 Nastran の経路は、明示された PSHELL・PCOMP の厚さ、積層、材料軸と、Case から組み立てる支持・接着に適用する。元デッキの梁・集中質量・点支持・RBE2 を構造全体に組み込む工程は残る。外部メッシュを使った変位・応力・固有モードの比較と、CLI・Python を通した実行・再開も IM-06 の後続の受入条件である。

## 試験環境

対象ソースは `5318520e5d0dc8079a573cd2f919a37a3ea57384`。Ubuntu 24.04 の GCC 14.2 と Windows 11 の MSVC 19.52.37029 で、Release の対象 CTest 4件がそれぞれ合格した。Windows では、無変更の JSON パーサーの翻訳単位に MSVC 19.51 でビルド済みのオブジェクトを使った。対象は `io.external_case_chart`、`io.external_shell_cross_format`、`io.gmsh_case_support_boundary`、`io.gmsh_shell_reference_set`。変更した3翻訳単位の clang-tidy と、変更した C++ ファイルの clang-format も通過した。

隔離した GCC ビルドで、照合済みの参照を受け取らず Case から作り直す変異を試した。Gmsh と Nastran の累積確保量の比較がそれぞれ失敗し、この試験が参照の二重準備を検出することを確認した。
