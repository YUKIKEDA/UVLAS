# IM-06 Gmsh 対応表にある全 Shell の参照を準備する

認証済みの Gmsh 対応表を SI Case と照合し、表に出てくる順に全 Shell の参照を準備する。結果は Shell ごとに Case から作った PG、元の面と物理グループ、対応表の宣言位置、幾何と厚さの照合結果を所有する。対応表の元ファイルも追跡できるよう、ファイルの識別とダイジェストを保持する。途中で不一致があれば、最初に失敗した Shell と元の診断を返す。[FD-03 対応表の契約](../../specs/foundation/external-mesh-sidecar-contract.md)

Case が `fit` を指定した場合は、その距離・法線予算と変換観測 ID を使う。PG を Case から準備したまま保持し、元の四辺形の双線形写像と同じチャート上で面全域の差を包絡する。その前に、対応する元面全域が Case チャートに収まり、指定された Case 側領域を覆うことを確認する。幾何に許容差を使う場合も、明示厚さは Case の厚さ領域で覆われる面積が正の部分について厳密に比較する。物理グループで一度宣言した厚さは、そのグループに属する別の Shell にも適用する。

## 実ファイルで照合した範囲

元 MSH の四辺形 702 を Shell 2 の平面、四辺形 701 を Shell 1 の曲面に割り当てた。同じ `fit` の下で両方を準備し、共通の物理グループ (2, 7) と明示値 250 mm をそれぞれの結果で確認した。変換観測 ID 1、法線予算、距離予算も両方の結果で確認した。

Shell 1 の曲面は元の平面から `0.1s(1-s)` m 離れ、同じチャート座標の二点間の距離は `s=1/2` で最大 1/40 m になる。距離予算を 0.051 m から 0.024 m に変えると、平面の次に処理する Shell 1 が元面 701 を示して失敗した。Shell 1 の Case 厚さだけを 0.5 m に変えた例では、幾何照合後の厚さ不一致を同じ元面で検出した。どちらの失敗後にも、同じ認証済み入力と作業領域で Shell 2 を再準備できた。件数上限を 2 から 1 に減らす対照では、一括結果を返す前に資源超過を検出した。

一括準備を検証する実ファイル試験は、既存の参照取得試験と実行対象を分けた。CTest の60秒上限はそのまま適用する。

実ファイルでは `fit` を検証した。`supplied` の参照ファイルの照合と、変換観測の値を用いた独立の R-05 受入には後段の検証が必要となる。

## 検証に使った構成

対象ソースは `2508aa71f25a583270e2cc6b1605249d2a7dd342`。Windows 11 の MSVC 19.51.36260 Debug と Release で、`io.external_planar_pg`、`io.external_pg_regional_thickness`、`io.reference_input`、`io.gmsh_shell_reference_set` が各4件合格した。Gmsh 一括準備の実ファイル試験は各構成で87アサーションだった。

Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）でも同じ4件を確認した。Gmsh 一括準備は87アサーション、7.71秒だった。Windows と並行した初回では従来の参照試験が60.09秒で時間上限に達したが、コンパイル済みの同じバイナリを単独で再実行すると45.38秒で合格した。

変更した C++ 翻訳単位の clang-tidy と clang-format 21.1.2 を通過した。
