# 元メッシュの内部辺とPG外周を照合する

同じPGに配置する面すべての向き、重複、領域、面積和を照合した後、元の節点順で辺を調べる。
内部辺の両側に同じ節点IDが逆順で現れ、端点の材料座標が一致することを求める。
組になる辺がない場合は、PG外周に属する原子辺を使って全区間を覆えるかを有理数で確かめる。
一つの元辺が複数の原子辺にまたがることは許す。
[IO4-04](../../specs/foundation/io-execution-adoption-specification.md#io4-04-gmshと外部面からの参照構築)

二枚の `CTRIA3` の対角線を共有できることを確認した。
片側だけが同じ座標を持つ別の `GRID` を使うと、対角線が二本の自由辺になり、認定を拒否した。
片側の宣言を逆順にしてPG上の向きを合わせても、元の対角線が両側で同じ向きなら拒否する。
[同座標の別節点についての指摘](https://github.com/YUKIKEDA/UVLAS/pull/339#discussion_r4678768299)

片側の `CQUAD4` の辺 A–B に対して、反対側の二枚の辺が A–M と M–B になる配置も拒否した。
両側を A–M と M–B に分け、元節点IDと向きまでそろえた配置は通った。
[内部のT字接続についての指摘](https://github.com/YUKIKEDA/UVLAS/pull/343#discussion_r4679893620)

## 厳密面対応の検証

PGの底辺の一部に名前を付け、PGの境界分割を横切る元の自由辺も通ることを確かめた。
MSVC DebugとGCC 14.2 Debug（ASan・UBSan）では、固定ソースの `io.external_planar_pg` が各5ケース・120アサーション通過した。
Linuxの分離コピーでPG外周にない自由辺を拒む条件だけを無効にすると、裂け目とT字接続は従来の面積・被覆検査を通り、二つの拒否アサーションが失敗した。
ソースを復元して再リンクすると、新しい対照の15アサーションが通った。
