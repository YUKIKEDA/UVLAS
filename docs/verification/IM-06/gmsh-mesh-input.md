# Gmsh メッシュ入力の検証

対象は IO4-04 のメッシュ読取りである。[入力契約](../../specs/foundation/gmsh-mesh-input-contract.md) に従い、宣言digestを照合したスナップショットから、元の座標字句と出典を持つ結果を作る。

節点・要素・所属・物理名の期待値はテストに手で書いた。固定メッシュは492 B。SHA-256は `1e75f5772cc5680f0111656b39e12937afb277221c7ede759c059f22e2606f13` で、読取り側と別に計算した値を照合に使う。点・一次線・一次三角形・一次四辺形の4要素を同じ入力から取り出し、順序、範囲、向き、非連続タグを確認した。最大節点タグは9007199254740993で、倍精度の整数へ変換すると表現できない。座標 `1e-500` とパラメータ `+.250` も元の字句で比較した。

MSVC 19.51のDebugとRelease、Ubuntu 24.04のGCC 14.2 Releaseで、`io.gmsh_mesh` がそれぞれ通過した。153アサーションの4ケースで、任意節と繰り返し、未対応の版・要素、未定義のタグ、重複、次元、バイト量と作業量の境界、取消、役割違いを検査した。取得元を破棄してから結果を読み直し、C++確保は元バイト列と5配列の6件だった。

GCCの隔離コピーで、読取り時に境界の反転だけを捨てる変異を作った。コンパイルとリンクの後、期待した反転の比較1件が失敗し、Catch2は終了コード42を返した。元の実装は同じ対象試験を通過した。検証したメッシュ処理の版は `c6351dc2965ee1848129413486eb15292b18bd38`。

この検証は読取りとタグ照合を扱う。部材・材料・支持・接続、長さ単位、参照曲面への対応はsidecarと外部格子変換で扱う。

## ブロック数とタグのレビュー対応

MSHのブロック数と、配列に格納する節点・要素の数を分けた。空ブロックと1件入りのブロックを併せた入力は、節点と要素の上限をそれぞれ1にして通る。同じ入力で実体側の2147483647と、節点・要素側の18446744073709551615を保持することも確認した。定義、物理グループ所属、向き付き境界、節点・要素ブロックの所属の6すべてで、2147483648の絶対値を持つタグを確保前に拒否した。

レビュー修正のソースは `27c8918f04e178e5cfc152dcb397e9ccdf22c6fa`。MSVC Debug・ReleaseとGCC 14.2 Releaseで、対象試験は各1件、6ケース・214アサーションが通過した。GCCの隔離ビルドで、ブロック数を旧上限へ戻すと1件、タグの上限検査を外すと2件のアサーションが失敗し、どちらもコンパイルとリンクの後にCatch2が終了コード42を返した。

## 空ブロックの所属照合

節点と要素のブロックヘッダーから、所属キーとタグの位置を一時配列に保存する。実体節を読んだ後、空ブロックも含めて各所属を一度ずつ照合する。実体節を節点・要素節の後ろへ移した正常入力も受理した。空ブロックの所属だけを未定義の曲線99に変えると、両節で `InvalidInput` とタグの位置を返した。固定メッシュのC++確保は、元の6件に照合用の一時配列1件を加えた7件だった。

対象ソースは `357928cb8fc1e42b6377e40dc6762b0524c93605`。MSVC Debug・ReleaseとGCC 14.2 Releaseで6ケース・227アサーションが通過した。GCCの隔離ビルドで所属照合を節点・要素のレコード単位へ戻すと、空ブロックを誤って受理する節点と要素の2アサーションがともに失敗し、Catch2が終了コード42を返した。clang-tidyの対象2翻訳単位も通過した。
