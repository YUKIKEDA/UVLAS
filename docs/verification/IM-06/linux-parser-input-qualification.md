# Linux 候補の使用ヘッダーと外部参照を一括で確認する

固定した GNU Make の Release ビルドと、同じ生成元に属する移設 CLI・Python 拡張を監査する。元ビルドと移設物の両方で生成元の指紋を照合し、実際のコンパイルが残した `input_document.cpp.o.d` からヘッダーを特定する。選んだ候補が期待する四つの SHA-256 に一致すれば、構文不正の実入力で例外ライブラリーを照合し、BDF・MSH・両対応表を含む固定 Case の受理を確かめる。[実行方法](../../build.md#非公開のランタイム用ディレクトリ)

対象は、読み取り専用のヘッダーを用いた固定ビルドである。依存ファイルのパスと現在のヘッダーの指紋を記録する。実行時の COW 文字列を説明する `cow_string.h` はこの ABI=1 の製品翻訳単位では読み込まれないため、実行時ライブラリーの提供元と確保の検証で扱う。

## 同じ Case を使った AlmaLinux 8.10 の対照

glibc 2.28、GCC 14.2.1、CPython 3.12.16、WSL2 6.18.58.1 で、候補 `a13bce0b1622b420a4b0a0083a0b8f3d9d70de66` を照合した。実際の依存ファイルにある四ヘッダーと例外ライブラリーの指紋が一致した。移設した CLI と Python のファイル入口が元 Case を受理し、Case の指紋も一致した。[元 Case と4参照の指紋](im06-private-wheel-external-references.json)

負対照ではビルドを複製し、同じ `__GLIBCXX__=20250110` の公式ソース RPM に含まれる配布パッチ適用前の `vector.tcc` で、製品の文書オブジェクトを再コンパイルした。再コンパイルしたオブジェクトと、再リンクした CLI・拡張の SHA-256 は元と同じだった。依存ファイルの SHA-256 と、それを取得した正負のビルド領域は台帳に記録した。依存ファイルに残った実ヘッダーの指紋が候補と異なり、監査は終了コード1で拒否した。

ヘッダー期待値または Case の期待 SHA-256 だけを違える対照でも、それぞれ終了コード1を返し、成功 JSON を出さなかった。

監査の固定元は `bef6126f486152e50dadbdbefa435714766ca04a`。Ruff と Pyright strict が通った。外部参照の実行は上記カーネルの対象パスを確認したもので、古いカーネルへの適用、確保モデルの本体受入、正式な配布範囲は各ゲートに残る。[カーネル機能と試行の範囲](linux-release-runtime-qualification.md)
