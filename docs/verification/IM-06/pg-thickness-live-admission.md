# IM-06 参照面の厚さを準備する有理数の見積り

Nastran の角別厚さを準備するとき、PSHELL 領域値の上限と、角別厚さを持つ面ごとに四つの有理数を見積もる。生成を始める前にその容量を控除し、元欄の十進値の読取りや単位換算にも控除後の枠を使う。Gmsh の定数厚さには、対応表の行数と対象面数の小さい方を用いる。

領域比較では、面ごとの厚さを Case と照合したあと、結果にその値とチャート面積を残す。元値と結果に複製した値が同時に生存するので、厚さ一値を両側に一つずつ、面積を結果側に一つ数える。角別の四辺形なら面ごとに九つである。比較で使う元値と複製は、三角形ならそれぞれ三つである。これは多倍長演算の作業メモリの見積りで、所有バッファの確保は従来どおり共有 ResourcePlan に計上する。

## 固定予算での対照

生成側は、一つの PSHELL 領域値と四角形一面の四つの角値に必要な容量を与えた。一面は通り、PSHELL の領域を増やさず角別厚さの面だけを二面にすると資源超過を返した。境界から一バイト減らしても、一面の生成に必要な容量を受け付けなかった。

比較側は、実 MSH の二つの四辺形を先に通常の予算で認証した。独立した四つの明示角値を各面に割り当て、比較に同じ予算を与えたところ、一面は通り、二面は結果を確保する前に資源超過を返した。一面の境界から一バイトを引く対照も同じ失敗になった。そのあと十分な予算を渡すと、同じ参照と要求から二面の照合結果を得た。

外部面の準備では、同じ予算に対して先に幾何認証の見積りを検査する。生成の容量境界は製品が用いる入口を直接確認し、比較の対照では認証済み幾何を共用して厚さの見積りを独立に検査した。

## 検証に使った構成

製品と回帰を固定した `fad39c37df3e1d3e246ffd092efeae5049814b8c` は、Windows 11 の MSVC 19.51.36260 Debug と Release、Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）で、`io.external_planar_pg`、`io.external_pg_regional_thickness`、`io.reference_input`、`io.gmsh_shell_reference_set` が各4件合格した。整数幅を明示した最終ソース `342fca193840b4f0e31aa13ed5bd29e779db6bde` でも、三つの構成で領域厚さの131アサーションを再確認した。

GCC の隔離複製で生成時の角別容量と比較時のコピー容量を省くと、どちらの対照も二面を受理し、回帰試験が失敗した。元のソースをバイト単位で復元し、両対照の20アサーションを再実行して合格を確認した。

製品と最終試験の clang-tidy、clang-format 21.1.2 も通過した。
