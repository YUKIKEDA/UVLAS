# IM-06 Nastran の静止点支持を同じ Case のシェルで照合する

[FD-03 の実例](../../specs/foundation/external-mesh-sidecar-contract.md#L182) は、選択した SPC セットと GRID を Case の支持 ID に対応させる。同じ物理点と並進成分を、認証済みの元デッキと Case の PG で照合した。対象は、元 GRID が平面 PG の面角に対応し、Case の支持点がその中心面を指定する定数零運動の並進拘束である。

対応表を結び付けるときに取り出した元の SPC、SPC1、SPCADD を所有する。選択した SPCADD が同じ番号の直接項より優先する規則を、対応表と物理照合で共有する。元項はカード順に走査する。Case の $(s,t,\zeta)$ は、認証済み面角の $(s,t)$ に厳密に一致し、$\zeta=0$ であることを確認する。`ZOFFS` がある面では、その面角の SI 座標をオフセット前の GRID の SI 座標とも照合する。

Case の静止支持は、並進と回転ベクトルが定数零で、運動の基準フレームの回転が単位行列のものを扱う。元 SPC の D は厳密に零と照合する。SPC1 の零拘束と符号付きの零も受理する。元 GRID の CD に従う選択軸は、既存の有向包絡で世界座標に写す。双方の拘束方向の数が等しく、元の全選択軸が Case の世界軸で張る部分空間に含まれれば、直交独立性から同じ拘束になる。Case が選ばない方向の成分は包絡全体が零のとき一致する。包絡が零を含まずに離れていれば不一致とし、零を含む幅のある包絡では精度未解決を返す。

結果は元デッキと対応表の識別情報・指紋、Case 支持とシェル、所有 PG の識別子、GRID と CD、元面、元項の欄位置、世界の拘束成分を保持する。元項数、走査、数値操作、外部多倍長領域に上限を適用する。個別の照合には平面 PG の所有結果を使う。一般の規定変位、有限回転、厚さ方向の支持点、曲面上の支持、拘束行の構造組立には、それぞれに対応する物理照合が必要になる。

## 実デッキによる対照

[試験の定義と元デッキ](../../../tests/io/external_shell_cross_format_test.cpp#L501) は、実ファイルを読み込み、同じ Case で `CaseNastranPlanarPgSet` を準備してから照合を呼ぶ。元の GRID 10 には矩形変位座標系を指定した。定義点から CD の 1 軸は世界の $+Y$、3 軸は $+Z$ となる。SPCADD 61 に含まれるセット 31の二項を世界 $Y,Z$ の Case 支持として受理した。同じ SID 61 の直接項は選択から除外され、Case の成分だけを $X,Z$ に変えると GRID の CD 欄と元の SPC1 成分欄を示して拒否した。

D を 0.001 に変えた入力と、Case のチャート位置をずらした入力もそれぞれ拒否した。Case の PG と元面を 1/8 m 持ち上げた対照では、オフセット前の GRID の位置との違いを検出した。取消、別の Case の証拠、元項を一つまでに制限した予算も検査し、同じ所有入力で二項を許すと成立することを確かめた。

|---|---:|---:|

| Windows 11、MSVC 19.51.36260、Release | 5/5 | 92 |

容量の対照は実デッキの元項数を二項に固定し、上限1と2を比較した。円筒や球の CD、零を含む幅のある包絡、走査・多倍長領域の上限境界は、この静止点支持の試験範囲外である。

## 製品基底と成分別の疎消去

同じBDFの平板を移動し、GRID 10の基本系位置を$(2,3,5)$ mとした。照合結果は元の座標と材料座標を保持する。Caseから準備した同じ参照の基底を中心面の点で評価し、各係数と基準自由度の積和で元GRIDの位置を復元した。点行の形状関数に既存パッチの定数場を代入すると厳密に1となった。

元行と疎チャートを試験中に連結した。$Y,Z$ は同じ行集合なので1因子を共有し、スカラーrankは2だった。自由位置から基準座標を厳密に復元した。$X$ の並進は拘束されず、$X$ の支持反力は厳密に零だった。独立力と元行の転置から全Cartesian力を再構成し、元の力と同次接線の仕事が縮約後にも一致した。元支持IDの重複と、別の支持が同じ点に矛盾する固定値を指定した場合を拒否した。後者では失敗後も元拘束を保持した。

GCC 14.2 Releaseの隔離ビルドで、疎消去を直接検査する段階の実BDF試験は930アサーションが通った。CTestは `io.external_shell_cross_format`、`structure.pg_full_trace`、`structure.pg_chart_candidate` の3件が合格した。

## Caseからの準備

`prepare_case_nastran_pg_chart` の点支持を受け付ける入口は、同じ認証済みBDFとSI Caseから、Shellの対応、元SPCの来歴、構造基底と成分別の疎チャートを所有する結果を返す。外部入力の記述を外した同じSI Caseを `prepare_case_component_pg_chart` に渡すと、チャートの識別、自由列、復元した全位置が有理数で一致した。点支持と反対側の全厚固定支持を同時に与えた対照でも、両入口の識別が一致し、元行に支持IDと世界成分マスクが残った。

外部入口では、元GRIDに対する方向、非零の規定変位、材料点または元面オフセットの不一致を、GRID 10と理由を示して拒否した。対応表の支持件数上限を0にした試験では、計画への確保課金なしで `ResourceExceeded` を返した。

MSVC 19.52とGCC 14.2のReleaseで、SPCADDの実BDF試験は各1,083アサーションが通った。両環境で `io.external_shell_cross_format`、`io.external_case_chart`、`structure.pg_full_trace`、`structure.pg_chart_candidate`、`coupling.case_structural_pg_support`、`coupling.case_pg_chart_entry` の6件が合格した。Windowsの未変更のJSONパーサーには、同じソースで構築したMSVC 19.51のオブジェクトを使った。

GCC の隔離複製で Case が選ばない方向の成分検査を外すと、世界 $X,Z$ の負対照が通り、回帰試験は失敗した。ソースを復元してハッシュを照合し、再構築した同じ試験で92アサーションが合格した。変更した翻訳単位の clang-tidy と clang-format 21.1.2 も通過した。

材料座標域をそろえた二つのShellを、高さ5 mと9 mに置いた。パッチ表からそれぞれを借りて点支持の行を評価すると、対応する高さが固定右辺に残った。借用するパッチを交換すると、どちらの向きでも新しい確保を行う前に `InvalidInput` を返した。
