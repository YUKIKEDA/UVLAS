# Gmsh メッシュ本体に子ファイル宣言がないことを確かめる

`gmsh-msh4.1-ascii` の取得済みスナップショットを最後まで検査し、採用範囲の MSH 4.1 ASCII として読めた場合にだけ子参照がないと確定する。証明には親ケース、参照元の文書ノード番号、ソース ID、SHA-256、元のバイト数を保持する。検査には取得済みのスナップショットを使う。[Gmsh メッシュ入力契約](../../specs/foundation/gmsh-mesh-input-contract.md) [元ファイルの形式](https://gmsh.info/doc/texinfo/gmsh.html#MSH-file-format)

初回は節、字句、個数を確かめる。次は同じスナップショットからレコードを読み、節点・要素・実体のタグを照合する。読取りに使う節は `MeshFormat`、`PhysicalNames`、`Entities`、`Nodes`、`Elements` に限り、そこで参照するタグはメッシュ内の値である。物理グループ名にパスに見える文字列があっても名前として扱う。未知節が末尾にあれば、その位置で `Unsupported` を返す。

メッシュを所有する従来の入口と、子参照を確かめる入口は同じパーサーとタグ解決を使う。証明の入口では元のバイト列を複製しない。照合に使うレコードを資源計画に計上し、証明の返却前に解放する。資源不足、取消、入力不正、未対応を区別し、失敗から証明は得られない。

回帰試験では、SHA-256 を照合したメッシュから出発し、入力と資源計画の破棄後も文書ノード番号とダイジェストを読めることを確認した。六つの一時配列の容量ちょうどで受理し、1バイトの不足と作業枠の不足を拒否した。別版、binary、未対応節、壊れた字句、重複 ID、未定義タグの失敗コードと位置を従来のパーサー入口と照合した。

この証明の範囲はメッシュ本体である。ケースが別に宣言する Gmsh 補助ファイルの形と材料・部材・支持・接続の対応は、インポーター契約が定める。[ケースの型辞書](../../specs/foundation/case-schema-fields.md)

Windows の MSVC 19.51.36260.0 Debug と Linux の GCC 14.2.0 Debug（ASan・UBSan）で、対象の8ケース・308アサーションが通過した。Linux の clang-tidy 21.1.1 では本体の通常構成と確保計測構成、回帰試験を確認した。
