# マニフェスト直下の参照を取得する検証

[外部参照の契約](../../specs/foundation/reference-snapshot-start-contract.md#マニフェスト直下の参照)に従い、直接宣言した8役割を所有する入口と、そこから読んだGmshメッシュを検証する。ファイル内の依存宣言と、Gmshのsidecarによる部材・材料・支持・接続はIM06-0の後続で扱う。

各宣言の役割、ID、参照先の序数を、型辞書のフィールド順と配列の添字順で手書きした期待値と比較した。ファイルは8件、宣言は9箇所。重複した観測参照は、元の字句 `900` と `0900` を別々に残し、一つの取得済みファイルを参照する。同じ内容の別ファイルは区別する。

ファイル由来のケースでは、入力と資源計画を解放して一時ディレクトリを削除した後、全バイト列とPythonの `hashlib.sha256` で求めたダイジェストを比較した。Gmshの読取りはその結果から疎な節点タグ11、42、99と要素91を再構成し、座標の元字句 `1.000` と接続順も保持した。数値の許容差は設けず、字句とIDの完全一致で比較した。

メモリ由来のケースでは、先に取得したファイルを含めて根の数、所有するバイト数、読取りバイト数・回数、ハッシュ対象バイト数と実体比較数を制限した。必要量から1だけ下げると拒否し、最後のファイルのハードリンクとダイジェスト不一致も検出した。拒否した位置は `/initial/file` と一致した。失敗後も投入した宣言とケースを参照できた。

MSVC 19.51 Releaseで参照入力、同一ハンドル取得、Gmsh、チェックポイントの対象CTestが4件通過した。GCC 14.2 Releaseでは参照入力とチェックポイントの2件が通過した。両OSで参照台帳の2ケース、258アサーションを確認した。Windowsの対象3翻訳単位に対するclang-tidy 21.1.1も通過した。

GCC 14.2の隔離コピーで、ファイル取得後に累積読取り回数を減らす処理を取り除いた。読取り回数が1不足する対照だけを実行すると、誤って成功したことを1件のアサーションが検出した。変異の終了値は42。対象のファイルを復元し、コピーの差分が空であることを確かめた。
