# IM-06 Gmsh の物理支持グループを Case の名前付き外周に照合する

認証済み Gmsh 対応表から Support ID と物理グループの組を指定する。対応表・元メッシュ・準備済み PG が同じ Case に属することを照合し、対象の Shell と境界番号を Case の `Support.trace_constraint` から解決する。物理グループには次元とタグの両方を使う。結果には元の線要素・節点順・接する面に加え、元ファイルと対応表のダイジェスト、宣言位置、PG の識別を保持する。[FD-03 対応表](../../specs/foundation/external-mesh-sidecar-contract.md)・[Case 構造支持](../../specs/structure/pg-case-structural-support-contract.md)

元の一次線は、対象 Shell の認証済み面のうち一面だけに、元の二節点を保った辺として接する必要がある。共通分割の外周辺から、Case の名前付き境界を出典に持つ区間を選ぶ。各元線について、これらの区間と共線になる部分のチャート上の長さ $|\Delta s|+|\Delta t|$ を厳密に足し、元線全体が入ることを確かめる。元線の重複を除外し、境界全体の長さと照合して、途中の欠けを検出する。

## 実ファイルの対照

二枚の四辺形が覆う単位正方形に対し、Case はチャートの $s=0$ にある名前付き外周を選ぶ。元線 501 と 502 はそれぞれ $t$ の下半分、上半分を覆う。501 の節点順は逆向きで、位置の照合に影響しない。物理タグ 7 を共用する次元 1 の線と次元 2 の面を区別した。

502 を外すと外周が半分残る。501 を別の外周へ移した例は、線が面に接していても選んだ境界の外として拒否した。501 の辺を別 ID で再び指定すると重複、二面が共有する辺を指定すると内辺として拒否した。元線数が一件不足する場合と取消では、線の結果を確保しなかった。

## 証拠の範囲

この入口は、厳密平面の面証拠か、線の接する面の位置差上界が零である `fit` の証拠を使う。位置差が正の上界しか得られない曲面例では適用外を返した。この場合に元線だけの一致を認定するには、辺に制限した位置の証拠が別途要る。

Gmsh の一次線と対応表は、全厚方向の拘束範囲、拘束成分、支持運動を外部側の物理宣言として持たない。ここで確かめたのは中心面の境界とその出典までで、Case の全厚支持行は既存の構造準備で扱う。

## 検証に使った構成

対象ソースは `5566d743d04668f570b578624b1bfa1a697dd2b3`。Windows 11 の MSVC 19.51.36260 Debug と Release、Ubuntu 24.04 の GCC 14.2.0 Debug（ASan・UBSan）で、`io.external_planar_pg`、`io.gmsh_shell_reference_set`、`io.gmsh_case_support_boundary`、`io.external_shell_cross_format` が各4件合格した。支持境界の実ファイル試験は各構成で93アサーションだった。

GCC の隔離複製で境界全体との長さの照合を外すと、元線が一部しかない入力を受理し、欠けを検出する試験が失敗した。元ソースをバイト単位で復元し、対象試験を再実行した。変更した翻訳単位の clang-tidy と clang-format 21.1.2 も通過した。
