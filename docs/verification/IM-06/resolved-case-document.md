# SI 変換済みケースを結果の来歴へつなぐ

構造ケースを読み取り、型検査と SI 変換を経た `SiCase` から、UTF-8 の解決済みケース、状態、来歴を生成した。来歴は元ケースと解決済みケースの正確なバイト列をそれぞれ SHA-256 で指し、状態は来歴のバイト列を SHA-256 で指す。Windows と Linux で、入力の所有者と資源計画を破棄した後も三つのバイト列を読み出せた。[IO4-01・IO4-05](../../specs/foundation/io-execution-adoption-specification.md) [SI 変換契約](../../specs/foundation/si-precision-conversion-contract.md)

## 元の値と SI の誤差をたどれる

元ケースの全文を UTF-8 の文字列として収録する。各変換行には元の欄を指す JSON Pointer、元の正確な値、SI の次元と変換要求、実際に保持した値と誤差半径を記録する。Binary64 の値や TwoWord の上位語・下位語は IEEE 754 のビット列で保持し、二進スケールも記録する。補足の来歴がなければ空の内容を展開し、初期状態と再始動指定は元の不在を記録する。

試験では、`37.00 mm` を含む構造ケースを変換した。出力 JSON を nlohmann/json で独立に読み、全変換行を元の欄と照合した。長さをメートルに直した際の上位語、非零の下位語、誤差半径を元の `SiCase` とビット単位で比較した。元の小数表記、日本語を含む全文、前後の空白、三つの SHA-256 の対応も確かめた。同じ設定で生成したケースのバイト列は一致した。

## 上限内で三つの文書を生成する

出力量を変換行数、UTF-8 のバイト数、作業量、資源計画の残量で制限する。二回の出力走査とハッシュ計算を作業量に含める。出力の上限に収まるときだけ、解決済みケースの所有バイトを一度確保する。回帰試験では、ちょうど収まる容量、行数・バイト・作業の上限超過、事前の取消を確かめた。ケース生成後に状態・来歴の容量が足りなければ、三文書の戻り値は得られず、確保済みのケース分は資源計画に残る。

`io.resolved_case_document` と `io.result_documents` は、Windows の MSVC 19.51.36260.0 Debug、Linux の GCC 14.2.0 Debug（ASan・UBSan）でそれぞれ2件とも通過した。検証範囲は内部 C++ の所有バイトまで。公開ファイルの形式・CLI 保存、外部参照の依存グラフ、物理モデルの準備で初めて決まる値は後段の契約で扱う。
