# Q9途中解放・試行棄却・イベント左右再開の限定試験

版：0.1、2026-10-30。1〜5節を実装・実行前に記載。

## 1. 物理入力と対象

前回の保持体積力・非ゼロ初期ひずみ・12支持・全69自由度を使う。保持平衡を初期位置とし、支持に整合する初速度 $v_0=0.02\omega_1 y_h$ を加え、保持荷重下で動いている途中に解放する。この準備条件は前回の静止からの解放と区別する。全自由度を保持し、物理減衰は加えない。

前回の窓 $T_1/20$ を320等分した時間を1 tickとする。開始0 tick、解放37 tick、終了357 tick、通常提案2 tick。解放時刻は通常格子の中間に置く。予定ステップ数は保持区間19、解放後160の計179、イベント確定1回。算法は一般化α法0.8、前回の動的残差・速度補正尺度を使用する。

## 2. 比較経路

- 明示した区間分割参照：保持区間 `[2]*18+[1]` tickを積分、同じ位置・速度で荷重除去と算法加速度再初期化、右区間 `[2]*160` tickを積分する。
- イベント駆動：通常提案を境界で切り、左へ到達した後に独立したイベント写像を確定する。参照と全端点の位置・速度・算法履歴が同一。
- 正の時間試行をNewton予算0で強制棄却し、同じ予定刻みを再試行する。右区間の非静止状態で行い、棄却は必ず検出する。
- 境界左でイベント候補を作った後に破棄し、左状態を変更せず、再試行した候補だけを確定する。
- 直前（36 tick）、境界左（37 tick・未解放）、境界右（37 tick・解放済み）、境界後（57 tick）の各状態から新規モデルを構築して保存・再開する。

同じ時間積分器による区間参照であり、別の材料・時間積分法による独立な精度参照ではない。今回は状態遷移・荷重ルーティング・履歴の一致を確認し、実務時間精度の合格判定はしない。

## 3. 事前基準

- 正常・棄却・再開経路の全確定状態ハッシュ列、最終状態、出力キー列が一致。ビット一致は同一環境・演算順に限定する。
- 解放37 tick、受理ステップ179、イベント確定1、最終確定世代180、初期を含む出力フレーム181。左右の時刻は同じ、位置・速度のビット列は同じ、加速度差の荷重整合誤差 $\le10^{-12}$ 。
- 棄却・候補破棄・未収束によって確定状態のハッシュと出力位置を変えない。二重確定、古い親、境界横断、未適用イベントを残した時間前進、早期イベント適用を拒否する。
- 保存のモデル・方式・イベント予定の同一性、時計・左右・荷重集合・カーソル・配列長・有限値・出力位置を検査。不整合なチェックポイントはチェックサムを再計算しても拒否。
- 右境界の算法加速度へ左履歴を流用した不正状態を拒否する。検査を意図的に迂回した負の対照では、最終位相空間差 $>10^{-8}$ または後続算法履歴の尺度付き差 $>10^{-8}$ を検出する。

## 4. 保存試作

JSON一時書込み、読戻し検査、置換で保存し、確定状態だけを公開する。モデルには初期ひずみ・参照幾何・支持写像・材料・質量・保持荷重・持続荷重、方式とイベント再初期化の方針を識別して含める。読込みで位置・速度・算法履歴を復元し、通常状態の算法加速度を物理加速度で再生成しない。

整数tickは本試験の時刻表現であり、任意時刻・浮動小数点整列の製品採用ではない。容量不足・電源断・OS間互換性・CLI/Python・後流・同時多イベントは未検証。

## 5. 停止・記録

240秒・4 GiB。Newton最大12補正、動的加速度残差 $\le10^{-10}$ 、速度補正 $\le10^{-10}$ 、物理変位補正 $\le10^{-12}$ m、非有限値・非正の標本 $\det F$ で棄却する。事前基準の事後緩和をせず、失敗とソース・依存ハッシュを保存する。製品の連成方式・時刻型・永続形式は未採用とする。

## 6. 初回の検査集計不整合と保存入口の確認

初回の全状態一致・イベント・出力数・負の対照は成立したが、`guards` の集計が基準経路の「再開を行っていない」という情報フラグまで成功条件へ含め、総合判定が未達となった。初回JSONは `q9-event-transaction-initial-result.json`、ソースはローカル `build/analysis/check_q9_event_transaction_initial.py` に保持した。修正は情報フラグをガード判定から除外し、各拒否検査をそのまま残すものである。数値結果や許容差を変更しない。

再実行前に、保存入口を確定状態型だけへ制限し、未確定の時間試行候補・イベント候補の直接保存を拒否する追加検査を定める。これは同じプロセス内のAPI型区分であり、チェックサムの認証能力を増やすものではない。実験用の辞書型を製品の公開APIとして採用しない。

## 7. 実施結果

[結果JSON](q9-event-transaction-result.json) の10判定が成立した。[初回JSON](q9-event-transaction-initial-result.json) の集計不整合は保持し、初回ソースのスナップショットも6節の位置に残した。初回と再実行の全確定軌道NPZは同じSHA-256であり、集計と保存入口の修正によって計算軌道を変えていない。

| 確認対象 | 結果 |
|---|---|
| イベント整列 | 通常2 tickの提案を36→37 tickの1 tickへ切り、境界左へ到達 |
| 左右状態 | 同じ37 tick、位置・速度はビット一致。加速度跳びの荷重整合誤差 $1.82\times10^{-20}$ |
| 正の時間進行 | 保持区間19、解放後160、計179受理ステップ |
| イベント確定 | 1回、ゼロ時間の確定世代更新を1回追加 |
| 出力キー | 初期を含む181件、確定世代0〜180が各1回 |
| 明示区間参照 | 全確定状態のハッシュ列が一致 |
| 時間試行棄却 | Newton予算0の棄却を検出。確定状態・出力位置不変、再試行後の全軌道が基準と一致 |
| イベント候補破棄 | 左状態を変更せず、後続の1候補だけ確定 |
| 再開 | 下表4か所で新しいモデルを構築し、全状態・出力キーが連続実行と一致 |

| 保存位置 | 保存時の意味 | 再開後の扱い |
|---|---|---|
| 36 tick | 解放前、通常区間 | 1 tickで左境界へ到達して適用 |
| 37 tick・左 | 到達済み、未解放 | 時刻を進めずイベントを1回適用 |
| 37 tick・右 | 解放済み、右履歴へ再初期化済み | 再適用せず右区間を継続 |
| 57 tick | 解放後の通常区間 | 保存した算法履歴から継続 |

解放時刻は約0.123726 ms、終了時刻は約1.193792 ms。初速度を与えて保持荷重下で動かしたため、境界左も非ゼロ速度の状態である。位置・速度をゼロへ戻す操作はしていない。

### 拒否条件と履歴の反例

古い親世代・二重確定、境界を横断する提案、未適用イベントを残した時間前進、早期／繰返しイベントを拒否した。未確定の時間試行候補・イベント候補は保存入口で拒否した。

チェックサムを作り直した意味的不整合を含め、13件を拒否：有効荷重集合、イベントカーソル、左右区分、時刻、受理番号、確定世代、出力位置、履歴世代、配列長、右状態への左履歴流用、チェックサム、モデル／方式識別、算法加速度欠落。

右境界へ左の算法履歴を流用する不正状態は読込みで拒否された。検査を意図的に迂回した負の対照では、最終位相空間差 $1.09\times10^{-4}$ 、次ステップ算法加速度の尺度付き差約0.50002が生じた。通常再開で算法加速度を保存する規約と、既知イベントの左右で明示的に再初期化する規約を混同できない。
