# n4四次の全背景とU形切断でピボット行尺度を共有できる

全候補の分母を使った共通行尺度を、n4四次の全背景とU形切断で検証した。各従属候補の従来尺度から共通尺度に変換しても、有限体の補正桁と厳密な残差更新が保たれる。両領域の全ピボット行・全従属候補で変換に必要な整数関係を確かめ、既存の512ビット枠に収まった。IM01-7の子Issue #224の結果である。

## 行ごとの正の整数倍率が補正桁と証明を保つ

選択基底の有理ピボット行列を $B$、候補 $j$ の有理右辺を $a_j$ とする。従来は各ピボット行 $i$ について、同じ行の基底成分と右辺成分の分母の最小公倍数 $d_{ij}$ を求めた。共通尺度 $d_i$ は、その行の全候補の分母の最小公倍数とする。零成分の分母は1である。

正の整数 $t_{ij}=d_i/d_{ij}$ は、使う素数 $p=2{,}147{,}483{,}647$ の倍数を含まない。すべての分母が $p$ の単元であり、その最小公倍数と商も単元になるためである。整数行列 $M_{ij}=d_{ij}B_i$、初期右辺 $b_{ij}=d_{ij}a_{ij}$ は、共通尺度でそれぞれ $t_{ij}M_{ij}$、$t_{ij}b_{ij}$ になる。

補正桁 $z$ を求めるとき、共通尺度での現在右辺 $t_{ij}c$ を $d_i^{-1}\bmod p$ で正規化すると、従来の $c$ を $d_{ij}^{-1}\bmod p$ で正規化した値に一致する。従って有理基底 $B$ を還元した同じ有限体因子で、同じ $z$ が得られる。割り切れる差の更新も

$$
\frac{t_{ij}c-t_{ij}M_{ij}z}{p}
=t_{ij}\frac{c-M_{ij}z}{p}
$$

を満たす。初期右辺からの帰納法で全補正桁に適用できる。共通分母を払った正方系の証明では残差も同じ正の整数倍となり、厳密な零判定が保たれる。

基底行の絶対値和と初期右辺の絶対値の大きい方を $L$ とすると、$|c|\le L$、$0\le z_k<p$ から差の絶対値は $pL$ 以下になる。検査には従来と同じ保守的な `bit_length(L) + 32` を用いた。

## 実係数で最大幅と複製される要素数を確認した

凍結した係数から既存の候補行列を組み立てた。疎順で求めた有限体の基底列とピボット行を独立証明書と照合し、その全ピボット行と全従属候補について、共通尺度との比、整数右辺、基底行の絶対値和、$L$ の関係を検査した。

| 観測 | 全背景 | U形切断 |
|---|---:|---:|
| 活動行 / 候補 / rank | 20,032 / 1,496 / 774 | 5,634 / 1,496 / 498 |
| ピボット行と従属候補の照合 | 558,828 | 497,004 |
| 尺度比が1を超えた組 | 69,712 | 50,732 |
| 尺度比の最大幅 bit | 3 | 3 |
| 共通尺度の最大幅 bit | 110 | 110 |
| 既存尺度での差の予約幅 bit | 157 | 153 |
| 共通尺度での差の予約幅 bit | 157 | 153 |
| 共有対象の行列・因子1組 B | 3,671,304 | 1,937,008 |
| 1組を保持すると省ける論理バイト数 B | 2,647,010,184 | 1,931,196,976 |
| 既存証明書座標のコピー分 B | 1,153,420,992 | 1,025,816,256 |

論理バイト数は、`Data` が持つ疎な整数行列、有限体の非対角因子、3本のインデックス・逆元配列、3本のオフセット配列の要素数と型サイズの積である。座標の値は既存の参照表に保持されるため、そこから借用する場合に省ける複製を別に数えた。いずれもベクターの余剰枠、管理領域、行列・因子生成中の一時領域を含まない。[全背景とU形切断の結果](result.json)

手計算できる $(1/2)x=3/5$ に同じ行の別候補 $1/3$ を加え、素数7で従来尺度10、共通尺度30、補正桁4・1、更新後右辺を照合した。素数で割り切れる分母を拒否し、差の幅が上限ちょうどの場合は通過、1ビット不足の場合は拒否することも確認した。

## 再現

1. `probe.cpp.txt` をMSVC 19.51.36260、Boost 1.92.0でビルドする。指定は `/TP /std:c++latest /O2 /EHsc /MD /DNOMINMAX`。Boostのヘッダーと凍結した `rank-comparison.cpp.txt` のディレクトリをインクルード先に加える。Windows x64で実行した。
2. `python -B run-census.py.txt` に係数原本、全背景とU形切断の各証明書、証明書索引、検証バイナリ、固定バッチ共通ランナー、n4切断ランナー、容量検査器、凍結調査記録と独立した出力先を渡す。要求した2領域を一意に選び、入力のヘッダーとSHA-256を照合する。
3. `python -B gate-probe.py.txt` を通常モードと `-O` で実行する。各モードで公開ゲート8件、9入力の直接・ハードリンク衝突18件を確認した。片方の検証失敗・観測欠落や証明書交換では旧出力または未作成の状態を保った。[公開ゲートの結果](gate-result.json)

今回の検証は共有化を固定バッチへ接続する判断材料である。全活動行の再構成は既存の実行記録を参照した。共有経路への差し替え、準備時の一時領域と実常駐量、全準備の事前確保、製品実装の開始審査は親Issue #140に残る。
