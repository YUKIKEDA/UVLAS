# PG指定支持の原行履歴

[指定運動と保持精度の契約](../../specs/structure/pg-chart-support-history-contract.md)に従い、厳密な支持履歴を固定チャートへ渡した。計算に使ったのは実PGの単位平板全厚トレース。物理IDが異なる二つの支持が同じ原拘束を持つ。活動原行の一つの疎列を空間係数とし、各行の時間応答を解析式から別に作った。

$t=1$ までは $t^3$、その後は $1+3(t-1)+5(t-1)^2$。片方に $0,1,2$、もう片方に $0,1/2,1,3/2,2$ の節点を与えた。準備区間は $[1/4,7/4]$。両端と内部の全イベントを比較した。7つの時刻・片側指定で、すべての元行の値、速度、加速度を解析微分と厳密に照合した。時間係数の左右の加速度は $t=1$ で6と10になり、参照の両支持に一致した。入力節点を破棄してから読み出し、片側加速度で位置の二階微分を復元し、原CSRの作用から元右辺を回復した。

- 後半の節点 $t=3/2$ の速度だけを変えると、全共通節点の値が同じでも拒否する。重複ID、未知ID、節点の重複と逆順、原行成分の欠落、区間被覆の不足、節点の側の欠落、端の外向き、区間外と要求済み取消を検査した。
- 入力節点数と総係数組数は等号で通り、1不足で拒否する。作業幅262,144 bitでイベント枠と結合枠を別に計算した。葉演算の見積りを加えた結合枠の等号で通り、1 B不足で拒否する。さらに旧二重減算の下で葉演算の余裕が0 Bになる設定で、現版が通ることを確かめた。いずれの拒否でも呼出し側の元チャートを保持した。

## 実行

ソースは `9df5cc1a`。MSVC 19.51.36260のReleaseとDebug、Ubuntu 24.04のGCC 14.2.0（ASanとUBSan、最初の違反で停止）で、専用 `structure.pg_support_history` の12,161アサーションが通った。CTest時間は順に0.73秒、4.44秒、9.72秒。Boostは1.92.0。関連2翻訳単位をclang-tidy 21.1.1で確認した。

MSVC Releaseで、零次の係数だけ検査する変異は速度の矛盾を捕捉できず、最初の拒否検査で失敗した。結合枠を元上限から求めず二重に減算する旧処理は、総枠が足りている設定で `ResourceExceeded` となり失敗した。変異の照合は `b6677bc0` のMSVC Releaseを使い、変異翻訳単位だけを置き換えた。

この検証は、元行に写した支持履歴から全区間の厳密係数を検査し、値と片側導関数を同一チャートへ渡す。物理支持から元行へ写す入口と、Binary64／TwoWordの値を用いる製品の反復作用には、契約に記した元作用と観測による認定が残る。
