# 凍結R4 Caseから全厚拘束と疎チャートを準備する

R4の曲面2パッチ接続のうち、分割数$(1,1)$と$(1,2)$を使った。両配置とも実厚さ$1/20\,\mathrm m$、各パッチ幅$1/2\,\mathrm m$。既存の[凍結Case生成器](../../../../tools/qa/vpg_case_reference.py)で2件を生成し、構文・型・SI変換を経て、[Caseからの疎チャート入口](../../../specs/structure/pg-case-chart-contract.md)に渡した。生成された34 Caseを記載したmanifestのSHA-256は `a3464f54edfc40b1e2752f13bafa648c29a898faef877de7593b67db725e1fb4`。

## 照合条件

凍結した両曲面の参照幾何と全厚位置の独立式は、R4二曲面接続の検証に保持している。この試験では、同じ型付きCaseの参照から作った基底を候補点の選別に読み、正の有限重みと点の位置を製品入口に与えた。Gramの作業・出力小数部は768／704ビット、因子・候補小数部は768／128ビット。固定チャートの値と途中計算の上限は65,536／262,144ビット。不整合分割では準備済みパッチにも、先行R4検証と同じ幅を使った。Caseチャート全体は累積48 GiBの一つの `ResourcePlan` を使った。

Caseと点列入力を破棄した後、準備結果が持つ2パッチの基底識別と寸法をチャートの列配置と照合した。Joint #1とSupport #1の元行、接続の共通区間数、左側全厚支持の区間数を確認した。全元行の参照残差が厳密に零であり、同じ自由成分から参照係数を全て再構成することを確かめた。別の有理ベクトルを用い、$J$ と $J^\mathsf{T}$ の仕事の一致を独立積和で比較した。元乗数に対する $C^\mathsf{T}\lambda$ も、全元CSRの独立積和と照合した。

元Caseから向きの宣言だけを同向きに変更した入力と、固定支持のMotion枠だけを反射にした入力を拒否した。異なるShell ID、0バイトの計画、開始前取消は準備の課金0で失敗した。既存の全厚試験では、同じ数値IDのJointとSupportをともに保持し、Joint内・Support内の重複をそれぞれ拒否した。

## 結果

| 分割数 | 基底列 | 元行 | rank | MSVCの累積課金 [B] | GCC 14の累積課金 [B] |
| --- | ---: | ---: | ---: | ---: | ---: |
| $(1,1)$ | 344 | 192 | 116 | 4,538,406,718 | 4,559,331,326 |
| $(1,2)$ | 521 | 288 | 171 | 9,670,047,942 | 9,724,812,822 |

不整合分割の元CSRは70,428項。疎因子の保持はL 11,106項、U 34,860項で、両環境が一致した。表の確保量は、製品の準備と同じ計画で行った最終の独立照合までの累積値。最大常駐量はこのCase試験では計っていない。

整合分割には、元非零120,000、元行500、疎チャートのピボット／行作業／因子容量300／480／70,000を使った。不整合分割をこの小さい設定とパッチ8,192／32,768ビットで試すと、両環境でResourceExceededとなった。不整合分割の再実行には先行R4と同じ元非零2,000,000、元行4,096、疎チャート384／1,024／100,000、パッチ65,536／262,144ビットを使った。両設定で48 GiBの累積上限と合同誤差上限は同じ。両環境でパッチだけ8,192／32,768ビットに戻した対照も合格し、累積課金と元CSRおよび疎因子の実項数が一致した。

WindowsとLinuxはReleaseで実行した。既存の4 CTestは両環境で合格した。整合分割と正負対照は3f0d8951の実行で記録した。パッチ借用の検査を追加したfe3d4b98では、同じCaseの曲面係数を零にした平面対照6,499アサーションと、反射枠の拒否69,857アサーションをMSVCで再確認した。不整合分割はcda37b4aの試験設定で実行した。

## 再実行

[独立実行ソース](run-case-chart.cpp.txt)をC++23としてコンパイルする。インクルード先は `include`、`src`、`src/structure`、`tests`、`tests/coupling`、`tests/structure`、既存有限則系列の `run-series.cpp.txt` を置いたディレクトリと依存ライブラリ。リンク先はReleaseの `uvlas_coupling`、`uvlas_aero`、`uvlas_structure`、`uvlas_io`、`uvlas_numerics`、`uvlas_core`、Catch2。MSVCには `psapi.lib` と `/STACK:67108864` を指定する。GCCの実行時にはスタックを64 MiBにした。

リポジトリルートで `python -m tools.qa.vpg_case_reference generate <新規出力先>` を実行する。生成先を作業ディレクトリにして、実行ファイルに `[.frozen-vpg-chart],[.frozen-vpg-chart-negative]` を指定する。既存回帰は `structure.pg_full_trace`、`structure.pg_support_history`、`coupling.case_pg_support_motion`、`coupling.case_structural_pg_support` を実行する。

IM-02には同じ所有パッチの $N,G,X_0$、正の測度、層・片側、有限点列、および原拘束と消去・転置を引き渡す。曲面の有限則の合同認定から、連続内積への収束や、層材料・物理質量・剛性・構造応答の認定は得られない。
