# ケースの構造支持から固定PGチャートまでの検証

[構造支持の契約](../../specs/structure/pg-case-structural-support-contract.md)に従い、空力面のないケースに全厚辺を動かす二つの `Support.trace_constraint` を登録した。
支持IDは17と71。PCHIPの内容が同じ宣言を別々に読み込み、支持IDの指定順を逆にしても同じ元行を得た。

基準点は $(1,2,3)$ m。基準姿勢は鉛直軸回り90度、$t=1$ sの基準からの相対回転も90度とした。
節点を左と右から評価し、元行の位置と速度が一致し、加速度が変わることを確かめた。
右側では各微分次数について世界Cartesianの剛体場を100桁演算で計算し、全座標の期待値とした。
共通ジェットを有理中心とした経路では、元CSRを掛け直して $Cq=c$ を全原行で厳密に照合した。
有理の乗数と自由列力を使った仕事の差も厳密に零だった。
数値候補は同じ点で、右辺の半径を加えた元行残差 $10^{-5}$ と仕事差 $10^{-6}$ の呼出し側上限を満たした。

境界番号が異なるケース、元境界の片を省略したチャート、同じ境界番号で一片の長さを短くしたチャートを拒否した。
異なる回転履歴を同じMotionグループとして渡す場合と、チャートにある支持IDを省略する場合も拒否した。
異なる回転履歴の試験では、入力チャートを再び使用できることを確認した。

この検証の入力は、ケースのShellとGeometryに対応付けた準備済みパッチである。
離れたMotionグループ間の全時刻適合と、実空間の許容値を使う数値チャートの性能・精度の認定は、それぞれ別の受入条件となる。

ソースは `16abcf46`。新規試験の3,149アサーションは、MSVC 19.51.36260 Release 1.29秒、Debug 8.09秒、GCC 14.2.0 ASan/UBSan 17.65秒で通った。
従来の共通時計と剛体支持の6,365アサーションも同じ構成で通った。Boostは1.92.0。UBSanは最初の違反で停止する。
全厚元行の照合を無効にした負対照は、4番目のアサーションで異なる境界番号を受理したことを検出した。
Clang-Tidy 21.1.1で変更対象の3翻訳単位を確認した。
