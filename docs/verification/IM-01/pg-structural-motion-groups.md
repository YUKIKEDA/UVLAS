# 同じ固定PGチャートで複数の構造支持Motionを検証する

[構造支持の契約](../../specs/structure/pg-case-structural-support-contract.md)に従い、実ケースの二つの全厚支持を一つの固定PGチャートに登録した。
支持ID 17の平板は、$t=1$ sで基準から90度回転し、世界座標の並進にはPCHIPを用いた。
支持ID 71の別の平板は、世界の $x$ 方向へ2 m/sで並進した。
空力面のない同じケースを別々に準備し、支持IDの指定順を逆にしても同じ群と原行の対応を得た。

同じ厳密時計で右側の位置・速度・加速度を評価した。
世界Cartesianの剛体場を別に100桁演算で作り、元有理CSRへ掛けた値が、群ごとの共通有理中心と右辺半径の範囲に収まることを全元行で確かめた。
三つの微分次数ごとに、同じチャートから復元した座標へ元CSRを掛け直し、$Cq=c$ が厳密に成立した。
元行乗数で計算し直した仕事差も厳密に零だった。

同じ全厚辺を二度拘束してMotionだけを変えた場合、群数上限が1なら容量不足、2まで許しても元CSRの像に入らないため入力不正となった。
同じMotionを持つ二つの宣言は共有した。独立準備済みの現在ケースで一方の並進だけを変えると、元チャートが同じでも世代不一致となった。

この検証の全時刻適合は、各Motionの生成子を個別に元CSRの像に入れる条件による。
時間レシピ間の相関によってのみ成り立つ適合は保証範囲外とする。

ソースは `2958a240`。新規試験の5,473アサーションは、MSVC 19.51.36260 Release 2.23秒、Debug 13.97秒、GCC 14.2.0 ASan/UBSan 37.67秒で通った。
従来の6,365アサーションも同じ構成で通った。UBSanは最初の違反で停止した。Clang-Tidy 21.1.1で変更対象の3翻訳単位を確認した。
個別の像検査を外した変異は、異なるMotionで同じ冗長辺を動かす入力を誤受理し、3番目のアサーションで検出された。
