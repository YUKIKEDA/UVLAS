# 共有行尺度でn4四次の全候補を固定領域のまま再構成した

四次n4の全背景とU形切断に共有行尺度をつなぎ、各1,496候補の元式と独立証明書が厳密に一致した。列別診断のSHA-256も、各領域の従来版と一致した。複製していたピボット行列と有限体因子を1組にした結果、全背景の固定保持は2,909,437,240 B、U形切断は1,693,580,696 Bになった。IM01-7の子Issue #234の検証記録である。

## 既存の全行用整数係数からピボット行を取得する

全行証明向けに既に作る行尺度と整数化済み列を使い、ピボット行列を1組作る。有限体の基底順と因子は従来の探索結果を使う。[共有行尺度の式と適用域](../pg-rank-shared-pivot-scale/verification.md) の条件のもと、行尺度は同じ補正桁と厳密な残差証明を保つ。

従属候補ごとに、あらかじめ確保した右辺を零に戻し、幅の上界を基底行の絶対値和で初期化する。整数化済みの候補列からピボット行だけを読み込み、右辺の絶対値が大きい場合は上界を更新する。独立証明書の座標は既存の参照表の該当範囲を読み取る。更新用の確保を禁じる監査は右辺の初期化から持上げ・全行証明まで続く。

ハッシュで固定した旧ソースに、派生器が列挙する11箇所で入力引渡しと比較・監査を接続した。逆変換では旧ソースの全バイトが一致した。持上げの補正桁、復元、厳密な全活動行の検査は旧コードを通る。

## 失敗時の出力保持と再試行を確認した

小例で、容量上限ちょうどでは成功し、1バイト不足では右辺を読む前に拒否した。非零右辺の直後に零右辺を処理し、旧右辺が残っていないことを確認した。借りた座標表の値を変えたときは不一致を返し、元へ戻した後は同じスクラッチで成功した。

公開ゲートは保存済み集計値を使い、全背景の完了後に切断の失敗や列診断の不一致を注入した。通常モードと `python -O` で、公開条件10件、全14入力の直接指定・ハードリンク衝突28件、派生器の衝突1件をそれぞれ確認した。失敗時は既存出力や入力のバイト列を保持した。[公開ゲートの結果](gate-result.json)

## 再現

1. `python -B derive-header.py.txt` に凍結した `fixed-batch.cpp.txt`、パス検査を借りるn2派生器、生成ヘッダー `frozen-shared-batch.hpp`、別の来歴出力を渡す。
2. `shared-batch.cpp.txt` をWindows x64でMSVC 19.51.36260、Boost 1.92.0を使ってビルドした。指定は `/TP /std:c++latest /O2 /EHsc /MD /DNOMINMAX` と `/STACK:67108864`。Boost、旧バッチ、生成ヘッダー、共有ブロックの各ディレクトリをインクルード先に加える。
3. `python -B run-shared.py.txt` に凍結係数、各領域の証明書、索引、容量調査、バイナリ、来歴、従来版2記録と尺度の記録、既存ランナーと容量検査器、別の出力先を渡す。両領域を順に実行する。列別診断を再生成する場合は、同じバイナリへ係数・証明書・領域名・`all` を渡す。全列を鍵順固定、空白なしのUTF-8 JSONへ直したSHA-256を用いる。実行したバイナリと生成ヘッダーのSHA-256は別々に記録した。
4. `gate-probe.py.txt` を通常と `-O` で実行する。初回の全背景ピークの2倍、6,268,223,488 Bを、全実行前のホスト余裕の目安とした。実行直前の物理メモリ空きは27,475,333,120 B、コミット余裕は27,710,529,536 Bだった。

動的な入力・行列・有限体探索・行尺度の準備は監査外である。固定保持は列挙した領域の実容量で、プロセスの常駐量や全準備の事前確保を保証しない。準備全体の入場、全操作の課金、辞書・分割との同時保持と製品実装の開始は親Issue #140で扱う。
