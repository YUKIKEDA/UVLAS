# 派生物の公開失敗と走査件数の誤報を検出する

PR #235のレビュー対象 `55a4ce29c494ea296bbb8b327d856e6a243d8844` では、来歴ファイルの親ディレクトリが存在しない場合でも、既存ヘッダーが先に上書きされた。走査件数の検査は範囲だけを見ていたため、全候補の件数を0に変えても受理した。

## 来歴の置換に失敗したらヘッダーを復元する

新しいヘッダー、来歴、既存ヘッダーの復元用バイト列を、置換を始める前にそれぞれの出力先に隣接する一時ファイルへ保存する。来歴の置換に失敗した場合は、先に置換したヘッダーを元のバイト列へ戻す。先行ヘッダーがなかった場合は新規ヘッダーを取り除く。復元まで失敗した場合は復元用ファイルを保持し、エラーにその場所を示す。

この手順が対象とするのは、同時に書き込む別の処理がなく、実行中のプロセスが通常の置換エラーを処理できる場合である。通常モードと `python -O` の各12件で、親ディレクトリの欠落、1回目・2回目の置換失敗、既存出力あり・なしの組合せ、復元失敗時の回復用バイトの保持、正常時の両出力を確かめた。

## 独立に数えた非零係数で観測を照合する

凍結した係数辞書と組立用の係数から、Pythonの `Fraction` で各候補列を再構成する。元係数を加算し、厳密に相殺された項を除く。U形切断では正面積の半セルだけを数える。疎順で並べ替えても非零数は同じである。独立証明書の基底列を除いた候補から、最初の従属列と全従属列の非零数を求める。

| 領域 | 最初の従属列 | 全従属列 |
|---|---:|---:|
| 全背景 | 64 | 951,340 |
| U形切断 | 18 | 231,163 |

通常モードと `python -O` で、保存値との一致、0・1件不足・1件過大・浮動小数点値の拒否、手計算で追える相殺と半セルの小例を確認した。計数だけを0に変えた4通りを旧出力あり・なしで実行し、すべて公開前に拒否した。旧出力のバイト列または未作成状態を保持した。[回帰検査の結果](review-235-result.json)

レビュー時にタイムアウトした全背景の全候補も、Windowsで既存バイナリを使い、1起動60秒の上限で再確認した。修正版の入口で両領域の最初の従属列と全候補が通過し、走査件数、列別診断のSHA-256、追加確保試行0件が保存値と一致した。

元の派生器、ランナー、マニフェストをバイト列が一致するコピーとして保存した。既存の数値証拠のハッシュは引き継いだ。
