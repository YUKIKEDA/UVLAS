# PG面上の位置写像と転置の検証

[面上の位置写像の契約](../../specs/structure/pg-boundary-position-contract.md)に従い、水平面の上下と外周側面の点を固定し、位置と共役力を計算した。SH-D02、SH-D05、N4-02、N4-03、N4-06、N4-08、N4-09に対応する。

## 独立照合

n=1平板の2層が共有する位置で、上層の下面と下層の上面を別々に指定した。入力の4行は、上層の下面、外周側面、下層の上面、上層の下面の順である。面レコード、層、上下、背景セル、点順を照合した。三角形の頂点と側面の端点、材料層の端から有理数で各点を組み立て、元基底の局所単項式と変換係数で全109列を別計算した。

Binary64とTwoWordで、計872個のNを比較した。Nの誤差上限はそれぞれ $2^{-43}$ と $2^{-90}$ とした。独立に求めたNと、語を厳密に有理数へ戻した入力から、順方向の12成分と転置の327成分を各表現で求めた。計678成分を、それぞれの誤差上限 $2^{-32}$ と $2^{-75}$ で比較した。仕事の差は、成分の誤差上限に入力の絶対和を掛けた値以下だった。

## 所有と反復

停止済みの準備は所有確保0 Bで終了した。2行目の面番号の不正と、Nの誤差枠0による精度拒否の後も、元の認定基底を使って準備できた。成功した準備の所有確保をResourcePlanの累積値と照合し、準備に使ったResourcePlanの寿命後に結果を読み出して計算した。

同じ結果とWorkspaceを順方向、転置、順方向の再実行に使った。C++の確保試行は成功9呼出しと精度拒否2呼出しでいずれも0だった。作業量ちょうどと1不足、Workspaceの1 B不足、取得済みWorkspace、非有限入力、取消、誤差枠0を検査した。失敗後に前回の結果を読み出し、同じWorkspaceで再評価した。既存の体積点の照合と拒否の試験も同じ対象で実行した。

## 負対照と実行環境

隔離したLinuxソースで水平面の上下を逆に記録すると、上下の照合が6件失敗した。側面と位置写像の計算は照合を通った。変異の解除後に、検証したソースのSHA-256が一致することを確認した。

Windows 11 x64ではMSVC 19.51.36260を使い、DebugとReleaseの `structure.pg_conditioning` が通過した。Ubuntu 24.04 x64ではGCC 14.2.0のASan・UBSanで同じ対象を実行し、13ケース・149,520アサーションが通過した。Boostは両OSで1.92.0を使用した。clang-tidy 21.1.1で射影、位置写像、条件付け試験の3翻訳単位を検査した。新しい面側の独立照合には上記の平板を使用した。
