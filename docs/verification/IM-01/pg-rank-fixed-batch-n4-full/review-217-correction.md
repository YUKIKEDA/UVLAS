# 平坦と四次の入力をどちらの実行でも保護する

PR #217のレビュー対象 `a922ab7c928d59fe7fdadbbeeb989da9aaed3e5b` では、平坦の実行時に四次の係数を出力先に指定できた。一時ディレクトリにコピーした四次の係数を使い、旧版が正常終了して平坦の結果JSONで上書きすることを再現した。

修正版は、平坦と四次の係数および索引に登録された両形状の証明書を、バッチを起動する前に出力先と照合する。証明書索引には `n=4, full, sparse` の記録を形状ごとに1件求める。係数と証明書の内容を照合してバッチへ渡すのは、指定された形状のものだけである。

## 両方向の入力と通常の公開を確認した

`review-217-probe.py.txt --root <repo> --coefficient-dir <係数> --certificate-dir <証明書>` を通常モードと `python -O` で実行した。平坦から四次、四次から平坦について、係数と証明書を出力先に直接指定する場合とハードリンクで指定する場合を各モードで計8件検証した。すべて所定の同一ファイルエラーで拒否し、元のSHA-256、ハードリンクの同一性、一時公開ファイルがないことを確認した。

従来の公開ゲートは両モードで、公開条件20件、ランナーの衝突18件、派生器の衝突1件を通過し、保存済みの集計を再現した。Windowsで既存バイナリを使い、別の出力先で実行した平坦と四次の全候補では、元式・座標の照合件数、追加確保試行0件、列別診断のSHA-256が各形状の保存済み記録と一致した。

元のランナーとマニフェストを保存し、旧証拠のランナー参照をバイトが一致する原本コピーへ付け替えた。
