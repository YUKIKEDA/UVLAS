# n4四次・U形切断のランナーで入力ファイルの上書きを防ぐ

PR #210のレビュー対象 `d203779ad349a4fa1b26b1867399b1f86aa49b77` では、来歴ファイルの一時コピーを `--driver-record` と `--output` の両方に渡すと、計算が成功して完成結果が来歴を上書きした。

修正版は、出力先と各入力の解決済みパスおよび既存ファイルの同一性を照合する。係数原本、生成来歴、証明書索引、容量調査結果、バッチ実行ファイル、共通ランナー、容量検査スクリプトを引数解析の直後に調べる。索引から選んだ証明書も、バッチの起動前に照合する。衝突時は対象を示して処理を中止する。

## Windowsで入力の保持と正常系を確認した

`review-210-probe.py.txt --root <repo>` を通常モードと `python -O` で実行した。8入力について、同じパス、`..` を含む別表記、ハードリンクの計24件を各モードで拒否した。各件で入力と出力先のバイト列およびリンクの同一性を照合し、バッチ呼び出しと公開用一時ファイルがゼロであることを確認した。

既存の公開ゲートも両モードで各28件通過し、保存済みのゲート結果をバイト単位で再現した。別の出力先を指定して既存バイナリを再実行した結果、1,496候補、元式8,428,464行、745,008座標、追加確保試行0件、列別診断のSHA-256が保存済みの集計と一致した。

旧ランナーと旧マニフェストの原本を保存した。旧証拠のランナー参照先は、同じバイト列を持つ原本コピーへ付け替えた。
