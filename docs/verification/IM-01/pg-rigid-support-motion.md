# 共通時計で剛体指定支持の元行を検証する

[剛体指定支持の契約](../../specs/structure/pg-rigid-support-motion-contract.md)に従い、全厚の実PG支持を固定チャートの元行へ渡した。単位平板の同じ全厚支持を物理IDの異なる二つの支持として登録し、両方を共通Motionで動かした。

基準点は $(1,2,3)$ m、基準姿勢は世界鉛直軸回り90度。型付きケースの局所並進はPCHIPで0、1、3 m、回転ベクトルは鉛直軸回り0度から180度。共通時計の $t=1$ sで基準からの相対回転は90度になる。並進の速度係数は $4/3$ m/s、加速度係数は左 $1/3$ と右 $5/3$ m/s²だった。

世界Cartesianの剛体場とその導関数を100桁演算で別に作り、採用前の元CSRを直接掛けた。位置・速度・加速度の全元行が返却したTwoWordの中心と外向き半径に収まった。元行乗数に対する $\lambda^T\dot c$ は $(C^T\lambda)^T\dot q$ と一致し、返却した速度の半径から計算した仕事率の上界にも収まった。支持が構造へ与える仕事率には負符号を使う。動かす対象を空にした対照では元行の定数位置と厳密な速度・加速度零を得た。

両支持は初期位置で同じ式を持つ。片側だけを動かすと、全時刻に対する元行の適合を準備時に拒否した。現在ケースの回転履歴を変えた対照は世代不一致、節点の誤った側は入力不正となった。元行上限は等号で通り、1行不足と作業不足を拒否した。原点のジェットを引かず、単位点のジェットを回転列に使う変異は、20番目のアサーションで解析参照との差3を検出した。

ソースは `9f880a3d`、時計の統合元は `5cdd35e8`。対象 `coupling.case_pg_support_motion` はMSVC Release 0.71秒、Debug 3.64秒、GCC 14.2.0 ASan/UBSan 7.85秒で各6,365アサーションが通った。UBSanは最初の違反で停止。MSVCは19.51.36260、Boostは1.92.0。Clang-Tidy 21.1.1で実装と試験の3翻訳単位を確認した。

この照合は、呼出し側が一つの準備済みMotionに結び付けた原行を扱う。複数Motionの偶然の整合性、ケース上の構造支持IDとMotionの自動対応、原行半径を含む近似疎チャートの実空間認定は別の検証範囲となる。
