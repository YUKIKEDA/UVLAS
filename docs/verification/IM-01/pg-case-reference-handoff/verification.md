# 凍結R5のCaseから支持付きPG参照を引き渡す

凍結R5第2版の後退・テーパ外形を、分割 $n=1,2$、基準厚さ $1/100,1/10000\,\mathrm{m}$ の全4配置で再生した。各Caseは凍結ソースの曲面・変厚・外周と根元全厚支持を保持する。Caseを検査して、有限則を保持する準備済みパッチと元拘束の疎チャートを作った。入力Caseと点・重みの一時保管を破棄した後、物理Shell IDで同じ所有物を参照した。

## 照合したもの

- 保持則の全点について、体積ordinal、三つの有理座標と重みを、準備に渡したものと照合した。同じ列と元行を使い、固定支持の全元残差と、非零の入力による元拘束の正方向・転置の仕事を厳密に確認した。
- 各配置で、保持則の末尾2点、下・上の水平面各1点、横境界1点の参照位置、体積・面積測度、体積・面ordinal、層と面の側を照合した。位置と測度の参照には、凍結高さの別微分と法線写像・曲率から組み立てた100桁十進式を使った。比較の絶対差枠はそれぞれの物理単位で $10^{-70}$。凍結Caseは1層のため、層界面の両側は[別のR5参照幾何試験](../pg-r5-domain-geometry.md)で確認している。
- $N$ と物理勾配 $G$ の全列を読み、同じ列の単位並進と参照座標を別の有理積和へ渡した。$N$ は定数と参照位置を再現し、$G$ は定数で零、参照座標で単位行列になった。二次拡大では係数を厳密に比較した。根号が有理の場合は二乗と符号で零を確認した。
- 同じ末尾2点を既存の体積参照入口に渡した。保持序数・層・元重みと、全 $N$ および体積JacobianのTwoWord値を照合した。絶対差枠は形状で $2^{-60}$、体積Jacobianで $2^{-60}\,\mathrm{m^3}$。$G$ を含む一括射影では、範囲外、計画ゼロ、事前取消、指定精度の未達を個別に検出した。
- 二パッチの対照はR4のCaseから高さのみを零にした。Shell #2の列開始位置とJointの右側物理IDを照合した。パッチの訪問枠1では拒否し、2では成功した。通常の曲面Gram試験では、保持則の2点を一括射影し、同じ点を直接指定したときの全語と一致した。保持則を指定した結果にだけ、開始ordinalを付けた。

## 物理勾配の射影

元の有限則は局所rankを増やす点を選んだもの。合同変換の保証はその有限則の内積に適用する。厚さ $1/100\,\mathrm m$、$n=1$ の保持則に対する一括射影は、全成分にこの試験の絶対枠 $2^{-60}$ を設定すると `PrecisionUnresolved` を返した。0始まりの点281、列157、全体座標 $x$ 方向の勾配は約 $9.95894\times10^{24}\,\mathrm{m^{-1}}$。100桁で求めた値を最近接の上位語と残差の下位語に丸めたときの差は $5.88420\times10^{-8}\,\mathrm{m^{-1}}$ だった。

[採用仕様5節](../../../specs/structure/main-shell-adopted-specification.md#5-求積と数値精度)の $10^{-8}$ は尺度を用いる参照・必要微分および原停留の照合条件。線形の全3D作用差は $10^{-12}$ 以下。面内の主・独立点数は $D$ 分子の次数にそれぞれ3と5を加え、厚さは7点と9点を使う。R5の判定では同じ尺度で位置・エネルギー・原停留を観測し、独立な体積力と全6面荷重も使う。各 $G$ の絶対射影誤差をどこまで許容できるかは、後続の物理作用への伝播を見て判定する。 [凍結R5の判定条件](../../../../rd/structure/main-shell/paired-geometry/records/paired-shell-r5-domain-protocol.md)

### 同じ2点で丸めたときの必須場

実際に拒否された勾配を独立に最近接TwoWordへ丸め、元の有理な並進・参照位置係数と積和した。点280・281で、単位並進の微分と零との差は最大 $7.87339\times 10^{-32}\,\mathrm{m^{-1}}$。参照位置の微分と単位行列との差は最大 $2.94120\times 10^{-33}$ だった。前節の単一成分の差は、この2点の必須場に同じ大きさで現れなかった。一般の変位、積分点全域、材料作用への誤差はここでは測っていない。 [丸めの比較](run-r5-gradient-reproduction.cpp.txt)

通常の独立照合で $G$ の三つのCartesian成分を巡回させると、配置0の最初の点で参照位置の微分が単位行列と一致せず、36,657番目のアサーションで検出した。

### 同じ曲面に正の積則を使う比較

比較候補には[切断放物柱面で用いた正の積則](../pg-curved-gram-continuum-v1/verification.md)と同じ、面内各17点、厚さ3点、分母 $10^{48}$ の節点と重みを使った。比較した $n=1$、基準厚さ $1/100\,\mathrm m$ のR5には19体積があり、16,473点になる。MSVC Releaseで、参照基底は同じCaseの実際のパッチから準備した。

| 有理値幅／作業幅 [bit] | 実測結果 |
| --- | --- |
| 8192／32768 | Gram準備中に `ResourceExceeded`。それまでの累積課金541,239,401 B |
| 65536／262144 | Gram準備中に手動停止。経過662.88 s、CPU 650.25 s、停止時までのピーク常駐量356,036,608 B |

計画上限はともに48 GiB。外部整数見積りには同じ48 GiBを設定した。幅を広げた試行も、凍結R5で準備・求解・観測に置く300秒以内にGramの準備を終えなかった。変換を得ていないため、この積則が同じ2点で $G$ の増幅を避けられるかは判定できない。

[比較ドライバー](run-r5-product-gradient.cpp.txt)には `pg-curved-gram-continuum-v1/finite_moments.py` の出力を `r5-product-rule.hpp` として渡し、`[.r5-product-g]` を指定する。8192／32768 bitの試行では、ドライバーでGramの有理値幅と作業幅を上書きする2行を外す。第2版の物理比較では面内28点で独立荷重を求め、30点で応答を観測する。厚さ方向には7点を使う。この17点の比較とは求積の目的と点数が異なる。 [凍結R5の実行ソース](../../../../rd/structure/main-shell/paired-geometry/experiments/check_paired_shell_r5_domain_v2.py)

## 再実行

[ドライバー](run-r5-handoff.cpp.txt)をC++23として扱い、[R4凍結チャート](../pg-case-full-chart/run-case-chart.cpp.txt)と[有限則の点選択](../pg-r4-curved-interface/run-series.cpp.txt)をインクルード先に置く。Releaseライブラリと64 MiBのスタックの設定はR4凍結チャートの検証と同じ。`python -m tools.qa.vpg_case_reference generate <新規出力先>` で凍結Caseを展開し、その出力先で `[.r5-case-handoff]` と `[.r4-paired-handoff]` を指定する。計画の上限は48 GiB。表の課金は準備から消費までの累積ResourcePlanで、プロセスの常駐量は含まない。

### Case入口での指定点と積則の一致

R5のCaseから高さ項だけを零にした平面対照で、根元の全厚支持と切断・変厚を保った。`CasePgRuleBinding` に明示の積則を渡し、面内7×7点・厚さ3点を19体積へ写した。独立な有理式で単位三角形への写像を展開し、全2,793点の順に体積番号、三座標、重みを比較した。各体積の重みの和は $1/2$。同じ独立式で作った点列全体を従来の明示点入口に渡して得たパッチ・チャートの識別と一致した。全厚支持の192元行のrankは37で、参照位置を全元行に代入すると残差は零だった。

非正の入力重みを `InvalidInput` として拒否した。確保上限ゼロと事前取消は、それぞれ `ResourceExceeded` と `Cancelled` で、計画の累積課金はゼロだった。両環境で14,574アサーションに合格し、既存の構造支持・支持運動の2 CTestも通過した。

| Release環境 | 積則経由の累積課金 [B] | 独立明示点列の累積課金 [B] |
| --- | ---: | ---: |
| MSVC | 720,430,793 | 720,213,705 |
| GCC 14 | 723,087,977 | 722,870,889 |

積則の累積課金には支持の元行残差の評価が含まれる。明示点列はチャート準備までを計上した。

[Case正積則のドライバー](run-case-product-rule.cpp.txt)を上と同じ手順でコンパイルし、`[.case-pg-product-rule]` を指定する。比較は、選んだ積則と明示点列を同じCase所有経路で受け渡せることを示す。物理作用の積分誤差は、曲面の正積則候補を含めて後続で判定する。

### 曲面R5のGram準備の内訳

同じ `r5-taper-00` の19体積、17×17×3点、159列と、値65536 bit・作業262144 bitの上限を使った。MSVC Releaseの隔離コピーで、全点列を作成してから各点の幾何、列評価、外積の時間を計った。先頭512点は幾何2.176秒、列評価404.427秒、外積21.295秒だった。先頭16点をさらに分けると、列評価13.635秒のうち13.516秒が基底多項式だった。

面内座標と体積が同じ厚さ点では、基底多項式の有理値を再利用できる。先頭16点の同一入力を旧経路と試作で比較し、外積の全12,720区間、25,440端点が厳密に一致した。幾何・列評価・外積の合計は旧経路14.903秒、試作6.258秒だった。求積の完走時間と曲面の物理作用の精度は未測定。

同じ面内点の別列が使う座標のべき乗も、認定済み辞書の次数と有理演算の資源上限に収まる場合は共有する。製品コードの同じ先頭16点で、旧経路と全25,440端点が一致した。曲面の回帰試験では、積則と明示点列の全端点を比較し、値の上限を1536 bitに下げてべき乗を共有しない場合にも同じ端点を得た。

この曲面回帰はMSVC Debugで従来の300秒枠に達した。同じ実行ファイルを同じシードで直接再実行し、297.17秒で35,810アサーションが通過した。負荷による実行時間の差を見込み、MSVC DebugのCTest枠を600秒とした。

### 凍結R5の曲面積則の全点計測

製品版 `1fefa3158b35c3e263b1e05e25fce35a97f7dc36` のMSVC Releaseで、同じ凍結曲面の全19体積、16,473点を計算した。Gram準備は4,643.68秒で、計上した整数演算の仕事数は542,769,896,145だった。累積ResourcePlanはGram準備まで11,985,810,769 B、2点の射影まで12,139,836,881 B。Gram準備中に採ったプロセスの最大常駐量は355,885,056 Bだった。

Gramから得た基底を、元の有限則で厳しい絶対枠の射影に失敗した点280・281で評価した。159列、3方向の $G$ について、100桁十進式で比較した最大絶対値は $2.1679\times10^4\,\mathrm{m^{-1}}$。最近接のTwoWordへ丸めるときの最大誤差は $1.66867\times10^{-28}\,\mathrm{m^{-1}}$ だった。同じ2点に対する製品の絶対差枠 $2^{-60}$ の射影も成功し、ドライバーの34,627アサーションが通過した。

Gram準備だけで凍結R5の性能目標300秒の15.5倍を要した。この実行の射影は2点で確認した。全求積点における物理作用の精度、独立な全3D作用との積分誤差と所要時間はIM-02の検証で評価する。

### 混合べき乗の再利用

同じ面内点で複数の列が使う混合べき乗を、認定済み辞書の全次数以下で保持する。算術予算が不足する場合は軸ごとのべき乗を共有する経路を使う。その保持枠も取れない場合は厚さ方向だけで基底多項式を共有する。曲面回帰では、混合べき乗、軸ごとのべき乗、値幅を1536 bitに絞った経路、明示点列の全区間端点を照合した。算術予算を絞る対照では、軸の保持枠を満たし、混合べき乗の保持枠に届かない予算を使った。

MSVC Releaseで同じ凍結R5の先頭64点・159列を計り、軸ごとの共有と製品版 `7e7edc58790dd3f8f055a0a9de389634beaa7ecd` の混合べき乗を比較した。同じドライバーと算術上限で、全点列を展開した後、各点の幾何、列評価、外積の時間を別々に加算した。外積の累積区間を64点目で採取した。両経路の12,720区間、25,440端点は厳密に一致した。

| 経路 | 幾何 [s] | 列評価 [s] | 外積 [s] |
| --- | ---: | ---: | ---: |
| 軸ごとの共有 | 0.454 | 15.540 | 5.115 |
| 混合べき乗の共有 | 0.483 | 11.939 | 5.172 |

64点の列評価は23%短縮した。製品版の全16,473点の所要時間はこの比較では測っていない。

同じ64点を計測用ビルドで再評価し、べき乗を共有した163,724項について係数の変換に0.088秒、単項式との乗算に1.043秒、有理数の加算に10.057秒かかった。列評価全体は11.927秒で、加算が84%を占めた。計時を入れたビルドでも全25,440端点が製品版と一致した。

### 共通分母の列評価と外積での重みの再利用

列の各成分を評価する際は、係数の分母の最小公倍数を $L$ とし、面内座標の分母を $d_u,d_v$、それぞれの最大指数を $E,F$ とする。分母を $Ld_u^E d_v^F$ にそろえ、整数和を作ってから一度約分する。$L$ を計算する前に、係数の分母の積から中間整数のビット幅を上から見積もる。ガード桁を含む作業幅か保持枠が上限を超えるときは、従来のべき乗を使う演算へ戻る。曲面の回帰では、整数べき乗の保持枠だけを外した経路を加え、全区間端点の一致と累積の所有領域課金の減少を確認した。

外積では、同一列の区間と非負の測度の区間を一度掛け、その結果を各行に再利用する。途中の丸めを挟まないため、相手の列を先に掛けても区間積は等しい。区間の符号から極値に寄与する端点が決まるときは、その積だけを求める。

MSVC Release で同じ凍結R5の先頭64点を使い、比較する二つの経路を交互に実行して、各経路を3回計測した。列評価の中央値は、共通分母を使うと8.530秒から2.230秒に下がった。外積の比較では両経路で共通分母を使い、中央値は5.393秒から2.281秒に下がった。比較ごとに採取した全12,720区間、25,440端点は厳密に一致した。区間行のSHA-256は `6e76f85e130a2adf81e5b196a550241fc030abe091b50028f43b5f2122ae2952`。64点の比較からは、全16,473点の計算時間を判定しない。
