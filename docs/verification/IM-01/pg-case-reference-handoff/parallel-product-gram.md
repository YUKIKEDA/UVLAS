# 凍結R5の正積則を固定4区間で準備する

凍結曲面R5の全16,473点で、並列と直列のGram区間を構成する25,440端点が厳密に一致した。GCC 14 ReleaseのGram準備は並列56.560秒、直列230.836秒だった。どちらも合同変換を認定し、以前の有限則で絶対枠に収まらなかった2点の物理勾配をTwoWordに射影した。 [正積則と射影の比較](verification.md#同じ曲面に正の積則を使う比較)

## 予算を確保してから同じ核を並列に呼ぶ

正の積則の点列を、同じ面内位置の全深さ点を含む群で区切る。固定4区間それぞれで従来の整数格子の積和を計算し、親が元の区間順に厳密加算する。出力格子への外向き丸めは集約後に一度行う。

親は、局所基底の元行と指数、体積片ごとの点群数、最大整数幅から、4区間の累積payload、スカラー演算、分割訪問と固定整数の仕事を事前に見積もる。外部整数領域は共有点列・結果の保持分を引いてから、同時に生存する4区間に配分する。スカラー上限には深さ点ごとの幾何・物理測度と、各群の最初に計算する局所基底値を含める。固定整数上限は平方根、区間端点積、部分和と親の最終丸めを含む。見積もりが残量に収まらなければ従来の直列経路を使う。事前見積もりで使う分割訪問も計上する。

子は計画を個別に持ち、基底と入力点を読み取る。起動済みの子がすべて終了した後、成功した確保と消費済みの作業を親へ計上する。取消で途中終了した場合も確保済みの累積payloadを親に残す。子の結果に失敗があれば、元の基底を移さずに失敗を返す。

## 同じ凍結入力での計測

製品ソースは `494256de3281cabce0d58e3474d95477ea437ae2` 相当のファイルを隔離複製でビルドした。入力は `r5-taper-00` の $n=1$、基準厚さ $1/100\,\mathrm{m}$、19体積。17×17×3の節点と重み、格子幅、合同変換・射影の許容差を両経路で共通とした。Core i5-13400FのWindowsホスト上でWSL2とGCC 14.2.0 Releaseを使い、全点比較を順に1回ずつ実行した。直列計測中は同じホストでWindowsのビルドと回帰を実行した。

| 項目 | 並列 | 直列 |
| --- | ---: | ---: |
| 親の累積payload上限 [B] | 51,539,607,552 | 1,800,000,000 |
| Gram準備 [s] | 56.560 | 230.836 |
| Gramの固定整数仕事数 | 79,611,726,177 | 79,608,746,917 |
| Gram準備終了までの累積payload [B] | 1,332,322,513 | 1,225,031,857 |
| 2点の射影終了までの累積payload [B] | 1,486,760,769 | 1,379,470,113 |

同じ親の外部整数見積もり48 GiBを使った。小さいpayload上限は4区間の予約を拒否する一方、直列計算を許す。表の確保量は `ResourcePlan` の課金累計である。並列で約107 MB増えた。

比較ドライバーの `R5_FINAL_ENTRY` 行を抽出して、出力順のままLF区切りで連結した。下端・上端12,720組のSHA-256は両経路とも `7f68c5172b663248d27b45f75dd5c18dc79f3018c2658f8e24edb8c35eb2affa`。2点・159列の100桁計算に対するTwoWordの最大成分差は両経路とも $1.66867\times10^{-28}\,\mathrm{m}^{-1}$ だった。

## Case入口から同じ曲面・拘束を受け取る

型付きの凍結Caseと同じ積則を `prepare_case_pg_chart` に渡した。所有結果からShell 1を開き、全16,473点の元体積番号、面内・深さ座標と重みを独立な有理積と厳密比較した。固定支持は元192行、rank 45。準備したパッチの参照座標を同じ所有チャートに渡すと、元192行の全成分の残差が厳密に零になった。

GCC 14 ReleaseではCase準備が62.815秒で完了し、検査82,947件が通った。残差の比較までの累積payloadは1,442,774,721 B。上の並列・直列比較の時間はGram工程だけを計測している。プロセスのピーク常駐量は今回の計測に含めなかった。

通常の回帰では曲面の増点則で並列経路と外部整数予算による直列経路を照合した。両経路で上下端がすべて一致した。GCC 14.2.0とMSVC 19.52 Releaseで、資源計画・曲面Gram・正の積則の対象3件を確認した。隔離したGCCビルドで並列経路を無効にすると、両経路の累積payloadが179,905,472 Bで一致し、子の確保が親に計上されたことを確かめる検査が失敗した。

## 再実行

[比較ドライバー](run-r5-product-gradient.cpp.txt)の生成・リンク条件は[既存の手順](verification.md)を使う。両版を `UVLAS_R5_COMPARE_ENDPOINTS` 付きでコンパイルし、片方だけに `UVLAS_R5_SERIAL_BUDGET` を追加する。凍結Caseがある作業ディレクトリで両版を `[.r5-product-g]` で実行する。端点の出力はGramの計時区間外。

Caseからの全厚拘束と引継ぎは、通常予算の版を `[.r5-product-case-chart]` で実行して照合する。Caseと節点表のハッシュは検証台帳を参照する。 [検証台帳](../im01-pg-parallel-product-gram.json)

300秒は参照準備・求解・観測を含む1配置の目標である。全3Dの材料・質量、独立荷重への応答、層別応力と固有対を含む所要時間はIM-02で評価する。 [凍結R5の判定条件](../../../../rd/structure/main-shell/paired-geometry/records/paired-shell-r5-domain-protocol.md)・[V-PGの分担](../../../plans/pg-verification-gate-ownership.md)
