# PGの共通分母を使った整数Horner評価

[曲面の有限積則](../../../specs/structure/pg-product-volume-rule-contract.md)から、面内座標 $(u,v)$ における基底の各成分を評価する。係数分母の最小公倍数 $L$、座標分母 $d_u,d_v$、最大指数 $E,F$ を使う共通分母 $Ld_u^E d_v^F$ は従来と同じ。変更するのは、その分子を求める整数積和の順序である。

各係数を $L$ 倍した整数に直し、正準の指数順を逆にたどる。固定した $u$ の次数に対して、まず $v$ の次数を高い方からまとめる。次の項まで指数差 $k$ があれば、部分和に $v$ の分子の $k$ 乗を掛ける。各項の分母をその組の最大次数にそろえ、組全体を共通の $d_v^F$ に合わせてから、$u$ についても同じ手順を使う。最後に一度だけ約分する。

途中の各整数は、共通分母にそろえた展開式から、未処理の冪を除いた項または項の和。座標の分子が零でも、幅の見積もりには各底の絶対値と1の大きい方を使える。既存の分母積・係数幅・項数を使う事前判定が、部分和も含めた整数幅を覆う。整数を作る前に、既存のガード付き幅、外部整数領域と作業枠を照合する。入場できない場合や指数が正準順でない場合は、従来の項別有理式を使う。

## 検証

SH-D07 と N4-08 を対象にした。

独立な展開式から、欠けた指数、正・負の座標と係数、異なる非単位分母、零座標、全項の相殺を照合した。指数順を逆にした対照では、既存経路へ戻す時点の算術課金と累積の所有領域課金がともに増えないことを確認する。既存の10/11ネイティブlimbの容量境界、整数べき乗の保持枠を外した経路と明示点列の全区間端点も使う。

MSVCとGCC 14のReleaseで、PGのrank準備・条件付け・積則の回帰が各3件通過した。GCC側は既存の静的検査修正 `c4760e13` と組み合わせ、変更した二つの翻訳単位をClang-Tidyでも検査した。組の分母を全体の最大次数に整列する箇所の指数を1下げた別バイナリでは、独立展開式との比較に失敗した。

## 凍結R5の先頭64点

製品ソース `5b2adce751c1094ffb9bae1f358e76d37dddf9cf` で、凍結R5の `r5-taper-00` の17×17×3積則を全て展開し、先頭64点と159列を測った。
MSVC Release、1論理CPU、同じ有限則、値幅65536 bit、作業幅262144 bit、同じ資源枠と外積を使用した。
基準とHornerを各3回、順序を変えて実行した。範囲内の幾何・列評価・外積は区間別に計時した。別のテストビルドが同時に動く環境での比較である。

| 経路 | 先頭64点の列評価3回 [s] | 列評価中央値 [s] |
| --- | --- | ---: |
| 係数ごとに冪を掛ける基準 | 3.739 / 3.661 / 3.297 | 3.661 |
| 整数Horner | 1.759 / 1.662 / 1.552 | 1.662 |

全6回の12,720区間、25,440端点が既存記録と一致した。
端点の `R5_ENTRY` 行をUTF-8・LFで連結したSHA-256は `6e76f85e130a2adf81e5b196a550241fc030abe091b50028f43b5f2122ae2952`。
入力CaseのSHA-256は `80044242b860ef7f299bdf56373248b7009cac865a42b311ecd2176a47eeda95`。
試作では、分母が1のときの除算と積だけを省いた項別評価も計測した。別の各3回における中央値は基準2.378秒、整理後の項別評価2.274秒、Horner 1.077秒で、全9回で同じ端点を得た。
先頭64点の実測であり、全16,473点の所要時間は別に計測する。

## 再実行

比較する両版の複製に、[先頭64点の計時差分](measure-gram-prefix.diff.txt)を適用する。[既存の比較ドライバーと積則](verification.md)を使い、`[.r5-product-g]` を同じシードで実行する。計時版は64点目の内積の累積区間を出力し、そこで意図的に終了する。標準エラーの `R5_STAGES` が工程別時間、標準出力の `R5_ENTRY` が25,440端点。時間の比較からは端点出力を外す。
