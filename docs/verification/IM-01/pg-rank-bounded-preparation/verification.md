# PG局所rankの有界な製品準備

Issue #264。採用した候補順、全活動行の再構成、全背景アンカー、所有結果と資源の契約は [有界な局所rank準備](../../../specs/structure/pg-rank-bounded-preparation-contract.md) にある。Windows 11 x64、MSVC 19.51.36260、Boost 1.92.0で実行した。

## 元辞書から所有結果まで

製品の有理グラフから係数辞書と共通分割を準備し、同じ48 GiB `ResourcePlan` を `PgRankPreparation::prepare` に渡した。製品側は独立証明書を読む前に、正の行・列尺度で正規化し、有限体の非零pivotとすべての先行列関係を確かめて結果を返した。比較側は製品と別の資源計画を使った。ランナーは凍結入力・独立証明書のSHA-256を照合し、全系列が成功してから一度だけ結果を保存する。

全n=1/2/4、平坦・四次、全背景・U形切断の12系列で、選択列と3,746,550件のS/W/Z座標を凍結した独立証明書と厳密に照合した。暗黙の零も確認した。原辞書から別に結合したTの2,225,344座標とBの23,655,910係数も一致した。製品は51,779,436活動行の等式と、853,008行分の全背景アンカーを検査した。元のDの72頂点、336セルの活動面積と90の高さ係数を、作成後の所有証跡から読み直した。

選択した列の順序に関する独立レビューでは、正の尺度で階数が変わらず、有限体で非零の小行列式が有理数での独立を証明することを確認した。飛ばした列は、後から選んだ列の座標が零で、すべての活動行の残差が零の場合だけ従属と認定する。返却する基底には行・列の尺度を戻し、従属座標には基底側と従属側の列尺度の比を掛ける。分割の順序付き元Dは、factoryが所有する元の有向辺を照合したうえでコピーする。

## 48 GiBプロファイル

四次n4の両領域について、rankを呼ぶ前に、同じPlanに計上した費用とグラフ・辞書・分割を生成した工程の外部領域見積りを48 GiBから控除した。この残量をrankの追加上限として渡した。各工程の外部見積りには既に使い終えたscratchも含まれるため、合計は保守的な受入指標である。プロセスピークは独立証明書を読む前に計測した。

| 量 | 全背景 | U形切断 |
|---|---:|---:|
| rank | 774 | 498 |
| rankの追加事前算定（B） | 5,081,127,800 | 3,566,621,332 |
| 上流の外部見積り込み事前算定（B） | 25,370,260,016 | 39,835,098,679 |
| 同じPlanでの累積確保実績（B） | 9,066,874,488 | 7,974,813,391 |
| 製品区間の観測プロセスピーク（B） | 4,468,871,168 | 3,540,779,008 |
| rank準備中の予定C++確保試行 | 44 | 44 |
| rank準備中の観測C++確保試行 | 44 | 44 |

全12系列で有界rank区間のC++確保試行44件は予定と一致した。実行枠は最大128桁、定義した仕事量10兆単位で維持した。測定は専用プロセスの逐次実行で、64 MiBのスタック予約を使った。別の入力での同時保持や48 GiBハード上限、大域疎グラフのfillをこの実績から保証しない。

## 失敗と再現

WindowsのDebug・Releaseの対象CTestは、それぞれ2件中2件成功した。容量と仕事量の等号と1不足、固定幅超過、復元桁不足、微小非零、分母を割る素数からの再試行、無効添字、取消、Workspace再入、最初と最後の確保での故障を検証した。別Planと別Workspaceから同じ不変入力を読み、すべてのB/T/S/W/Zが厳密に一致した。元入力が破棄された後も所有結果を読めることを確かめた。

[変異記録](mutation-result.json)は、製品源の隔離コピーの一箇所だけを差し替えた結果である。列尺度の誤りは座標照合、非活動セルの混入は独立証明書の形状照合、アンカー項の符号の誤りは製品側の全背景アンカー検査で拒否された。

[ネイティブ照合器](run-series.cpp.txt)は `/TP /std:c++latest /EHsc /O2 /MD /W4 /WX /utf-8 /DNOMINMAX` でコンパイルし、`tests/support/allocation_audit.cpp`、通常のRelease構造・基盤ライブラリ、Windowsの `psapi.lib` とリンクする。インクルードには `include`、`src/structure`、`tests/support`、既存のBoostとEigenを使う。スタック予約は `/STACK:67108864`。[`run-series.py.txt`](run-series.py.txt) にバイナリ、凍結証明書索引、別ディレクトリで再生成した6係数ファイル・12証明書と出力先を渡す。各系列の結果とバイナリ、入力、証明書のSHA-256は [実行結果](result.json) にある。系列と変異を実行した版は fbc048f である。後続の6028c82では証跡公開型の既定値を明示し、通常入口が全ての成分を指定する構成と数値処理は同じである。

完了範囲は、指定したプロファイルでの有界な局所準備と所有結果である。現在の入力と全G/J recipeを使うキャッシュ再検証、物理内積による条件付け、R-02の大域疎拘束は既存の後続契約に残る。

## PR #267のレビュー確認

グラフ照合の入口試験を、WindowsのDebugとReleaseでそれぞれ1件実行した。辞書と分割は別々のグラフから準備した。高さ係数がともに 1/2^100 の組は、十分な上限でrank準備に成功し、作業上限0では資源超過を返した。取消済みの入力は同じ上限0で取消を返した。

分割側の高さ係数だけを 3/2^100 にすると、照合の手前の27単位では資源超過となり、28単位で入力の不一致を返した。いずれの失敗でも、渡したPlanに確保はなかった。上の12系列と変異試験は、記載した旧版での実行結果である。
