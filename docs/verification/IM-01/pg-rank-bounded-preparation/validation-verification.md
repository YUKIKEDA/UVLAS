# PG局所rankの所有と再検証

既存結果は全G/I/J項と元係数辞書の列来歴を所有する。Tの写像は同じ所有配列から選択候補の範囲を参照する。現在の入力を受ける `validate_for` は、グラフ、元Dの点順序、全セルの面積と活動、元辞書の来歴、全G/I/J項を有理数の実値で照合する。元入力を破棄して作り直したときも同内容なら再検証できる。有限資源、失敗と所有の規約は[有界な局所rank準備](../../../specs/structure/pg-rank-bounded-preparation-contract.md)にある。

## 独立参照と全系列

Windows 11 x64、MSVC 19.51.36260、Boost 1.92.0。n=1/2/4、平坦と四次、全背景とU形切断の全12系列で、最初のrankと辞書・分割を保持した状態で元式の再検証を実行した。ランナーは、再検証が成功してから製品辞書を凍結参照に照合し、全選択列とS/W/Zの3,746,550座標、Tの2,225,344座標、Bの23,655,910係数の厳密一致を確認した。元D、セル面積、グラフも照合した。初回準備と再検証は、どちらも各系列で予定どおり43回のC++配列確保を観測した。

元処理から継承する[12系列と変異の記録](verification.md)は旧版で取得した。方式を採用する前に不採用の累積exact呼出し方式が48 GiBで拒否された固定版の証拠は[局所rank契約の7節](../../../specs/structure/pg-local-rank-contract.md#7-二つの資源障害と開始ゲート)と[旧分割ゲートのPR #138](https://github.com/YUKIKEDA/UVLAS/pull/138)にある。

48 GiBの同じPlanで、グラフ・辞書・分割・初回rankの累積資源を差し引き、上流3工程の外部領域の保守的な見積りも残枠から控除した。追加の再検証も残枠に収まった。

## 回帰と再現

Windows DebugとReleaseでrankおよび資源の対象CTestは各2件成功した。同じ点と面積で順序だけ異なるD、同じ活動セルで面積の異なるD、同寸法の別グラフ、別graph同士の組み合わせ、移動元、Workspace再入、取消、容量と作業の等号と1不足、先頭と末尾の確保失敗を検査した。元所有結果と親入力を保持し、確保済みの課金を返金しないことも既存の資源契約に従う。

元の[ネイティブ照合器](run-series.cpp.txt)と[ランチャー](run-series.py.txt)を作業用ディレクトリへ複製する。リポジトリの根から `git apply --unidiff-zero --directory=<根から作業用ディレクトリまでのパス> docs/verification/IM-01/pg-rank-bounded-preparation/validation-runner.patch` を実行すると、使用した二つのソースを得られる。[既存のビルド条件](verification.md#失敗と再現)と同じ条件でコンパイルし、凍結入力・証明書と別の出力先を渡す。[再検証結果](validation-result.json)には全12系列の値、証明書およびバイナリのSHA-256がある。

保存した12件の報告を公開条件に通し直した。仕事量を欠落させた場合と、算定・実確保・累積確保・確保試行数を一つずつ1増やした場合の60件を拒否した。
