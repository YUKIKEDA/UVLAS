# 最大ビット幅を動的な厳密参照と照合する

PR #243のレビュー対象 `049e769f0370e55250fc9917f188c260af581b9e` では、固定整数の最大ビット幅を範囲だけで検査していた。保存結果の `max_lcm_bits` と `max_integer_bits` をともに1へ変えると、全背景とU形切断の両方で旧版が受理した。

修正版は、従来の動的な厳密参照で全行尺度と全整数係数を照合するとき、参照側で各値の絶対値の最上位ビットを調べ、最大幅を求める。C++側で固定整数から集計した幅との一致を確認し、両方の幅を出力する。ランナーも参照値と報告値の一致を検査してから結果を公開する。

| 観測 | 全背景 | U形切断 |
|---|---:|---:|
| 行尺度の最大幅 bit | 110 | 110 |
| 整数係数の最大幅 bit | 127 | 124 |

Windowsで凍結係数の両領域を再実行した。従来の報告項目はすべて保存値と一致し、算術中の追加確保試行は0件だった。各起動の60秒上限をそのまま適用した。[再実行の結果](review-243-result.json)

通常モードと `python -O` の各モードで、両方の幅、行尺度の幅だけ、整数係数の幅だけを1に変えた。全背景とU形切断で、3通りの改変を旧出力あり・なしで実行した。計12件すべてを公開前に拒否し、旧出力のバイト列または未作成状態を保持した。既存の対照を含む公開検査は各20件、入出力衝突の検査は各14件だった。[回帰検査の結果](review-243-gate-result.json)

元の結果と旧ゲートの集計は当時のファイルを保管する。元のマニフェストの `historical_artifacts` は、レビュー対象コミットにある旧ソース3件と各SHA-256を示す。新版の回帰検査では `gate-probe.py.txt --capture <review-243-result.json>` を使う。
