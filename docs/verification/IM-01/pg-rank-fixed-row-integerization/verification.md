# n4四次の行尺度と疎係数を固定領域で作った

凍結したn4四次の全背景とU形切断で、各行の分母の最小公倍数と疎係数の整数化を、事前に容量を照合した固定領域で実行した。全行尺度、全列境界、全整数係数が動的な厳密算術と一致し、算術の監査中の追加確保試行は両領域で0件だった。IM01-7の子Issue #241の結果である。

## 行尺度の計算前に確保する領域を決める

展開済みの疎候補行列から、行数 $m$、列数 $N$、格納項数 $K$ を得る。固定整数のサイズを $S$、行番号と整数値の組のサイズを $T$、配列の所有と作業領域を含むオブジェクトのサイズを $P$ とすると、計画容量は

$$
P + m(S+4) + 8(N+1) + KT
$$

となる。内訳は各行の尺度と重複検査用の行印、列オフセット、疎係数である。和と積を検査付きの64ビット整数で計算し、予算に足りなければこれらの配列を確保する前に拒否する。確保後は各配列の実容量を同じ式に代入し、計画と一致することを確かめる。

固定領域の入場後は、Boost 1.92.0の有理数backendから分子と分母を借用し、検査済みの桁だけを固定整数へ移す。前半で正の分母の最小公倍数を $L\leftarrow (L/\gcd(L,d))d$ で求める。後半で割り切れる商 $L/d$ を取り、分子との積を格納する。二項積は最大3,072ビットの作業領域で求め、結果が1,536ビットを超えれば拒否する。成功まで配列の件数を変えず、範囲外の行、重複する行、明示的な零係数を拒否する。項がない行の尺度は1である。

## 全行・全項の厳密な照合に通過した

| 観測 | 全背景 | U形切断 |
|---|---:|---:|
| 行尺度の照合 | 20,032 | 5,634 |
| 全列境界の照合 | 1,497 | 1,497 |
| 非零係数の照合 | 2,146,784 | 524,715 |
| 固定領域の計画と実容量 B | 450,631,648 | 110,304,104 |
| 行尺度の最大幅 bit | 110 | 110 |
| 整数係数の最大幅 bit | 127 | 124 |
| 算術中の追加確保試行 | 0 | 0 |

動的な参照は、同じ展開済みの有理行列から全行の最小公倍数を直接求め、各有理係数に掛けた結果を固定領域版と比較する。Pythonの `Fraction` でも凍結係数と組立写像から候補列を組み直し、厳密な相殺後の非零数を全候補で照合した。両領域とも各起動60秒以内、計画上限48 GiBの範囲に収まった。[検証結果](result.json)

手計算で追える負係数と空行、容量ちょうどと1バイト不足、不正な行・重複・零項、入力幅の境界、LCMと整数係数の幅超過を確認した。双方が1,536ビットの最大値でも、3,072ビットになる積を追加確保せず保持してから狭い領域への格納を拒否した。容量計算のオーバーフローも拒否した。

## 再現と範囲

1. `probe.cpp.txt` をWindows x64のMSVC 19.51.36260、Boost 1.92.0でビルドする。指定は `/TP /std:c++latest /O2 /EHsc /MD /DNOMINMAX` と `/STACK:67108864`。Boostと `allocation-profile.hpp.txt` のあるディレクトリをインクルード先に加える。
2. `python -B run-integerization.py.txt` に凍結係数、バイナリ、調査記録、既存のバッチランナー、パス検査、容量検査器、独立計数器、別の出力先を渡す。両領域の完了後に結果を公開する。
3. `gate-probe.py.txt` を通常モードと `-O` で実行する。各モードで公開条件8件と7入力の直接指定・ハードリンク衝突14件を確認した。切断側の途中失敗、件数不一致、監査件数の欠落は公開前に拒否し、旧出力または未作成状態を保持した。[公開ゲートの結果](gate-result.json)

追加確保の監査範囲は、確保済みの領域での事前検査、行尺度の作成、整数化である。計画容量は列挙した配列と作業領域の保持量を表す。元の有理行列を作る動的な展開、配列の初回確保、動的な参照計算は別工程である。共有持上げへの接続、有限体探索と証明書読取りを含む全準備の共通ResourcePlan、辞書・分割との同時保持、製品実装の開始審査は親Issue #140で扱う。
