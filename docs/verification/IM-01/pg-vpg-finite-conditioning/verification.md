# 凍結R4・R5の有限則でPG基底を認定する

凍結R4品質系列24配置、追加係数系列4配置、R5第2版4配置の計32配置を照合した。格子の内訳は $n=1$ が8、$n=2$ が16、$n=4$ が8。厚さは原本の $1/100$ と $1/10000\,\mathrm m$、保持する層は各凍結配置と同じ全厚の単層。入力の元行とケースキーは凍結監査のハッシュを確かめた上で固定した。

## 試験入力と合格条件

各形状を厳密な `PgGraph`、共通分割と参照幾何、局所rankと `PgReferenceBasis` の順に準備した。各三角形の候補内点から、元の $R/P/C$ の評価で有限体上の独立行が増える点を選んだ。全体積片から少なくとも一点を取り、各面内点に3つの深さと正の重みを与えた。この点列は試験用の入力であり、有限体の選別結果を製品の適格判定には使わない。

`PgDiscreteGram::prepare` でこの同じ点列の区間Gramを求め、`generate_and_certify` で合同変換の最大絶対行和を認定した。Gramの作業・出力の小数部は768／704ビット、因子・候補の小数部は768／128ビット。認定値を厳密分数として読み、採用上限 $10^{-20}$ 以下であることを照合した。結果が所有する点番号・座標・重みは全項を照合した。33必須場は認定後の座標に所有変換 $T$ を掛け、元基底の全行と厳密に比べた。保護部分の後ろは厳密な零となった。

準備には1つの48 GiBの `ResourcePlan` を使い、有限点列の選別と独立照合には別の計画を使った。Gramと因子はそれぞれ整数演算の上限 $10^{13}$ で実行した。準備の累積課金とプロセスの最大常駐量を分けて記録した。各配置は新しいプロセスで実行した。Gramと因子の所要時間はその製品呼出しの時間、全体時間は試験入力と点選別を含む。

有限則自身に対する合同認定を扱う。連続内積の一般曲面への収束、材料・整合質量、構造応答の受入にはそれぞれ独立した比較が必要である。凍結R4の2曲面接続には別の厚さと幅があり、その有限則認定は接続の検証記録に収めた。

mixed quartic の $n=1, h=1/100\,\mathrm m$ はMSVCでも再実行した。両環境で基底列数171、体積片8、点数267、必須場の保護ランク31、厳密比較5,643が一致し、合同誤差上界も同じ分数となった。上の表にこの再実行は含めていない。
集計器はケースキー、Gram記録、必須場の比較数、準備累積課金を個別に書き換えた対照を拒否した。

全準備の時間は認定の完了までを測った。独立照合の時間は除き、プロセスの最大常駐量は独立照合までを含む。
LinuxのRSSは `getrusage`、Windowsは `PeakWorkingSetSize` からバイト単位で記録した。数値計算を変えないヘッダー順と静的解析用のコメントの差を含むため、測定した両コンパイル入力のハッシュと配布ソースのハッシュは分けて記録した。

## 再実行

[実行ソース](run-series.cpp.txt)をC++23としてコンパイルし、Releaseの `uvlas_structure`、`uvlas_numerics`、`uvlas_core` と Catch2 MainおよびCatch2をリンクする。インクルード先は `include`、`src/structure`、`tests/structure` と依存ライブラリ。MSVCには `psapi.lib` と `/STACK:67108864` を指定した。

[集計ランナー](run-series.py.txt)にリポジトリルート、上の実行ファイル、新規出力ディレクトリを渡す。既定では全32配置を実行する。格子別に実行する場合は `--grid 1`、`--grid 2`、`--grid 4` を使う。スコープ内の全ケースが合格した時点で集計を公開する。
