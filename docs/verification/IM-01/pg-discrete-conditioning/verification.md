# PGの離散合同変換と必須場の検証

[離散変換の認定契約](../../../specs/structure/pg-discrete-conditioning-certificate-contract.md)を検証する。Windows 11 x64、MSVC 19.51.36260、Boost 1.92.0。

- 全背景のn=1平板、有効rank 109の参照基底を製品の辞書・分割・rank・参照準備から作った。試験は厚さ2 m、参照長1 m、単位平板に対する全5,995内積成分を局所単項式の解析積分で計算した。128 bit二進格子へ上下に丸め、全成分について元の有理数を含むことを確認した。
- 試験側の近似Choleskyで得た変換候補を製品の合同認定に渡した。3本の合同変換行は別経路の厳密有理演算で計算し、報告上限以下であることを確認した。変換係数の取得と `B T` を照合し、全33必須場・3,597座標で `T W_new=W` を厳密に再構成した。
- 行和の負対照では対称行列に二つの2⁻⁶⁷の幅を与えた。個々の成分は10⁻²⁰以下でも同じ行で足した上限は許容値を超える。幅を一つ消すと返却上限は厳密に2⁻⁶⁷になった。寸法の不一致、逆順区間、格子外の係数、零対角、事前取消、作業と容量の等号と1不足も検査した。

解析平板は独立した認定用の参照ケースである。製品の共通細分求積と曲面の区間内積を供給する工程は、既存の保証付き条件付け段階に属する。

認定の追加確保は3,935,552 Bで、事前算定と同じだった。全体の作業量は4,516,355単位、合同誤差の厳密な上限を十進で切り上げると3.810×10⁻²¹である。

Windows DebugとReleaseで、条件付け認定・参照幾何・rankの対象CTestを各3件確認した。認定試験は2ケース・18,704アサーション。clang-tidyは認定、rank実装と認定試験を確認した。行和を成分最大値へ置き換えた隔離版は、許容値を超える行を誤って受理し、負対照が失敗を検出した。

### PR #284のsanitizer回帰

Ubuntu 24.04 x64、GCC 14.2.0、Boost 1.92.0のASan・UBSan構成で、修正前のdd4aa81を再実行した。試験用の変換候補を生成する際、十進数の厳密な零をBoostの整数へ変換すると、内部で `ilogb(0)` が返した `INT_MIN` を符号反転して停止した。

試験では丸め結果が零のときに整数の零を直接構成する。3499bfcでは同じsanitizer設定で `structure.pg_conditioning` が成功し、2ケース・18,704アサーションを通過した。UBSanは最初の未定義動作で停止し、スタックを表示する設定で実行した。
