# PG面の接線写像と転置の検証

[面接線写像の契約](../../specs/structure/pg-boundary-tangents-contract.md)に従い、層境界と外周側面の2方向について、固定したPG基底の微分と共役作用を検証した。SH-D02、SH-D05、N4-02、N4-03、N4-06、N4-08、N4-09に対応する。

## 三角形と側面の独立微分

2層の平板で、入力を上層の下面、外周側面、下層の上面、上層の下面の順とした。共有界面では同じ三角形座標を指定する。外周側面は格納辺の方向と境界の反時計回り方向が逆のレコードを選んだ。側面の深さ方向には、選んだ層の厚さ座標の差が入る。

参照値は局所単項式を $s,t,\zeta$ で項別に微分し、共通三角形の頂点差、または反時計回りの辺差と層端差を掛けて求めた。参照値の入力には元の基底項、変換係数、頂点と層端の値を使った。Binary64では単位回転、TwoWordではCartesian軸の巡回回転を与えた。全109列、4点、2方向、2形式の計1,744係数を、有理数で得た参照値に照合した。基底微分の絶対誤差枠はそれぞれ $2^{-43}$ と $2^{-90}$ とした。

## 作用、所有、反復

保持した語を有理数へ戻した入力から、順方向の24成分と転置の327成分を各精度で別計算した。計702成分を、Binary64では $2^{-32}$、TwoWordでは $2^{-75}$ の誤差枠で照合した。順方向と転置の仕事の差は、成分の誤差枠を入力の絶対和で重み付けした値以下だった。

準備では二つのCartesian方向と射影前の積和に備え、既存の参照点評価の見積りに有理数32枠を加えた。点順、参照識別、セル、面番号、層、面側を面位置の記録と照合した。面位置と認定基底を破棄した後に接線結果を読み出し、両方向に作用させた。空の点列、停止済みの準備、確保・訪問・精度枠の不足、移動元からの適用を確認した。

同じ結果とWorkspaceを使い回し、成功9呼出しと精度拒否2呼出しでC++の確保試行がいずれも0だったことを確認した。作業量の1不足、Workspaceの1 B不足、取得済みWorkspace、非有限入力、取消、誤差枠0の後も前回の出力を照合した。体積と面位置の従来試験も同じ対象で実行した。

## 向きの負対照と実行環境

隔離したLinuxソースで側面の反時計回りの指定を無視し、格納順のまま辺差を計算した。基底微分や順方向・転置の照合が679件失敗した。変異を戻した後は、Linux側の入力と検証コミットのSHA-256が一致した。

Windows 11 x64ではMSVC 19.51.36260でDebugとReleaseの `structure.pg_conditioning` が通過した。Ubuntu 24.04 x64ではGCC 14.2.0のASan・UBSanで同じ対象を実行し、13ケース・193,162アサーションが通過した。Boostは両OSで1.92.0を使用した。clang-tidy 21.1.1は接線射影、作用、条件付け試験の3翻訳単位を検査した。
