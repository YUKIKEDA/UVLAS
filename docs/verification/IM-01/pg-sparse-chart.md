# PG大域原拘束と固定ピボット疎チャートの検証

[大域原拘束](../../specs/structure/pg-global-constraints-contract.md)から[固定ピボット疎チャート](../../specs/structure/pg-sparse-chart-contract.md)を組み立て、実パッチの元行に対する位置、接線、力と仕事を照合した。

- **大域集約**。隣り合う3パッチを、空間上の並びと異なる B、C、A の順に配置した。AB、BCの接続、Cの非零固定支持、ABと同じ係数を持つ別IDの接続を入力した。元行ごとの疎係数を局所の代表係数と元尺度から再構成し、固定支持の右辺、零行、物理区間を照合した。各局所作用と残差と転置を集めた参照に一致し、独立の有理積和でも仕事が一致した。局所のパッチとトレースを破棄してから同じ大域結果を得た。登録ID、接続先、上限ちょうどと1不足も調べた。
- **選択**。同じ物理IDを持つパッチと拘束の登録順を入れ替え、後順位の重複を外しても、元行の物理ID・元行番号と物理ピボット列は一致した。ABと同一の接続をより早い物理IDへ変更すると、元行の反力を戻す先もそのIDへ移った。固定支持の行は、接続の物理IDより後の番号でも先に選ばれた。
- **写像と力**。固定支持の右辺で復元した位置を全原行に入れ、厳密な残差零を確認した。任意の独立座標と全座標の力に対して、$f^T Jr=(J^Tf)^T r$ を独立な有理積和で照合した。選んだ元行に戻した $\lambda$ から、$C^T\lambda$ と自由列の力で元の全座標の力を再構成した。後順位に置いた重複行の乗数は零だった。
- **右辺と状態**。元行に既知の有理座標を作用させた右辺から、その座標を厳密に復元した。元行に同じ係数が2回現れる箇所で片方だけに一次係数を与えると、時刻零で適合する場合でもその係数は拒否された。互いに矛盾する固定支持、別のチャート世代、再入、ピボット容量不足も拒否した。無拘束では全列が自由になり、既定で計時しない。

物理的な時間依存支持の準備には、時系列の共通区間と区間ごとの全係数および必要な片側導関数を渡す入口が残る。ここでは渡された厳密な元右辺または係数の適合を検査した。R-02の実規模系列は別に扱う。

## 実行と準備の計測

ソースは `4f6ae086`。MSVC 19.51.36260のReleaseとDebug、Ubuntu 24.04のGCC 14.2.0（ASanとUBSan）で `structure.pg_full_trace` の2ケース、33,627アサーションを確認した。CTest時間は順に11.65秒、63.30秒、118.89秒。UBSanは最初の違反で停止する。Boostは1.92.0。関連2翻訳単位をclang-tidy 21.1.1で確認した。

大域集約だけを独立に検証した `ef632860` では30,625アサーションがMSVCの2構成とGCC14の同じsanitizer構成で通った。集約で元尺度だけを落とす変異は、最初の不一致で停止させて56件中1件で検出した。固定ピボットで支持優先だけを抜いた `2b9548be` の変異は、最初の保持行が支持でなくなることを29,589件中1件で検出した。

MSVC Releaseの `2b9548be` の計時例では、三成分組に共通のrankは95、元CSRの非零は8,213、$L$ の保持項は151、$U$ の保持項は3,963。ピボット、一時行と因子の容量は300、327、30,000項。準備のResourcePlan累積課金は7,254,936 B、開始から公開直前までの準備時間は416,920,500 nsだった。これは3パッチの単一標本であり、R-02の系列計測とは別に保存する。
