# PG体積質量の参照点投影の検証

n=1平板で、Binary64とTwoWordへ投影した全列が指定の誤差枠に収まった。対象はSH-D02、SH-D03、SH-D07とN4-02、N4-03、N4-06、N4-08。 [体積質量に渡す認定参照点の契約](../../specs/structure/pg-volume-mass-reference-contract.md)

## 体積点列から実際の格納値まで

点は2つ。n=1平板の同じ基準三角形で、材料層を逆順に指定した。基底の認定には解析積分で得た幾何内積を使った。体積Jacobianと全109列のNを、Binary64とTwoWordに投影した。試験側は三角形のチャートJacobianに層幅を掛けて体積Jacobianを求めた。また、元基底の局所単項式と変換係数からNを評価した。格納した語の仮数と指数から有理数を復元し、両者を比較した。両形式を合わせてNの436成分と体積Jacobianの4成分を照合した。

Binary64の枠はNが $2^{-43}$、体積Jacobianが $2^{-53}$ m³。TwoWordの枠はNが $2^{-90}$、体積Jacobianが $2^{-100}$ m³。TwoWordで高位だけを用いると、体積Jacobianが設定した枠を超えることも確認した。点の順、層ID、セル、分割記録番号、参照識別子と、ResourcePlan破棄後も読める所有配列を検査した。

## 丸め境界と失敗

正負の隣接中点、負の最小subnormalの半分での符号付き零、最小subnormal付近の偶数丸め、最大有限値とoverflowの境界を照合した。$\sqrt{2}$ の高位と低位は、Python `decimal` の140桁計算から独立に丸めた固定値と照合した。平方根が有理数となる場合の厳密な相殺、誤差枠ちょうどの成功と隣接する小さい枠での拒否も検査した。

不正な精度タグと誤差枠、事前取消、確保と走査の枠不足、厳しすぎる誤差枠、後ろの不正な点を拒否した。投影失敗後も同じ認定元を使えることと、成功時に認定元が結果へ移ることを確認した。

中点で常に大きい絶対値を選ぶ変異では、4アサーションが失敗した。正の中点で高位と低位が変わり、負の極小値で符号付き零が失われた。

## 実行と適用範囲

Windows 11 x64のMSVC 19.51.36260とBoost 1.92.0で、Debug、Releaseの条件付けと参照幾何を検査した。両構成で計2件ずつ通過した。Ubuntu 24.04 x64ではGCC 14.2.0とBoost 1.92.0を使い、ASan・UBSan付きの同じ2試験を各180秒の上限で直接実行した。条件付け6ケースの33,269アサーションと参照幾何10ケースの1,710アサーションを通過した。UBSanは最初の違反で停止する設定とした。clang-tidy 21.1.1は3翻訳単位を検査した。 [検証記録](im01-pg-volume-mass-reference.json)

質量作用の精度と計算費用は、層密度、求積および下流の両語消費を含む条件で検証する。
