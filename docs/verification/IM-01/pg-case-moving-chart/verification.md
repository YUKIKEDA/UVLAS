# 同じCaseのPGチャートで動く全厚支持を評価する

凍結R4の二曲面のうち、整合分割 $(1,1)$、厚さ $1/20\,\mathrm m$ のCaseを使った。形状とJoint #1を保ち、左外周のSupport #1に並進 $t^2(1,2,-1)$ [m] を与え、右外周に静止Support #2を置いた。両支持は3成分の全厚位置拘束。姿勢は一定、時刻は秒。平面対照では同じCaseの高さ係数だけを零にした。

## 独立照合

型とSIを確認したCaseを `prepare_case_pg_motion_chart` に与え、同じ所有パッチを使って作った全厚元行と疎チャートを共通時計の支持へ渡した。入力Caseと点の一時保管を破棄した後、基底の物理ID・列配置、Jointと各Supportの元ID、および `CaseStructuralSupport` と表に返したチャートの同一性を確認した。

時刻 $t=1$ で前区間の左側と後区間の右側を評価した。動く支持の位置・速度・加速度に使う並進係数はそれぞれ $1,2,2$。独立に元CSRと単位並進の係数を積和し、各次数の公開TwoWord包絡が独立値を含み、絶対半径が $2^{-44}$ 以下であることを確かめた。共通ジェットから得た有理中心と、同じ因子で復元した座標の全元行も独立値に一致した。Jointと静止支持は位置の参照右辺を保ち、速度・加速度の右辺は零だった。自由成分を零に固定して独立な有理力を入れ、各次数で元力の仕事と元乗数・右辺の仕事を照合した。

平面の負対照では右の静止支持を左の動く支持と同じ辺へ移し、全時刻を表す生成子が両支持を満たせないことから拒否された。最外の取消および下位の支持算術からの事前取消は、同じ計画の累積課金ゼロで `Cancelled` になった。

## 結果

| 形状 | 元行 | rank | MSVCの累積課金 [B] | GCC 14の累積課金 [B] |
| --- | ---: | ---: | ---: | ---: |
| 平面対照 | 288 | 111 | 600,878,042 | 606,196,698 |
| 凍結R4の曲面 | 288 | 172 | 4,737,034,498 | 4,757,961,842 |

両環境で3試験・228,134アサーションに合格した。正対照2件で元右辺の成分10,368個を比較した。
表の課金は、準備から独立照合までの累積ResourcePlan。既存Case支持の2 CTestと、静止Case入口の6,499アサーションも両環境で通過した。

静止元行の速度へ位置の右辺を誤って写す変異だけを別バイナリで実行すると、独立な包絡比較が絶対差1、半径0で失敗した。
実行後の配布ソースでは試験用の形状enumに8ビット型を指定し、Clang-Tidyで検査した。製品ソースにはその差がない。

## 再実行

[実行ソース](run-case-motion.cpp.txt)をC++23としてコンパイルする。凍結Caseの静止チャートと有限則の両実行ソースをインクルード先に置く。リンクするReleaseライブラリとスタックの設定は静止チャートの検証と同じ。リポジトリルートで `python -m tools.qa.vpg_case_reference generate <新規出力先>` を実行し、その出力先を作業ディレクトリとして、実行ファイルに `[.case-pg-moving-chart],[.case-pg-moving-curve]` を指定する。

この検証は[Caseチャートの指定運動](../../../specs/structure/pg-case-chart-contract.md)と[全時刻の元行適合](../../../specs/structure/pg-case-structural-support-contract.md)を扱う。材料・質量・剛性・平衡応答はIM-02で同じ参照と拘束を使って判定する。
