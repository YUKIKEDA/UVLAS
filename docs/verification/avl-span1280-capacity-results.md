# N1280候補：容量経路の準備・回帰結果

2026-10-31。[事前仕様](avl-span1280-capacity-experiment.md) に従い、N1280を扱う別容量版と既存8ケースの回帰を検証した。N1280の数値計算はまだ実施していない。

## 1. 求解経路と容量

親のspacing-pi64対称計測版を保持し、別の `source-symmetry16000-spacing-pi64` を作った。ソース変更は2ファイル・3定数のみ。NVX／NVMAXを16000、NSMAXを1000へ増やした。核・分点・物理入力・LU・計測・出力規則は変更していない。

[準備記録](avl-span1280-capacity-preparation.json) は全ソース、差分、コンパイラ、リンクライブラリ、41再コンパイル対象、親実行体と8入力を識別する。[容量差分](fixtures/avl-measurement/capacity16000.patch) も保持した。COMMON／moduleに関係する全オブジェクトを再コンパイルし、明示的DOUBLEの同梱LAPACKソースはREALの倍精度化オプションを付けずに維持した。

## 2. 資源監査と見積もり

[Linux資源監査](avl-span1280-resource-audit.json) では、メモリ総量25,102,790,656 bytes、利用可能24,249,987,072 bytes、swap使用0だった。cgroup v2の可視な当該階層と親を照合し、この時点で有限な追加メモリ制限はなかった。外部blas／lapack／openblasはライブラリ探索で未検出。インストールや交換をせず、同梱逐次LUを使う。

容量16000の密配列割当は14,336,000,000 bytes（13.35144GiB）。実未知数15360による算術値13,212,057,600 bytesとは区別する。その他の配列等を含むピーク値の保証ではない。既存N640の最大93.35秒を8倍した時間シナリオは746.80秒であり、これも性能保証ではない。

N1280段階は開始前の有効利用可能20GiB、プロセス群RSS16GiB、各1200秒・計2400秒を別予算として固定した。実行中は空き2GiB未満、swap増加256MiB超過でも停止する。現在のスナップショットだけで将来の開始を許可しない。

[資源判定の製造試験](avl-span1280-resource-guard-result.json) は6件が成立した。親cgroupの有限制限、子の制限、両者の厳しい側、残量0、制御情報不明を含み、空きの過大評価や不明状態での細分化開始を拒否する。実際のOS隔離や停止時刻の試験を代替するものではない。

## 3. 回帰で確認した範囲

[回帰記録](avl-span1280-capacity-runs.json) はFW-V01／02のM6N40、M24N160、M24N320、M24N640、計8件。FT／FS／FE、元の行・力・帯、対称モードmeta、ガード試験は計測前後と親8000版の両方に対してバイト一致を検査した。小系では元行列のbinaryも含む。比較出力は計66件。

[独立成果物監査](avl-span1280-capacity-artifact-audit.json) は許可した差分、全再コンパイルのコマンドと精度フラグ、親入力／出力、保存ファイル、時間・メモリ・終了状態、N1280未実行を確認する。数値の許容差へ切り替えて容量変更の相違を許容する処理はない。実測時間・メモリ・保存量は同監査に記録する。

監査は全条件成立。8ケース・66出力の親版とのバイト一致と、計測前後の一致を確認した。

| 測定対象 | 時間 | ピークRSS | 保存量 |
|---|---:|---:|---:|
| 全41オブジェクトのビルド | 30.16秒 | 69,554,176 bytes | ビルドログ等を別保持 |
| 回帰8ケース | 合計261.08秒 | 3,433,209,856 bytes | 73,039,703 bytes |
| FW-V01・M24N640 | 102.20秒 | 3,433,209,856 bytes | 回帰合計に含む |
| FW-V02・M24N640 | 106.09秒 | 3,433,132,032 bytes | 回帰合計に含む |

この回帰の最大実未知数は7680であり、N1280の15360未知数を解けた証拠ではない。小さい問題で仮想配列が割り当てられたことから、全配列のページが常駐したとも推定しない。ファイルfaultとswapを同一視せず、major／minor faultとswap使用量を別記録とする。

## 4. 次に実行する範囲

次は [事前仕様4節](avl-span1280-capacity-experiment.md#4-n1280の開始ゲートと予定ケース) に従って、N1280専用ランナーと8入力を用意する。両翼M3／6／12／24を同じ版・同じN1280で計算し、N160／320／640／1280のスパン窓と、N1280の弦系列を同じ基準点で評価する。旧版との混用や次数条件の緩和は行わない。

スパン窓のN160／N320／N640には、今回の16000版回帰で保存した場を使う。容量だけが違う旧版とバイト一致していても、比較系列そのものを同じ容量版で揃え、親の追跡を単純にする。

モーメントの誤差は引き続き未評価。容量回帰の成立を、参照全体の受入、保証された連続解誤差、非対称／動的連成、UVLAS荷重一致、J1や製品数値コアの開始へ昇格させない。

## 5. N1280実行時に判明した追加容量（2026-10-31）

最初のN1280入力は、amake.fの局所KSMAX=500によりLOAD段階で停止した。前回の容量調査はこの局所上限を含められていなかった。[初回失敗](avl-span1280-fine-runs.json) を保持し、[局所容量の追加仕様](avl-span1280-ksmax-addendum.md) で別版のKSMAXだけを1000へ変更した。[全8入力の読込み](avl-span1280-load-result.json) と既存8ケース・66出力のバイト回帰が成立し、[修正版監査](avl-span1280-capacity-ks-artifact-audit.json) を経て再実行の開始条件を満たした。

通常console／FEの整数幅には制限がある。[読込み表示の追加仕様](avl-span1280-load-diagnostics-addendum.md) に従い、最細の未知数はUH meta・行数を用いて確認する。局所容量の修正を整数表示の書式変更と混ぜない。修正版回帰ランナーのビルド資源ハッシュは親版ファイルを指す記録のまま保持し、修正版の実際のビルド資源は監査JSONで別にハッシュ・検証した。初回や既存マニフェストを上書きして整合を装わない。
