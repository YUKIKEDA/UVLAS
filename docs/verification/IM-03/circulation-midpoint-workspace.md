# 有限翼の循環と荷重に使う P1 の費用

凍結斜翼 FW-V02 の M4/N8 で、迎角 $-1^\circ$ と $+1^\circ$ の循環、非貫通の元残差、近傍抗力と Trefftz 抗力を比較した。循環から荷重までを同じ製品経路で計算する。入力と独立参照には、既存の [有限翼格子系列](finite-wing-drag-refinement-v1/verification.md) を使った。

## CPU 採取と定数の再利用

GCC 14.2.0 Release の基準を Linux の論理 CPU 4 に固定した。Intel Core i5-13400F、WSL2 の kernel `6.18.58.1-microsoft-standard-WSL2`。`perf record -e task-clock -F 99 --call-graph dwarf,8192` は 7,888 サンプルを取得し、欠落は 0 だった。スタック最上位の一部と標準ライブラリの行番号は解決できなかった。製品の関数では `P1Engine::evaluate` の包含が 53.85%、π の区間を計算する `pi_constant` の包含が 14.97% だった。

同じ整数演算で求めた π と ln 2 の区間を P1 作業領域に一度ずつ保存する。常に初回の評価を含めた最大仕事量で入口を判定する。再利用時の実行仕事量からは省いた演算を差し引く。冷えた作業領域と再利用時の基底・13変数微分について、中心の上下語、包絡半径、指数をビット単位で照合する。

基準の `81f2fb94` と、定数の再利用だけを加えた `e4d0e4d7` を別々にビルドした。表の秒数は、計測器を外し、同じ CPU でプロセスを交互に起動した各巡の経過時間である。毎回、冷えた状態から入力準備と製品計算を実行した。両ビルドで同じ入力を使ったことは、有限翼格子系列 `finite-wing-drag-refinement-v1` の SHA-256 `29b7cf5fd5301a0b4ebfc684e81b9cf70a90fa7305f34451a88e9da5cbd15878` で確認した。

| FW-V02 M4/N8 | 1巡目 [s] | 2巡目 [s] | 3巡目 [s] |
| --- | ---: | ---: | ---: |
| 基準 | 80.964 | 81.262 | 88.529 |
| 定数の再利用 | 68.057 | 67.550 | 72.246 |

最短時間は 80.964 秒から 67.550 秒へ16.6%短縮した。全6回で1,647アサーションに合格し、近傍抗力、包絡半径、Trefftz 抗力の表示値が一致した。累積確保量は 356,038,352 B から 356,038,368 B へ増えた。

## 荷重中点の累積確保

正式格子 M128/N192 の束縛四辺形は24,576面で、三角形は少なくとも49,152枚。後縁を除く荷重中点は $128(2\cdot192+1)=49{,}280$ 個ある。中点ごとに三角形の点と強度の添字を確保すると、64-bit 環境ではこの二つの配列だけで $49{,}280\cdot49{,}152\cdot48=116{,}266{,}106{,}880$ B を累積計上する。一つの迎角で 108.28 GiB となり、24 GiB の制限を超える。

初回に確保した作用の配列を中点間で再利用する。毎回、正準辺と同じ中点であることと対象辺が後縁に属さないことを検査する。共有辺では束縛側の自己寄与を除き、後流側を保持する。照会点の解決費用には報告された実行仕事量を使う。

GCC 14.2.0 Release の `ResourcePlan` に記録した、循環評価と荷重の累積確保量を比較した。両翼とも、近傍抗力と Trefftz 抗力をそれぞれ独立参照と照合し、基準との表示値の一致も確認した。

| ケース | 基準 [B] | 定数と作業領域の再利用 [B] | 削減率 |
| --- | ---: | ---: | ---: |
| 水平翼 FW-V01 M2/N4 | 32,814,614 | 14,503,574 | 55.8% |
| 斜翼 FW-V02 M4/N8 | 356,038,352 | 121,039,504 | 66.0% |

二つの異なる正準辺を使う局所試験で、再利用の有無による速度の中心と包絡半径が厳密に一致した。別の自己辺を指定すると確保前に拒否した。初回と次回に必要な累積確保量ちょうどで成功し、1 B 少ないと2点目を確保する前に `ResourceExceeded` を返した。共有辺には束縛強度を零にしても後流の誘導が残った。

この計数は上の添字配列に限る。作用・求解・全履歴を含む総容量と実稼働時間は、正式格子での検証が残る。直接経路の束縛三角形だけでも、循環の組立てと元残差の二巡、および荷重中点で一迎角あたり少なくとも $2\cdot24{,}576\cdot49{,}152+49{,}280\cdot49{,}152=4{,}838{,}129{,}664$ 回の組合せがある。

## 対象試験と負対照

両変更を含むソースは `c52c7973a44823842d53b3b878d556d110a253e9`。GCC 14.2.0 Release では `aero.p1_induction`、`aero.p1_shared_action`、`coupling.case_uniform_flow`、`coupling.finite_wing_drag_refinement.fw_v01.m2n4`、`coupling.finite_wing_drag_refinement.fw_v02.m4n8` の5件が合格した。Windows 11 の MSVC 19.52.37029 Release では局所核・共有作用・水平翼 M2/N4 の3件が合格した。Windows の JSON パーサーは、無変更の翻訳単位に MSVC 19.51 の既存オブジェクトを使用した。

隔離した GCC ビルドで π を毎回計算すると、2回目に省ける仕事量を照合する試験が失敗した。再利用時に自己辺の指定を落とすと、別の辺を拒否し、失敗前の確保量を保つ試験が失敗した。二つの変異は計測と通常試験に含めていない。
