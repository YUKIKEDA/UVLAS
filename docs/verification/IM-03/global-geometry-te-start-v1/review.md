# 大域幾何・TE所有の設計検証

2026-11-18。Issue #134、IM03-5。対象は新しい開始契約と独立設計oracleであり、製品実装の試験結果ではない。UW-D04/07/08、UI-D01/03/05/06、N4-02/03/06/08/09のうち、有限三角形の許容接触、正規所有、資格、精度保持と資源計画を具体化した。

## 確かめたこと

Windows 11、CPython 3.12.8、標準ライブラリのFractionのみを使用した。製品コード、旧NumPyの平面切断、製品用の符号述語はimportしていない。oracleは6重心座標の非負多面体の基本実行可能解を列挙し、交差の頂点集合を求める。literal期待値とは許容差0で比較した。製品が採用する二平面切断/共面投影とは別の計算経路である。

12幾何例それぞれの全6×6置換で、交差のliteral頂点集合、共有実体への包含、閉AABB候補の包含を確認した。追加の尺度3組を含め、出力の `geometry_checks` は1332である。これは独立assertの全総数ではなく、この幾何系列の3項比較と尺度比較の数である。

例は非交差、非平行横断、許容一点、共有点を越す交差、共有辺、同端点別EdgeId、同一平面の共有辺/面積重複/包含、共線辺の部分重なり、一致面、非零低位gapを含む。尺度は二進指数±900、巨大共通原点は2^900とした。Fractionの座標は低位を失わない。別にbinary64のhigh=1/low=2^-60を個別復号し、high+lowをbinary64で先に加えると失われる差を確認した。

固定quad二子の交差は正規対角だけになる例を確認し、その対角をTEにする入力は拒否される。三面共有辺の例では共有線分内の接触を許す一方、複数Bound出現の辺をTEにしない。二つのquadのliteral境界を整数で組み立て、D1D2=0とT=単位行列を独立に確認した。wakeの誘導符号と幾何正境界は逆である。alias辺の向きを正規基底へ直す必要も負対照に含めた。

共有TE頂点3はepoch7で一ownerになり、epoch8/uint64最大とは異なる。AttachedとMaterialも別identityである。これは放出計画の一意性を確認する設計例であり、実製品の二重commitを試験していない。

速度のexact作用には1+2^-200+2^-400を使い、三つ目の有効bit帯が残ることと、さらに小さい不一致を拒否できることを確認した。速度/J/時間項の一致は共通の全成分比較のliteral例である。providerの物理写像を証明した結果ではない。180度回転した法線とdirectorが一致しても参照法線との内積が負になる例を置き、法線dotだけの反転判定を採用できないことを示した。

## 負対照の意味

8件の `negative_controls` を全てtrueと確認した。開AABBへの置換、共有点を持つ面対の全skip、許容点の両端だけを調べる判定、T符号反転、alias基底未変換、内部TEで最初の面を選ぶ経路、J末尾列無視、epoch無視が、それぞれliteral必要条件を破る。T/内部TE/Jは共通の小さな意味kernelに置換引数を渡して対照した。他は反例の期待値と誤った判定を直接比較した。製品ソースのcompile/linkを伴う変異試験とは区別する。

## 残る製品gate

製品のBVH、整数容量端、動的入力の全範囲、CSR/word decoder、資源計画と実step、各確保故障、lease再入、キャンセル、所有寿命、失敗後親不変、1/2/4並列byte一致は未実行である。新契約7節の製品gateへ残す。物理写像provider資格と時間経路の正則性を、この接触oracleから生成しない。現在の局所P1資格を大域資格へ書き換えていない。

本記録はR-03の製品規模の時間/メモリ予算を満たしたとは主張しない。BVH count passのnode対上界は安全側のadmission式であり、実規模の費用実測はIM03-0の対応子作業で行う。実際のcapが実務入力を拒否する場合は、品質を下げず資源計画を再審査する。
