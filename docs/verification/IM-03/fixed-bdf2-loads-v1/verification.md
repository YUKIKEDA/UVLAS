# 固定刻みの循環レートを同じ試行の荷重に使う

型付きCase時計の同じ区間から連続する三つの節点を取る。過去二点の循環には既存の原残差を通った解の保持語を使い、物理面IDごとに保存する。三点でCase、厳密な刻みと時刻、同じ準備済み接続を照合する。現在の循環は荷重試行の中で一度解く。 [採用済み時間法](../../../specs/coupled/coupled-adopted-specification.md)・[実装](../../../../src/coupling/fixed_bdf2_circulation.cpp)

## 値と前進・転置

$$
D_h\Gamma=(3\Gamma_2-4\Gamma_1+\Gamma_0)/(2h).
$$

レートは区間包絡のまま三角形の非循環力に入り、全ベクトル荷重と同じ試行に物理面ID付きで残る。固定した過去値と刻みでは、接線に $3\delta\Gamma_2/(2h)$ を用いる。転置ではレートの種に同じ係数を掛けて現在循環の種へ加え、保持した原行列の転置を解く。

刻み $h=1/10$ s の三点について、翼面速度を変えてそれぞれ循環を求めた。独立な有理数計算で両保持語を加え、レートと密度・面積による非循環力を照合した。現在の翼面速度だけを摂動し、レートの接線が $15\delta\Gamma_2$ となることと、全合力の前進と転置で仕事が一致することを確かめた。 [試験](../../../../tests/coupling/case_uniform_flow_test.cpp)

## 取り違えと適用範囲

節点または循環解の順序を入れ替えた入力を拒否した。同じ名前と世代で末端だけが異なるCase、独立に作り直した接続所有者も流用できないことを確認した。

MSVC 19.51のDebugとRelease、GCC 14.2のReleaseで対象CTestは各4件が通過した。重点試験は各構成で85件のアサーションを確認した。

実装時のMSVC Debugで既存の全荷重試験がスタック上限を超えた。BDF2専用の区間一時値を別の関数へ移し、既存荷重と新経路を合わせた重点試験5,603件を通過した。

隔離したLinuxビルドで過去差分の符号を反転すると、保存レートと二つの三角形力の照合が失敗した。転置に渡すレートの種だけを零にすると、双対仕事の照合が失敗した。それぞれ元のソースとバイト列が一致することを確かめ、復元後の重点試験は通過した。

この入口の入力は一様流・指定移流の準備済み時計と、同じ接続を用いた数値認定済みの循環解。受理済み物理履歴の取得、イベントの再始動、自由後流と非一様流を含む連成時刻ステップ、受理済み三点のファイル保存はIM-04とIM-06の接続先で検査する。 [最終微分規約](../../../specs/coupled/j1-initialization-output-derivative-addendum.md)・[検証票](../im03-fixed-bdf2-loads.json)
