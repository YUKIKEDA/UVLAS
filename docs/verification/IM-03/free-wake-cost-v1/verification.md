# 実自由後流の費用観測

R-03 の早期観測として、同じ連結後流を 2、4、8 枚に延ばし、各既放出行にある左右の物質点をすべて評価した。
束縛翼は 1 枚で、後縁では最初の後流パネルの先頭係数を束縛循環と共有する。
残りの後流係数は各行に属し、保持した下位語も入力に含めた。
コア半径は $1/8$ m、外気は $(1,0,1/8)$ m/s、時刻は $5/4,9/8,1$ 秒とした。
過去二時刻の座標は下流方向に縮み、同じ物質点が現時刻まで進む。
現在・過去の3幾何で接触と後縁所有を検査した。

速度の値、値と順方向、値と転置を別々に測った。
輸送では値と、値・順方向・転置をまとめて返す入口を測った。
Binary64 と TwoWord は同じ物理入力と絶対予算 $10^{-10}$ を使う。
毎回、時計・接触済み幾何・作業域を再利用する。
各受信点の作用は呼出しごとに組み立てる。
結果を返すまでの時間に、作用の予報・組立・計算と公開結果の確保を含める。
三回の再評価で、値・方向・双対の保持語、指数、包絡半径を要素ごとに照合した。

## 計測条件

Windows 11 10.0.26300、x64、Intel Core i5-13400F、16論理CPU、搭載メモリ 51,343,966,208 bytes。
MSVC 19.51、C++23 preview、Release、`/O2 /fp:strict`、1スレッド。
規模ごとに新しいプロセスを起動し、論理CPU 0に固定した。
精度・経路は固定順、各経路3回の測定で、最初の呼出しも含む。
時間と資源は `f160f7e1` の採取値を保存した。
後続の `1daf3a70` では履歴座標を行単位で生成し、三規模すべての入力座標が同じバイナリ語になることを別途確認した。
時間は単調時計で測った経過時間である。
プロセス常駐量を準備後と各呼出し前後に標本化した。
ピークはプロセス全体の最大常駐量で、経路ごとの確保量は `ResourcePlan` に記録される累積payloadである。
両者は別の量として読む。

再現にはRelease構成の `uvlas_test_coupling_case_uniform_flow` をビルドし、[capture.ps1](capture.ps1) の `-Executable` と `-Output` に実行ファイルと出力先を指定する。
測定時の計画上限は、呼出しごとに512 MiB、粒子ごとのP1組立24,000,000,000仕事単位、固定輸送の局所残差1,000,000仕事単位とした。
仕事単位については、[観測表](observations.csv) に速度側で実際に課金された値を載せた。
計測結果の正しさの照合と、表への書き出しはタイマーの外で行った。

## 独立参照

[独立求積](reference.py) は、既存の有限コア参照の線分とシートの積分を各後流行へ適用した。
各規模の最短・最長受信点で鉛直速度を独立計算し、製品の包絡と絶対 $10^{-12}$ の比較余裕で照合した。
75桁演算でGauss–Legendre 64点から88点への最大変化は $2.67\times10^{-27}$ m/s だった。
この差は求積の収束観測である。
V-AEROとは同じ有限コアの照合方法を共有する。
20帯の翼、合力・モーメント、局所荷重、理想核の誤差評価は[V-AERO受入](../../../requirements/practical-acceptance-plan.md)に残る。

観測した30組すべてで、同じ精度・経路の三回の保持語が要素ごとに一致した。
2枚はGCC 14 Releaseでも実行し、10条件×3回の結果の署名がMSVCと一致した。
8枚では遠方積分が加わり、速度と輸送はいずれも秒単位となった。
8枚の時間ばらつきを踏まえ、精度間の速度差や再評価による高速化は判断しない。
この計測では、作用の予報・組立と適用を同じ入口の費用に含めた。
大きい規模で支配する入口の内訳は、この二工程と遠方積分を分けて測る必要がある。

計測の上限は束縛1枚、後流8枚、粒子16点である。
R-03の次の比較には、実PGの構造追従、5,000空力面、全履歴のP作用と再利用、Arnoldiの確保・ピークが要る。
J1の新生・受理・棄却や、複数風速を含む12時間・48 GiBのA5-06受入は別の測定で扱う。
