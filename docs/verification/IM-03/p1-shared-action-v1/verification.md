# 共有辺・四辺形の P1 誘導作用

Issue #266。非空の全回帰と変異に使ったソースは `45936de4ce5f1d6f74c99ad41c993dbe67b249ea`。最終ソース `7db5eb486ba3383c3bd720ec53a35337f0abc6e1` で空の認定済み幾何の厳密な零作用を追加し、影響した共有作用と資源監査を両構成で再試験した。

認定済みの大域幾何から固定分割 `(0,2,1)/(0,3,2)` を評価し、四辺形の L/R 列と独立三角形の三列を元の強度 ID へ割り当てた。実・複素の速度、JVP、VJP は同じ局所係数と点の対応を使う。物質点は元の位置式で観測点微分を各頂点へ割り当てる。複素出力と強度の双対内積には実部付き エルミート内積を用い、幾何と半径の双対量は実数で返す。

同じ認定済み物理辺へ正規化した二つの解析境界項は、同じ core の下で両端の強度 ID が同じ逆向きの組だけを式から外した。独立した強度 ID に同じ数値を入れた場合も、その列の微分を保持する。遠方は採用済みの Gauss12 面積積分を使う。近接・遠方が混在する辺では、遠方の面積積分に含まれる項と対になる近接側の境界項を保持する。求積の差は各局所診断で読み取れる。

## 独立参照

[参照生成](reference.py) は、非平面四辺形と隣接三角形について Rosenhead–Moore の面積分を直接評価する。局所製品実装の境界項・渦層項と異なる式を用い、面積ベクトル、相対位置、半径、強度を全方向に微分した。標準ライブラリの Decimal を 60 桁で使い、Duffy 変換上のテンソル Gauss–Legendre 24、36、48 点を比較した。最大差は順に `4.92391794e−17` と `1.90624793e−25`。この収束差は参照の照合結果である。

製品の値と全方向 JVP は、独立参照との差が絶対 `1e−22` と返却半径の和以内に収まった。元座標、共通原点 `2^900` を高位語へ置いた表現、逆向きに宣言した共有辺 alias の三つで、同じトレースと異なるトレースを試した。複素 JVP/VJP の双対内積も返却包絡の中で一致した。物質辺上の観測点を含めて全点に共通並進を与えると、JVP と VJP の対応する作用に零を含んだ。

## 資源と負対照

Windows 11 x64、MSVC 19.51.36260.0、Ninja Multi-Config。Debug・Release で共有作用、局所 P1 核、確保監査、局所 packet、geometry snapshot、大域幾何の各 6 対象を確認した。新規の共有作用は各構成 5 ケース、286 アサーション。資源の新規ケースは各構成 353 アサーション。Debug は確保回数の集計を実観測に修正し、影響した確保監査だけを再実行した。

単一面の監査で準備の C++ 確保を 77 回観測し、全 77 箇所で失敗を注入した。計画に含まれるヘッダー・配列・共有管理ブロックは 12 回。残る 65 回は既存の Boost による厳密幾何判定で、既存の見積りとして扱う。作用は確保 0 回、VJP は 5 回で、VJP の全箇所の確保失敗も試した。同じ workspace への再入や最後の確保時の取消が起きても、以前の結果を保持した。

[隔離変異](run-mutations.ps1) の対照は 211 アサーションを通過した。トレース ID を無視する変異は 33 アサーションで失敗し、点微分の出現を一つ省く変異は 42 アサーションで失敗した。どちらもコンパイル・リンクに成功した後、Catch2 が exit 42 を返した。
