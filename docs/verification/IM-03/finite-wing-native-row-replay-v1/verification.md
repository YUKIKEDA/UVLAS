# 循環の元係数を一行ずつ再生成する試作

[有限翼の空間細分](../finite-wing-drag-refinement-v1/verification.md) のM2/N4を二形状とも使った。Case・認定済み幾何・コロケーション・後流・流れを同じ試行として渡し、既存の密区間を比較元とした。

原係数を行ごとに再生成し、上下端の符号付き仮数と指数を全64成分で比較した。行を使い回して既存の投影を適用し、同じピボット付き密LUで再求解した。解の保持語8成分、元作用で再評価した残差の中心の保持語・半径・指数、後流求積フラグまで一致することを検査した。

Case側の入力と照合は借用の有効期間内で行った。幾何、右辺、保持の世代、または尺度が一致しない場合は、確保前に拒否する。区間係数は実内容も比較する。容量0の拒否とRHS世代だけを変えた拒否では、計画済み確保が0のまま、基準解を後続の荷重・元残差で読めることを確認した。

| 環境 | 保持区間全体 | 行再生成の区間 scratch | 再生成試行の累積payload |
| --- | ---: | ---: | ---: |
| MSVC 14.51 Release | 18,432 B | 2,304 B | 9,057,200 B |
| GCC 14.2.0 Release | 20,480 B | 2,560 B | 9,147,184 B |

表の値は両形状で共通だった。GCCの区間型では、正式格子24,576成分の一行は7.5 MiBに当たる。区間だけを数えると8行から1行になった。累積payloadは射影先の密行列、基準密LU、作用の再準備も含む試作の計画値である。比較に使った基準経路も同じ試験プロセスに残るので、表から実行プロセスのピーク削減や正式格子の実行時間は推定できない。

既存の通常入口は引き続き密区間を保持する。実利用へ移すには、元のCase・照会・法線・後流係数を世代と実内容で束縛し、元の借用が消えた後にも同じ行を再生する所有形を決める。接線では元行を昇順に加算する。転置では元の行を昇順に走査し、各列への加算順を保てる。接線・転置の再生、元残差、既存の保持語一致、同時生存と累積の資源、正式格子の24 GiBと1200秒は次に確認する。

## 実行結果

MSVC 14.51 ReleaseとGCC 14.2.0 Releaseで各2件が通過し、形状ごとに573検査を行った。MSVCは水平13.80秒、上反角5度17.76秒、GCCは9.05秒と10.89秒だった。時間は基準経路と再生の両方を通す試験全体を計った。製品・試験の2翻訳単位でclang-tidyが通過した。

GCCの隔離複製では、同じ世代のまま第1照会の幅方向接線を変更した。元区間の実内容比較が不一致を検出し、StaleGenerationを返した。元の試験は同じseed 23で通過した。
