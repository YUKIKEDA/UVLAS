# 正式格子の係数組立ての費用

[M128/N192 の検証](finite-wing-interval-rounding.md)では、水平翼と斜翼の中央照会の組立てに36.624秒と44.553秒を要した。採用上限1,200秒を全24,576行に割ると48.8 ms/行となる。求解、原残差と抗力にも時間が必要である。

## 中央照会の CPU 内訳

`cbb4da2e` の空力コードを使った斜翼の隔離ドライバーを、Intel Core i5-13400Fの論理CPU 4に固定した。GCC 14.2 Releaseで、正式格子の中央照会を組み立てる区間にLinux perfを99 Hzで付けた。サンプル欠落は0。44.711秒で同じ149,368アサーションが通り、仕事量235,912,674 stepと累積確保462,487,352 Bを再現した。

自身の命令で観測したCPUサンプルの22.43%は `LocalBounds::root`、10.52%はP1区間丸め `p1::rounded` にあった。この照会では遠方積分を使わなかった。

## 束縛輪郭と後流を分けた予約

局所核の予約は、束縛輪郭と後流の各演算列から求める。束縛輪郭では入力、3辺の式、πの用意、出力認定を含める。49,536三角形のうち49,152が束縛輪郭である。束縛輪郭の最大は12,205 step、後流の最大は従来どおり616,685 step。

GCC Releaseの正式格子両翼では、先頭・中央・末尾の各照会の総予約が30,715,327,505から1,003,926,545 stepに縮んだ。メタデータの推定4,784,432 Bと初回の累積確保予約462,487,352 Bは一致した。予約の変更に伴う実行時間の利得は計上していない。

束縛輪郭だけの2枚の例は、局所核と共有作用の両方を予約値ちょうどで準備でき、局所枠を1 step減らすと予報で拒否した。循環の誘導速度と強度の転置は独立な輪郭積分と照合した。対象のP1、共有作用、Case一様流と水平翼M2/N4はGCCとMSVCで通った。GCCでは正式格子2件を加えた7件、MSVCでは5件を実行した。

## 平方根の試行に使う整数幅

商と剰余の計算は32,768 bitのまま保持する。正規化した商と257回の試行平方はどちらも $2^{514}$ 未満なので、試行には1,024 bitの検査付き符号なし整数を使う。1,073件の比較で、出力の上位語・下位語・半径・指数、失敗の区分と仕事量が変更前と一致した。

GCC 14.2 Releaseで、斜翼M128/N192の中央照会を同じ論理CPU 4に固定して交互に3回ずつ計測した。組立て時間は変更前が45.011、46.471、45.153秒、変更後が35.325、35.354、34.983秒。最短値は22.3%短縮した。各回で149,370アサーションが通り、235,912,674 step、累積確保462,487,352 B、49,536三角形と遠方0件が一致した。非零の強度と物理点・照会点・核半径・強度の変動を与えた誘導速度とJVPも、全成分の包絡がビット単位で一致した。

局所パケット、P1、共有作用、Case一様流、水平翼M2/N4の7件は、GCC ReleaseとMSVC Releaseでそれぞれ通った。中央の1行の実測であり、正式格子全体の求解・原残差・荷重の実行時間は未計測である。

## 組立て時の係数包絡から原残差を検査する試作

`assemble_influence` が返す元の係数区間を $A_{ij}$、求解用に投影した値を $\widehat A_{ij}$ とする。投影時に各行の $E_i=\sum_j\max|A_{ij}-\widehat A_{ij}|$ を上向きに足す。求解後、保持した循環 $\Gamma$ の上位語と下位語を読み、投影前の右辺 $b_i$ から $\sum_j\widehat A_{ij}\Gamma_j-b_i$ を区間で求める。その区間を各側に $E_i\max_j|\Gamma_j|$ 広げると、同じ離散作用素の原残差を含む。$A_{ij}$ には、後縁の循環転写の列と向きも組み込まれている。

GCC 14.2 Releaseの隔離ビルドで、水平翼・斜翼のM4/N8、迎角−1°と+1°の4求解を実行した。現行の再計算も実行して照合し、128行すべてで係数から得た区間が再計算区間を含んだ。4求解とも既存の無限大ノルムの原残差判定を通り、各翼1,647アサーションが合格した。正式格子の幅とL2判定は未検証。製品コードは現行の再計算を使う。試作の区間を返す場合は、直接再生と返却包絡をビット比較する検証について、独立照合と同じ版での再現性を保てることを別途示す必要がある。

## 正式格子の左右反射

Caseから製品経路で生成したBinary64座標を、反対側の対応点と成分ごとに厳密比較した。水平翼では頂点12,480組中5,246組、照会点12,288組中4,762組が一致した。斜翼ではそれぞれ4,847組、4,201組だった。四辺形の外周の対応12,384組と、接線の外積で得た未正規化法線12,288組は、両翼ともすべて反射に一致した。後流四辺形の左右2辺について、保存した座標から有理数で流れ方向の長さを求めると、1面内で等しい長さを持つ面は両翼とも192面中0面だった。隔離ビルドで従来の参照幾何と仕事量予報の試験も両翼で通った。

この丸め済み幾何から厳密対称な作用素を仮定して、片側の係数をもう片側へ複製することはできない。対称化を使う場合は、幾何と後流内の補間の差を評価し、元の離散系の原残差予算で認定する必要がある。

## 積と商の端点選択

積の両因子がそれぞれ非負または非正のとき、相手の符号から最小値・最大値を与える端点を選べる。商は分母が零をまたがない場合に、分母の符号で分子の端点を選び、その分子の符号で分母の端点を選ぶ。選んだ端点を同じ固定256ビット区間演算で囲う。すべての端点演算が作業整数と指数の範囲に入る条件でこの選択を使う。積の因子が厳密に零でも、従来の指数範囲と作業量を検査する。商では分子が厳密に零でも分母の零を拒否する。

非負、非正、厳密な零、零を端点に持つ区間、零をまたぐ区間を組み合わせた36組で、4組の端点を計算した場合と出力の有理端点が一致した。零を含む分母は拒否した。GCC 14.2、MSVC 19.52のReleaseで、このケースの244アサーションと、局所パケット、誘導、共有作用、Case一様流、水平翼M2/N4の対象CTest各7件が通った。Windowsは未変更のJSONパーサーに既存のMSVC 19.51オブジェクトを使った。

GCC 14.2の隔離試験では、4,096組の区間に同じ積と商を100回ずつ適用した。論理CPU 11で前後を交互に3回ずつ実行し、作業数819,200と端点の集約値は各回で一致した。従来は0.409、0.426、0.440秒、変更後は0.210、0.203、0.189秒だった。これは端点演算に限った計測である。

GCC 14.2 Releaseで、水平翼と斜翼のM128/N192の先頭・中央・末尾の各行を実際の共有誘導から組み立てた。更新後の147,456係数すべてが、独立式で照合済みの外向きBinary64包絡に含まれた。各行から抜き出した製品係数の表示端点は変更前の記録と一致した。

## 循環行列の値専用評価

循環行列と既知後流の右辺は誘導値と強度の転置を使う。近接の束縛輪郭とP1後流では、同じ式と256ビット区間演算で値を評価する。座標微分を使う呼び出しはこの準備結果を拒否する。遠方の固定求積の差は従来どおり値と全微分を評価する。循環を解いた後の元の非貫通残差では全微分を含む準備を行う。幾何、接触、精度、資源の事前検査は共通で、同じ共有領域を次の照会にも使う。

近接と遠方の混合幾何で、値専用と全微分の誘導速度の全包絡がビット一致した。実強度の転置は全9係数の有理端点が一致した。値専用の結果への座標JVPと座標転置の呼び出しは拒否し、同じ共有領域を全微分へ戻すとJVPが成立した。GCC 14.2とMSVC 19.52のReleaseでこのケースの314アサーションと対象CTest各7件が通った。Windowsは未変更のJSONパーサーに既存のMSVC 19.51オブジェクトを使った。

GCC 14.2 ReleaseのM128/N192の各3照会では、値専用で求めた合計147,456係数の包絡を、全微分経路と同じ独立参照で照合した。照合件数と抽出した係数の表示端点は全微分経路と一致した。各照会の準備を1回ずつ測ると、水平翼は10.44〜11.39秒、斜翼は13.74〜13.93秒だった。この実装で正式格子を全行組み立てる時間には引き続き対策が必要である。

値専用経路を含む `d6d322d7` の斜翼M8/N24は、同じ独立参照と許容差で8,775アサーションが通った。ログ作成から最終出力まで約651秒。近傍抗力と包絡半径、Trefftz面抗力、累積確保41,478,288 Bは先の斜翼M8/N24と一致した。

同じ空力コードの斜翼M128/N192で先頭・中央・末尾の照会を別に計時した。GCC 14.2 Release、論理CPU 6の1回の計時では、1行当たりの局所パケット準備が9.03〜9.26秒、値の核評価が5.94〜6.04秒、共有作用の初期化と辺の整理の合計が0.04秒前後だった。全73,728係数が独立に照合した外向き包絡に含まれた。

## 正式格子の行列係数の射影

小格子試験の行列射影誤差枠は係数あたり $10^{-13}\,\mathrm{m}^{-1}$。正式格子で、外向きBinary64区間を中央に射影した誤差の上界がこの枠を超えた係数は、水平翼182,866個、斜翼195,212個（各603,979,776個中）だった。両翼の全24,576行に少なくとも1個あり、行全体を多倍長演算へ戻す方式では高速な組立てが残らない。最大上界は両翼とも添字162の対角で $3.849\times10^{-9}\,\mathrm{m}^{-1}$ 未満。速度20 m/sを用いた試作の右辺側はすべて誤差枠内だった。

さらに同じ製品幾何の行・列番号33と162の対角を、有理数の外積、整数平方根による外向き囲い、Machin式の交代級数で独立に囲った。添字は0始まり。真値に最も近いBinary64値でも、水平翼ではそれぞれ約 $1.2851\times10^{-13}$、$2.5006\times10^{-13}\,\mathrm{m}^{-1}$、斜翼では約 $1.6972\times10^{-13}$、$1.9910\times10^{-13}\,\mathrm{m}^{-1}$ の射影誤差が残る。演算途中の精度を上げても、この枠を指定したままでは4係数ともBinary64へ射影できない。正式格子の受入では、射影の誤差と元の離散作用素での残差をそれぞれ検査する。小格子の試験入力と正式格子の抗力・原残差の判定値は変更していない。

[独立計算](finite-wing-drag-refinement-v1/projection_rounding_probe.py)は4係数分の製品入力を16進浮動小数点で保持する。`python -I -B docs/verification/IM-03/finite-wing-drag-refinement-v1/projection_rounding_probe.py` で再実行できる。SHA-256は `52cde8e1492e7352a0d638892072462355a5d54492ee4f201dfecf54d2fe1d74`。Pythonの通常実行と `-O` で4件とも同じ結果を得た。

両翼で許容されない接触は0件だった。水平翼の第1照会を翼の頂点へ移した負対照は2件を検出した。木の構築は各約0.03秒、循環照会の確認は各約0.8秒、辺中点の確認は2.1秒と4.1秒だった。法線や最近実体、遠近分類を含む局所パケットはこの試作では作らない。製品でこの判定を再利用するには、既存の現在配置の木と同じ幾何所有元へ結び付け、正規支持の別名と取消・資源枠を保ち、判定結果を使う輪郭経路の適用条件を確定する必要がある。

製品の `ContourContactIndex` は認定済みの現在配置を保持し、既存の参照木から現在の厳密な箱を作る。水平・斜翼の製品試験で、24,576コロケーションと49,280辺中点を各翼で全件検査した。厳密判定の候補数は両翼とも238,380と663,240で試作と一致した。別の試験で、参照から移動した面、箱の境界から最小正Binary64値だけ離れた二語照会、束縛面と後流面の接触の区別、辺IDの偽装、資源境界、取消を確認した。

定常閉後流は `SteadyWakeClosure` を使い、流下端を後縁と同じ符号付き循環列へ接続して既存のP1循環入口で解ける。正向きと逆向きの後縁を持つ小例では、求解で得た循環の二語を保持し、流下端に符号付きの強度を独立な固定履歴として与えて残差を再評価した。通常の元残差と再評価値はともに $10^{-13}$ m/s以内。GCC 14.2とMSVC 19.52のReleaseで、接触・資源・循環を含むCTest各3件が通った。正式格子の高速な輪郭演算を循環・荷重へ接続する工程が残る。

## 一定後流の解析輪郭と製品求解

一定後流の二三角形は、面内項が零になることを使って束縛輪郭と同じ解析核で評価する。近接と遠方の照会で、速度・座標接線・強度の転置を独立な線分積分と照合した。近接では既存のP1経路にも同じ強度を両端へ独立に渡し、速度の包絡が重なることを確認した。

水平翼と斜翼のM2/N4は、迎角−1°と+1°で、後流末端を循環と同時に求め、元残差、近傍抗力、Trefftz面抗力を凍結参照と比較した。元のP1経路による全行再評価と、保持した循環行の再生も通った。GCC 14.2とMSVC 19.52のReleaseで、両翼、共有誘導、Case一様流のCTest各4件が通った。GCCの近傍／Trefftz面の二次係数は、水平翼1286.339516932118／1366.531336941846 N/rad²、斜翼1280.213043612045／1359.494331374637 N/rad²だった。

正式M128/N192の先頭、中央、末尾の3行ずつを一定後流つきの製品共有作用で組み立てた。計147,456係数の製品包絡が、独立参照と照合済みの外向きBinary64区間に含まれた。GCC 14.2 Releaseで1行の値専用準備は、水平翼9.30〜11.31秒、斜翼11.06〜11.37秒だった。判定には1,200秒枠内の正式格子全行の求解・元残差・荷重が必要であり、正式格子では局所パケットを経由しない輪郭評価の接続が残る。

斜翼M8/N24も凍結参照を使い、`3761b327` の循環・荷重入口で後流末端まで求めた。GCC 14.2 Release、論理CPU 4で迎角−1°と+1°を実行し、元残差の再評価を含む8,751アサーションが通った。ログ作成から最終出力まで約318秒。近傍抗力は1537.77371501613 N/rad²（包絡半径 $3.240692188094053\times10^{-28}$）、Trefftz面抗力は1496.159174932179 N/rad²、累積確保は41,416,848 Bだった。

## 準備済みの閉輪郭による係数行と速度

`ClosedContour` は、正規辺と強度列の対応、辺ベクトルと二乗長さ、接触認定の木を準備時に保持する。同じ配置の各照会では、頂点から照会点までの相対位置とコア込みの距離だけを更新し、共有辺は一度ずつ評価する。

水平翼と斜翼のM2/N4で、係数行の全列と自己辺を除外した中点速度の3成分について、外向きBinary64包絡が高精度P1の包絡を含むことを確認した。どの包絡も幅は $10^{-10}$ 未満。準備のバイト上限を1 B下げると確保前に拒否し、照会上限を1 step下げると `ResourceExceeded` を返した。GCC 14.2とMSVC 19.52のReleaseで両翼各664アサーションが通った。隔離複製で輪郭の符号を反転させると包絡照合が失敗した。

正式格子M128/N192では、各翼の先頭・中央・末尾の3行で、全147,456係数の高精度P1包絡を含んだ。GCC 14.2 Releaseの論理CPU 6で、接触の確認を含む1行の評価は水平翼6.81〜7.89 ms、斜翼11.18〜12.87 msだった。辺と接触木の一回限りの準備は計時から外した。ここで計測したのは係数行であり、正式格子の循環求解と荷重の所要時間は引き続き確認する。

保存済みの正式格子循環を、接触認定つきの `ClosedContour::apply` で全24,576行について再評価した。GCC 14.2 Releaseの4ワーカーで、相対L2残差の上限は水平翼 $5.5310\times10^{-12}$、斜翼 $5.5418\times10^{-12}$、所要時間はそれぞれ53.47秒と70.18秒だった。計時は照会準備後の誘導評価から残差集計まで。

## 循環・荷重の入口への接続

M2/N4の両翼で、迎角−1°に接触認定つきの閉輪郭を選び、通常の `solve_discrete_circulation_loads` で係数行の射影、保持循環の原残差、自己辺を除外した荷重を検証した。迎角+1°には従来のP1評価を使い、両迎角から得た近傍抗力とTrefftz面抗力を同じ凍結参照と比較した。係数の射影上限は既存と同じ $10^{-13}\,\mathrm{m}^{-1}$。これを零にすると `PrecisionUnresolved` を返し、入力流れの所有権を消費しなかった。閉輪郭を選んだ再生では保持循環と元残差の語が一致した。GCC 14.2とMSVC 19.52のReleaseで両翼各677アサーションとCase一様流を含む対象CTest各3件が通った。

両翼の迎角−1°を4作業域でも解き、1作業域と照合した。保持循環の全語、元残差の中心語と半径、全辺・全節点の力、合力とモーメント、消費した演算数が同一だった。GCC 14.2とMSVC 19.52のReleaseで、両翼各1,328アサーションを含む対象CTest各3件が通った。
