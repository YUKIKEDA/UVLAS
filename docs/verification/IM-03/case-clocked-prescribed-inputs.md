# 同じ時計で指定運動と既知流れを評価する

型付き過渡ケースの区間と節点から、厳密な SI 時刻と片側を一度だけ決める。同じ節点を、指定運動、照会位置での既知流れ、指定後流速度に渡す。自由後流のケースでは指定速度を要求せず、運動と既知流れを同じ時計で評価する。準備時と評価時の区間、刻み、入力世代、運動と各流れの実内容を照合する。

## 一つの時刻から二つの片側を評価する

区間は $[0,1]$ s と $[1,2]$ s、刻みはともに $1/2$ s。並進の節点を $(0,1,2)$ s、回転の節点を $(0,2)$ s とした。並進の値は $(0,1,3)$ m。独立に求めた Hermite 勾配は $(1/2,4/3,5/2)$ m/s。1秒の到着と出発で、並進速度はともに $4/3$ m/s、加速度は左 $1/3$、右 $5/3$ m/s² になった。回転成分の速度は両側とも $1/2$ rad/s、加速度は厳密零だった。

既知流れの一成分は $1+3t$ m/s、指定後流では $4+2t$ m/s とした。1秒でそれぞれ4と6を返し、時刻と片側が運動と一致した。区間の中央節点は厳密な $1/2$ s を返した。終端の右側、別の入力世代、同じ形で刻みや運動を変えた入力、自由と指定を交換した入力は拒否した。

## 周期の継ぎ目で区間を分ける

元節点 $t_i$ と周期 $P$ を持つ列について、区間開始 $a$ より後の最初の出現は $t_i+P(1+\lfloor(a-t_i)/P\rfloor)$。この時刻が区間終端より厳密に小さければ、区間内にイベントがある。周期の最終節点は先頭節点と同じ列に属する。この方法は周期を展開した配列を作らず、元節点と解析区間の組ごとに有理演算と仕事の上限を求める。非周期の節点も厳密に比較する。

周期3秒の並進で、元イベントには $0,1,2,3$ s を指定した。継ぎ目 $-3$ s が内部に入る $[-3.5,-2.5]$ s の区間は拒否した。その時刻で区間を分けると受理し、二階微分は左 $4$、右 $-4$ m/s² を返した。共通のイベント検査枠を絞ると資源不足を返した。

Windows MSVC 19.51 と Linux GCC 14.2 の Release で、対象 CTest は各8件が通過した。追加した共通時計の試験は79項目。Linuxで周期計算の床関数を省くと、継ぎ目をまたぐ区間を誤って受理する負対照が失敗した。元のソースへ戻して79項目が通過し、変更した2翻訳単位は clang-tidy を通過した。

## 適用範囲

この入口は選択された一つの運動と、その試行で読む流れを対象とする。取付面の登録、全ての運動・荷重を含む試行、J1の確定履歴と再開は、後続の実行入口で照合する。
