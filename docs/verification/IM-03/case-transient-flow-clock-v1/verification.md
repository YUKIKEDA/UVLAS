# IM-03 過渡ケースの厳密時刻で二つの流れを評価する

対象ソースは `8a69b27e1d19cab79279d346fae1a699545f5f3d`。

型付きSIケースから固定刻みの全区間と、突風なしの既知流れ・指定後流移流速度を一括で準備する。時計は $t=t_a+k h$ を厳密有理数で計算する。区間の始端・終端は検査済みの時刻をそのまま用いる。区間の始端は右側、終端は左側を明示して照会する。区間内部は明示した側か自動選択を使う。結果が保持する出典は元ケース、入力版、区間と節点の番号、再始動の宣言、実際の刻み $h$。 [FD-07の時刻区間](../../../specs/foundation/case-schema-fields.md) [AE-07の入力契約](../../../specs/aero/uvlm-integrated-specification.md)

独立に準備した現行入力と、入力の発行元・版、スキーマの契約版・表現版、全区間の厳密時刻・刻み・再始動、両方の速度曲線の厳密入力を照合する。結果に保持する `SchemaIdentity` は評価対象を準備した側のもの。一つの厳密な時刻と左右の指定で両方の速度・微分を評価し、それぞれに明示した許容誤差で投影する。事前見積もりと本評価の作業枠を役割ごとに保守的に確保し、両方の所有ペイロードが共有資源計画に入ることを確かめてから評価する。投影が片方でも未達なら結果は公開せず、準備済みの時刻表と曲線を保つ。

## 独立照合

ケースは ft・min を使う。二つの区間の境界 $0.002$ min は厳密に $0.12$ s。左の終点の刻みは $0.03$ s、右の始点では $0.015$ s。両側で二つの速度の時刻が同じで、各側の宣言と刻みを保持した。旧区間の中点 $0.09$ s の速度・時間微分は、一次多項式と、等傾斜のPCHIPが再現する直線から有理数で算出した。返却した高低語と半径を有理数に戻し、各参照値を含むことを確認した。

同じbinary64へ丸まる別の開始時刻、同じ入力版で別の区間の刻みや指定速度標本が変わった場合、範囲外の節点や端点の反対側、明示上限と投影の未達を拒否した。J1時間前進・放出と移流による物質点の更新・履歴やチェックポイントは後続工程の対象。


## 実行結果

MSVC 19.51 Debug・ReleaseとGCC 14.2 Releaseで、`coupling.case_uniform_flow`、`aero.uniform_flow`、`aero.pchip_curve`、`io.si_case` が各4件合格した。Releaseの時計ケースは両OSで173アサーション合格、乱数種23。変更した製品・試験コードにclang-format 21.1.2と両OSのclang-tidy 21.1.1を適用した。

タイムアウト調整前に従来回帰を含むMSVC Debugのcoupling全体を2回計測し、54.44秒と42.03秒だった。長い回の60秒枠の余裕は5.56秒で、観測した実行時間差12.41秒より小さい。試験登録 `5677b1cb93ac8d2a943d4447b86ff108c811e287` でMSVC Debugの同テストだけを90秒にし、生成されたMSVC Releaseの60秒も照合した。90秒枠での再実行は 51.16 秒で成功した。

GCC 14.2 Releaseの分離コピーで、製品・試験ファイルの生バイトを固定ソースに照合した。元の対照は173アサーション合格。時刻表の始端と終端の厳密比較を除くと、同じbinary64へ丸まる別時刻を誤って受理し、負対照が1件失敗した。Catch2の終了値は42。
