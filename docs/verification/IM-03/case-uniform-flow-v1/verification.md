# 型付きケースから一様流を準備・評価・復元する

実際の入力文書を型付きケースとして検査し、SI 変換で保持した厳密な数値と単位を一様流へ渡した。定数・多項式・PCHIP は同じ入口で準備できる。再開時は独立に準備した現在のケースと照合する。解析の開始時刻、宣言イベント、速度、時間偏微分、空間ヤコビアンを試験で確認した。

## 分とフィートで指定した値を厳密な SI 値で返した

速度の換算係数は 127/25000 m/s per ft/min。定数では 2 の 64 乗に 1 を加えた入力から、71 ビットの分子を欠落なく得た。多項式では原点 1 分、尺度 2 分を秒へ換算し、係数を独立に展開して求めた速度と時間偏微分に一致した。比較には正規形の分子と分母を使い、全 9 成分の空間微分が厳密にゼロであることも確認した。

過渡 PCHIP は、型付き解析区間の初めと終わりをそのまま連続性の要求区間に使った。開始 1 分、終了 3 分、イベント 2 分の入力で、節点の左右と範囲を確認した。端値保持、負時刻の周期正規化、定常ケースで明示する要求区間も実際の入力文書から試した。入力世代が同じでも標本やイベントを変えると、見積もり・評価・復元はいずれも拒否した。 [ネイティブ試験](../../../../tests/coupling/case_uniform_flow_test.cpp)

## Windows の両構成で関連試験が通過した

MSVC 19.51.36260.0 の Debug と Release で CTest が各 3 件通過した。新規の接続試験は各 5 ケース、438 アサーション。評価の上限を見積もりと同じにすると受理し、1 ステップ減らすと確保前に拒否した。単位の分を秒に置き換えた隔離変異では、定数の分子・分母の 4 アサーションが失敗し、Catch2 は終了コード 42 を返した。 [ソース版と検証結果](../im03-case-uniform-flow.json)

次に、空間に依存する突風、指定支持運動と、循環計算が用いる精度への明示投影を既存の工程で接続する。 [IM-03](https://github.com/YUKIKEDA/UVLAS/issues/19)・[IM-06](https://github.com/YUKIKEDA/UVLAS/issues/22)
