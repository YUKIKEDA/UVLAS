# 有限翼の幅方向細分と局所核の仕事量

凍結水平翼 FW-V01 と斜翼 FW-V02 に対し、既存の [独立参照](finite-wing-drag-refinement-v1/reference.py) から M4/N12・M8/N24 の節点、照会点、全循環成分を別ディレクトリで生成した。再生成した参照の SHA-256 は `c6c7250deaccb940d628d8551d2244db89095c598ba0a12379d71629d524ecab`。節点・照会点・分割点・全循環を除く観測は、保存済みの [凍結観測](finite-wing-drag-refinement-v1/independent-larger.json) と JSON 値が一致した。

GCC 14.2.0 Release で `8184953b` の製品ライブラリを使い、既存の有限翼試験に幅を増やした独立参照を渡した。両翼とも、全48循環成分、解いた系と末端強度を置き換えた系の元残差、自己辺の除外、近傍抗力と Trefftz 抗力を照合し、2,511アサーションが通った。許容差は既存の [有限翼格子系列](finite-wing-drag-refinement-v1/verification.md) と同じ。

## M8/N24 の事前見積もり

同じ試験の M8/N24 では、両翼とも循環の求解を始める前に `ResourceExceeded` を返した。432三角形の作用を準備するためのメタデータ推定は、整数述語の28,672 Bと $32(9+3\cdot432)$ Bだけで70,432 Bとなる。M4/N12 と同じ64 KiBの枠では不足する。

仕事量にも別の超過があった。旧見積もりは局所核の実行量と無関係に、呼出し側が許した10億ステップを各三角形の評価へ積んだ。幾何の許容量を加えた項だけで440,640,000,000となり、1照会の上限150,000,000,000を超える。

`96e6d186` では、局所核が演算列から導く898,659を実行時の上限とし、組立ての見積もりにも使う。先の三角形分の項は9,028,220,688になる。幾何と照会の他の仕事はそれぞれ計上する。回帰試験では、局所の許容量を898,659から10億へ増やしても、同じ照会の予約が2,726,319で一致した。898,658では拒否した。隔離ビルドで旧見積もりに戻すと予約が3,000,030,342になり、一致の試験に失敗した。

同じ修正版で試験用のメタデータ枠を128 KiBにして再実行し、両翼が循環と荷重の計算に進むことを確認した。計算の打ち切りは1ケース1,200秒、累積確保の制限は24 GiBのまま維持した。M8/N24 の全観測と正式格子 M128/N192 の受入は、この記録の検証範囲に含めていない。

## 元残差と自由後流の作業領域

非貫通の元残差と自由後流の粒子速度でも、照会を順に処理する間に作用の作業領域を再利用する。元残差の結果は、入力の照合済み幾何を保持する。速度の値・方向微分・転置を同じ点、同じ順序で計算する。

GCC 14.2.0 Release で [自由後流の費用観測](free-wake-cost-v1/verification.md) の 2・4・8 行を再実行した。両版の局所核は同じで、`96e6d186` から `44adb081` への変更を比較した。各規模で Binary64 と TwoWord の5経路を3回ずつ比較し、計90件の結果指紋と三角形照会数、遠方評価数、相殺対数が一致した。表は TwoWord の各経路の初回に `ResourcePlan` が課金した累積バイト数である。
