# IM-03 型付きケースから指定移流速度を評価する

対象ソースは `2e871c16b4845d5d73dc100ee877636a0c4886d5`。

## 範囲

`Case.analysis.wake.convection` が `prescribed` のとき、型付きSIケースから、指定速度の定数・多項式・PCHIPの係数を厳密有理数として読み取り、所有する。時刻と左右指定で速度・時間偏微分を評価する。指定速度は空間上一様なので、空間微分はゼロ。自由移流と後流なしは入口で拒否する。

指定移流の準備済み入力と評価結果は、既知流れと別の型で保持する。既知流れの速度とイベントは既知流れの入力だけに属する。指定移流を評価するときは、別途準備した現行の指定曲線と、入力の発行元・版・内容を照合する。Binary64・TwoWordの投影は速度と時間偏微分それぞれの成分別許容誤差で判定し、失敗時は厳密結果を保持する。 [ケースの空力フィールド](../../../specs/foundation/case-schema-fields.md) [後流の採用仕様](../../../specs/aero/uvlm-wake-adopted-specification.md)

保存・復元の検証は、同じプロセス内の所有スナップショットと独立した現行入力の照合を対象とする。J1の時間前進・物質点輸送、全後流履歴とチェックポイントの永続化は後続工程で扱う。

## 独立参照と拒否試験

入力単位の ft/min を有理数 $127/25000$ m/s として計算し、時間微分にはさらに $1/60$ を掛けた。多項式は90秒で正規化時刻 $1/4$ を代入した。PCHIP の区間 $[0,1]$ 分は、独立に計算したHermite式 $x(u)=3u^2/2-u^3/2$ と $1-2x(u)$ を用い、30秒から速度と時間微分を求めた。節点の左右・自動、端値保持と負時刻の周期化を照合した。投影は丸め語と半径を有理数に戻し、参照値を含むことと指定幅に収まることを確認した。

別の既知流れを持つケースで指定速度が一致すること、同じ入力版で指定速度の標本が変われば評価・復元がいずれも拒否されることを確かめた。不足する解析区間、資源、取消と精度未達も試験した。評価は見積もりどおりの容量で成功し、作業上限の1不足では配列を確保せず失敗した。


## 実行結果

MSVC 19.51 Debug・ReleaseとGCC 14.2 Releaseで `coupling.case_uniform_flow`、`aero.uniform_flow`、`aero.pchip_curve`、`io.si_case` を確認した。MSVC Debugでは既存の3系列を製品コミットで実行し、試験整理の後に変更対象を既定60秒枠で再実行した。Releaseの指定移流ケースは両OSで680アサーション、乱数種23。clang-format 21.1.2と両OSのclang-tidy 21.1.1を変更した翻訳単位に適用した。

GCC 14.2 Releaseの分離コピー（`2e871c16b4845d5d73dc100ee877636a0c4886d5`）で、製品・試験の生バイトを固定コミットに照合した。対照は707アサーション合格。指定速度を誤って既知流れから読む変異では、入力の同一性と独立数値参照の82アサーションが失敗し、Catch2は42を返した。
