# 循環求解と線形化の元係数を行ごとに再生

[接触と照会の所有試作](../finite-wing-native-row-replay-owned-v1/verification.md) を接線・転置に広げ、凍結有限翼M2/N4の水平翼と上反角5度の両方で従来の密区間を基準にした。固定コミット 5de3e4ac で、同じ係数と非零の右辺を両経路へ入力した。接線・転置とも、保持語と元残差包絡の中心語・半径・指数、行の物理FaceIdが完全に一致した。MSVC・GCC 14のReleaseで両形状の比較を通過した。

接線の元残差は各行で $-b_i$ に $A_{ij}x_j$ を列番号の昇順で加える。転置は元行を昇順に走査して、各出力列の $-c_i$ に $A_{ji}\lambda_j$ を加える。各出力の積和順は従来と同じである。二進64への射影とピボット付き密LUを使い、保持解で元係数を再評価する。

## 通常の製品入口

循環結果に認定済み接触、再解決した各照会、法線、強度の散布と作業の制限を保持する。元区間の作業領域は一行で、保持データは照会行と強度散布の件数に比例する。通常入口から二次元の元区間配列を外した。密区間との比較は試験で呼ぶ検証入口に限り、その場で確保して破棄する。射影した密行列も基準密LUによる求解終了時に解放し、次の線形化と重ねて保持しない。

独立線形化、同一試行の接線・転置、荷重の陰的循環への転置は同じ所有行を読む。呼出元の接触・照会と行の借用を破棄した後で、保存循環の接線と転置を求解した。独立の循環参照、元残差、低位語、異なる世代・単位、容量0、取消を従来の試験で照合した。独立線形化のmax_stepsには、二回の元行再生を含む。旧代数処理用の100,000 stepでは不足するため、同じケースで予算不足を明示して検査した。

## 正式格子の残る資源条件

M128/N192の旧元区間配列の180 GiBは通常の保持から外れた。現行の行作用には独立の累積確保制約が残る。予測は各照会について全facet分の配列を課金する。64-bit ABIでは、facetの点と強度の二つのordinal配列だけで48 Bを要する。M128/N192の束縛未知数は24,576で、束縛面だけでも49,152 facetを持つ。通常の値求解で元行ごとに二回準備するため、この項だけで累積予約は少なくとも115,964,116,992 B（108 GiB）になる。採用上限24 GiBではこの計画を受け入れられない。

累積予約と同時生存メモリは別の量である。正式格子の判断には、行作用の準備領域を再利用する容量計画、密LUの外部領域を含むピーク、元の1200秒枠の実測が必要である。

## 実行結果

旧密区間との直接比較はMSVC Releaseで21.47秒と26.85秒、GCC 14 Releaseで11.90秒と14.17秒。両環境で各形状573検査を通過した。通常入口へ切り替えた61c3035fでは、MSVCとGCC 14のReleaseで各7件が通過した。内訳は通常の一様流・連成試験1件、大域幾何と資源2件、有限翼の2形状×2格子で4件。MSVC Debugでは通常の求解と線形化の2ケース、956検査が通過した。

M2/N4の元区間一行はMSVCで2,304 B、GCCで2,560 B。比較専用に復元した従来の全行はそれぞれ18,432 Bと20,480 Bだった。M4/N8の有限翼試験で、物理作用列の累積予約はMSVCで590,686,228 Bと590,765,880 B、GCCで594,069,756 Bと594,149,408 B。近傍と遠方の抗力傾きは両形状で従来の値に一致した。

隔離したGCCビルドで転置射影を前進行列に置き換えると、上反角ありのM2/N4試験は345番目の検査で原残差の非収束を検出した。同じseedの元ビルドは573検査を通過した。固定e6fdcca2では試験内のoptional検査だけを整理し、通常の一様流・連成試験は両環境で29ケース13,626検査を通過した。変更した製品と代表有限翼試験のclang-tidyも通過した。
