# 行再生に使う接触資格と照会の所有

[行再生試作](../finite-wing-native-row-replay-v1/verification.md) の固定入力を、認定済み現幾何から再保持した。接触検査のBVHは二度使う。候補を数え、その後で本検査を行う。検査が終われば解放する。接触資格に残るのは既存の現幾何・参照位相の所有者と検査記録である。再保持時は計画済みの1記録だけを確保し、元の共有所有者と検査記録を引き継ぐ。

接触の寿命試験では、元の幾何、位相、接触資格、作業領域、資源計画を先に破棄した。再保持した接触だけで、同じ幾何の識別子と面の役割を読んだ。容量がちょうど一致する計画では成功し、1 byte不足すると確保0で失敗した。

M2/N4の二形状の試作に再保持した接触資格を渡し、元の照会定義から同じ現幾何で照会を解決した。行の法線・相対速度と再解決照会を保持し、元の照会借用を係数の再生成と元作用の二つの処理で参照しない。各照会の実作業を計上した。同じ密LUで持つ基準の元区間、循環の保持語、元残差の包絡との完全一致を確認した。

この結果は一つの試行内で所有して再生する範囲を扱う。通常の循環結果の密区間を置き換えるには、元の借用が終わった後の接線・転置へ同じ照会と係数を渡す所有形を接続し、各行・各列の積和順、全段の資源、正式格子の受入を確認する。

## 実行結果

MSVC 14.51 ReleaseとGCC 14.2.0 Releaseで各4件が通過した。大域接触は4,935検査、資源は126検査、M2/N4の行再生は各形状573検査。行再生を含む試験全体はWindowsで11.30秒と14.03秒、Linuxで8.11秒と9.86秒。対象の製品・試験翻訳単位でclang-tidyが通過した。

両形状で、区間の作業領域はMSVCが2,304 B、GCCが2,560 Bだった。行再生試行の累積payloadはMSVCが9,245,200 B、GCCが9,335,600 B。接触の再保持に先に使った1記録の確保は、この累積再生値の外で計上した。最初の再生試作からの増分は、新しい照会の作業領域と所有照会8件を含む。
