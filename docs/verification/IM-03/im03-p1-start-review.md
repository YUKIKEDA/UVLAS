# P1核の開始審査

Issue #119。起点はmain c93e2731f13f72b833a844b0032a066657dc79ff。新規契約は[演算・全13変数・資源契約](../../specs/aero/p1-induction-kernel-contract.md)。これは設計の審査であり、製品P1核・数値認定・性能・実務受入の成功記録ではない。

## 決めた境界

| 開始条件 | 確認したもの |
|---|---|
| 式・全未知量・単位 | UIの同一RM核、3基底、点3/頂点9/半径1、外側極限、世界基底の値と微分 |
| 型・所有・失敗 | 元packet/query owner、126成分、尺度付き中心/半径、LocalOnly、既存FailureCode、親不変 |
| 数値表現 | 元dyadic差、固定256bit区間、既存整数依存、sqrt257試行、log/atan128項と剰余、最終両語 |
| 資源 | 式DAGの節点/基本opcodeからslot・workを合算し、sizeof/byte/指数をchecked審査。手置き安全定数を撤去 |
| 参照 | 連続面積分/complex-stepと固定Gauss12の独立高精度値を分離。全3基底/13列の固定閾値・負対照 |
| 後続 | 共有16変数/JVP/VJP、大域幾何/TE、循環・荷重・後流は既存IM03-0の次段 |

初稿レビューでは、根拠のないslot/work定数、farの丸め包絡と連続面積分誤差の混同、資源失敗名の不一致が指摘された。現在の契約へ訂正した。farの個別列/尺度正規化は、採用protocolの相対/絶対閾値を単位に依存せず適用する保守的具体化である。

## 限定設計証人

[p1-arithmetic-design-witness.py](p1-arithmetic-design-witness.py)をWindows、Python 3.12.8、標準ライブラリだけで実行し、[12例の結果](p1-arithmetic-design-witness.json)を保存した。整数平方根の独立囲い5例、Decimalのlnによる4例、別引数でのatan半角恒等式、Machinとの照合、定義域全体の剰余不等式を含む。半角係数2の欠落が不等式を外す対照も確認した。

最初のln照合は、参照引数をDecimalへ変換する際の誤差を無視し、ln結果の1ulpだけを許容したため失敗した。1に近い引数では引数変換の誤差がln結果のulpより大きい。修正版は元有理引数を外向きに囲い、その両端の正しく丸めたlnをさらに外向きへ広げ、級数区間との重なりを検査する。誤差を製品の許容差へ移していない。

この証人はscalar恒等式と解析剰余の限定確認である。製品区間演算の全丸め、P1値・13列、固定表、全call資源の製品検証を代行しない。文書7節の製品gateは未実施である。

新規契約の日本語quick lintは語彙反復の統計1件。同一の数値概念を同義語へ置き換えないため保持した。rootが式・精度・資源・参照と日本語を独立レビューし、上記の訂正後に設計契約として採用可と判断した。製品演算の包含とadmissionの実照合は未実施で、実装gateに残る。
