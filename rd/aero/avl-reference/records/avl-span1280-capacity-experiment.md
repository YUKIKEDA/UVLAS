# N1280候補の容量・資源・回帰：事前仕様

2026-10-31。[N640結果](avl-symmetry-fine-observation-results.md) の残るモーメント収束を調べるための参照経路を定義する。以下は新容量版のビルド・回帰の前に固定する。製品数値コアの実装や参照全体の受入ではない。

## 1. 選択した経路

同じ対称静的2翼、spacing-pi64・安定化ゼロコア核・同梱倍精度LUを維持し、容量だけを変える。外部BLASへの交換、反復法、速度行列の破棄／再計算は今回の経路に含めない。変更源を容量に限定して、元の解・力・観測を直接回帰できることを優先する。

親は `source-symmetry8000-spacing-pi64`、別コピーは `source-symmetry16000-spacing-pi64`。許可するソース差分はADIMEN.INCのNVMAX=8000→16000とNSMAX=500→1000、avl_heap_inc.f90のNVX=8000→16000のみ。境界条件・分点・基準量・核・I/F・ガード・計測処理を維持する。COMMONとmoduleの寸法が変わるため全オブジェクトを再コンパイルする。明示的DOUBLE PRECISIONのmatrix-lapacksubs.fだけは従来どおりdefault-real-8を付けない。

## 2. メモリ・時間の根拠

avl_heap_initは、実未知数ではなくNVXでAICN(NVX,NVX)、WC_GAM(3,NVX,NVX)、WV_GAM(3,NVX,NVX)を確保する。16000版は合計14,336,000,000 bytes＝13.35144GiBの仮想割当となる。これにCOMMON・作業域・ランタイム・監視等が加わる。前回の15360実未知数による13,212,057,600 bytesは格子規模の算術値であり、この容量版の割当量ではない。

WSLで確認した物理メモリは約23.38GiB、利用可能は約22.5GiBだった。これは測定時点のスナップショットで、実行時の空きを保証しない。システム／同梱toolchainの探索では外部BLAS/LAPACKを検出していない。同梱ソースは逐次LUであり、16論理CPUを時間短縮の根拠にしない。

最細の半翼15360未知数はN640の2倍。前回の約94秒から、全処理を保守的に立方倍率8で見た約752秒を開始時の時間見積もりとする。LUと係数生成の内訳を測った予測ではなく、性能保証でもない。資源測定と見積もりは新しい監査JSONへ保持する。

## 3. ビルド・回帰の実行条件

ビルドは逐次・600秒・4GiB以内。既存ソース／実行体を上書きしない。差分2ファイル・3定数、全ソースハッシュ、ビルドコマンド、コンパイラ、リンク入力を保持する。

回帰は各翼M6N40・M24N160・M24N320・M24N640、計8件の半翼。比較対象は全て同じπ版で保存済みの半翼。実行順は小規模からとし、各300秒・全900秒・プロセス群RSS5GiB・開始前利用可能8GiB・出力256MiB・console各8MiBを上限とする。開始前にLinuxの利用可能量とcgroup制限の残量の小さい方を用いる。cgroup残量を取得できない場合は不明と記録し、有限な制限を未確認のまま大規模実行しない。監視間隔0.2秒で時間・RSS・出力を検査し、超過時はプロセス群を停止する。上限はOSによる厳密な隔離ではなく監視による停止条件であり、瞬間的な超過可能性を明記する。入力・開始空き・peak RSS・minor／major fault・終了コードを保存する。

FT／FS／FE、UHの行・力・帯・meta・ガード試験は、計測前後および親8000版と**バイト一致**を要求する。小系ではUHの元行列binaryも同様に一致させる。相違が出た場合、許容差へ無断で切り替えず、原因を分離した追加仕様を先に定義する。実行終了0、拒否・非有限値・寸法超過がなく、各入力が同じであることも検査する。独立の成果物監査で8件・親実行体／入力／出力・ソース・資源・不変性を照合してから次段階へ進む。

## 4. N1280の開始ゲートと予定ケース

8回帰と既存の対称等価性・保存観測の監査が成立した後だけ、別の細分化ランナーを作り実行する。予定はFW-V01／02のM3／6／12／24・物理N1280、計8件。弦系列をN1280に揃え、端点移送だけに依存しない。正側11断面はN640と同一、各断面間の分割だけ32→64へ変更する。M24は半翼15360未知数・640帯、物理全翼30720パネル。

細分化は逐次・各1200秒・全2400秒・プロセス群RSS16GiB・開始前有効利用可能20GiB・出力512MiB・console各8MiB。監視中の有効利用可能が2GiB未満になっても停止する。Linux MemAvailableとcgroup残量、開始／終了のswap使用、major faultを記録する。swap増加256MiB超過は資源条件未達として停止し、その結果を合格に数えない。開始ゲートが満たせなければ実行せず、入力と理由を保持する。これらは回帰の予算とは別で、今回の容量回帰にN1280実行を混ぜない。

最細解を得ても、N160／320／640／1280の次数・方向・差減少条件は従来どおり。モーメントを未達ならnullのまま保持する。N1280と同じ版・同じ基準点で弦／スパンを評価し、条件付き外挿と保証された誤差を区別する。全域・帯・元点モーメントの保存と残差1e−11も維持する。後処理120秒・1GiB、derived-by-symmetryとnative-halfの別保存は継続する。

## 5. 今回の完了条件

容量ソース監査、資源・演算量見積もり、別版の全再ビルド、既存8ケースのバイト回帰と追跡監査までを今回の作業単位とする。N1280ランナー・実行・精度判定は次の作業単位。回帰成立だけで参照全体の採用・UVLAS比較・J1・本体開始を更新しない。
