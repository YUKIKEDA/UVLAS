# 作業4：数値基盤・型・主要I/Fの採用判断

2026-11-06。Eigen 5.0.1／Spectra 1.2.0／Boost 1.92.0、pybind11 3.1.0／nlohmann-json 3.12.0を使用する基準経路を採用する。**作業4の方式・契約設計を終了し、5の実務ケース・受入計画へ進む。本体実装開始の全体判定は6で行う。**

仕様は [数値基盤N4-01〜10](../../../../docs/specs/foundation/numerical-foundation-adoption-specification.md)、[入出力IO4-01〜07](../../../../docs/specs/foundation/io-execution-adoption-specification.md)。物理採用1〜3・品質目標・実務適用の初回範囲を維持する。

## 根拠と成立範囲

| 試験 | Windows／Linuxで成立した内容 |
|---|---|
| dense_sparse | 実LU＋複素後縁rank更新、100k三重対角疎行列、不定KKT、負剛性を保持した一般化固有値、実／複素非対称Arnoldi |
| precision_hash | FMA two-product、補償相殺、有理数の階数、256bit幅の外向き平方根囲い、SHA256既知解 |
| actual_j1_matrix | 実PG＋全自由後流の24状態行列を同じ原作用素として抽出。Arnoldiと完全固有値の差8e−15以下、元残差3.3e−16以下 |
| solver_contracts | 固定前処理GMRESの原残差7.3e−15以下、非線形陰的チャートの微分、随伴仕事、低位の非線形消費、不適格投影の拒否 |
| ownership_and_json | CPython 3.12.14／NumPy 2.3.5、read-only viewの所有者寿命、空結果、最大uint64 ID文字列、重複・未知キー・非有限・範囲外等9負対照 |

各OSで数値4試験＋binding1試験が通過した。実PGの行列は既存J1の2方向構造部分空間から得たもので、100k構造の全mode品質を証明したものではない。合成行列の固有値は解析構造／完全Eigen解を参照し、Spectraの元残差を別に評価した。固有値の部分抽出が収束しても全不安定機構の被覆とはしない。

初回Linuxビルドでは試験コードの行列型にvector用LinSpacedを呼ぶ不備があった。vector型へ訂正した。初回コンパイルログを保存し、最終ソース・両OSの再ビルド／全試験と対応させた。試験の物理入力・誤差閾値を変更していない。試作の検査条件はコード内に実行前から置いたが、独立した事前仕様書の整備は不十分だったため、今回の記録を事前固定済み実験と表現しない。

## 容量計測

| 合成問題 | Windows | Linux（WSL2） |
|---|---:|---:|
| n=5,000、実密LU分解 | 4.59s | 3.88s |
| 同、8右辺求解 | 0.053s | 0.036s |
| n=100,000、2D半径2疎LU | 6.62s | 5.50s |
| 同、原行列非零数 | 2,480,536 | 2,480,536 |
| 同、L＋U非零数 | 55,956,652 | 55,956,652 |
| 全プロセスpeak | 1,355,833,344 bytes | 1,341,747,200 bytes |

両方とも誤差・原残差2.8e−15以下。Eigen内部single-thread、CPUは同じi5-13400F機。OS比較の厳密な専用機ベンチマークではなく、構築／測定が近接した容量の予備測定である。時間の比を製品速度差の保証にしない。

**この疎graphはPGのgraphではない。全自由後流の評価・固有抽出・checkpointも含まない。** 5000／100kという配列寸法の経路が扱えることを確認しただけで、8〜12時間の性能合格や実PG全系の容量合格にはしない。

## 実装後へ渡す、入力・判定が決まった検証

| 項目 | 実装する内容と停止条件 |
|---|---|
| PGの局所準備・大域拘束 | 有界patch＋疎拘束の認定。実graphでfillと準備時間を計測。global dense nullspaceを作らない。階数／chart不適格を拒否 |
| 強連成のlinear solve | 全JVP＋固定ブロック前処理GMRES。小ケースで明示J／原残差照合。反復上限内で未達なら正常stepを返さない |
| 精度消費経路 | 既存4096格子の投影未達、精密保持、全kernel／荷重／状態／再開を移植。lowを捨てて成功しない。非対応はPrecisionUnsupported |
| 大規模固有抽出 | P／P*の作用と随伴照合、shift／ncv変更、mode被覆と臨界値予算。被覆未認定は未解決 |
| 外部格子変換 | IO4のカード／Gmsh、曲面・triangle活動領域、offset／材料・質量・拘束。物理量・modeの変換誤差を数値予算に含める |
| 保存・配布 | 全J1履歴をtyped chunkへ移植。破損・非互換・中断、CLI／Python一致、新規環境の導入を検証 |
| 製品性能 | 5で代表ケースを固定。実装初期から実graph・後流・作用回数を測る。性能未達を精度・範囲の縮小で解消しない |

未実装項目を今回の合格数へ加えていない。4の終了は、上記の方式・具体表現・責任・失敗規約を実装できる形へ確定した判断であり、製品の検証完了ではない。全製品の数値結果をPythonで先に揃える条件へ戻さない。
