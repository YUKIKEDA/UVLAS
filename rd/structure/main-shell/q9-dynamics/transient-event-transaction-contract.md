# 過渡イベントの境界・確定・再開契約案

版：0.1、2026-10-30。OP-09/12、TM-05、INIT-RELEASEの構造部分。既知時刻の有限力除去を対象とし、衝撃・拘束変更・状態依存根探索・UVLM同時イベントは未定義。

## 1. 時間境界と左右状態

次の既知イベント時刻 $t_e$ が提案ステップ $(t_n,t_n+h)$ 内にあるときは、まず $t_e-t_n$ へ刻みを切る。ステップ内部のステージは変更前の荷重集合で評価し、境界へ到達した確定状態を $z_e^-$ とする。時刻一致を理由にステージや終端を変更後荷重へ混ぜない。

境界状態からイベント写像 $z_e^+=\mathcal E(z_e^-)$ を別の確定操作として適用する。有限力除去では位置・速度は連続で、既に動いている場合にも次が成立する。

$$
q^+=q^-,\quad v^+=v^-,\quad
M_r(a^+-a^-)=-P^Tf_h.
$$

保持平衡から静止のまま解放する場合だけに限定しない。イベント直後の運動方程式は変更後の荷重集合を使用する。

## 2. 状態と確定単位

| 状態・識別 | 意味 |
|---|---|
| 受理ステップ番号 | 正の時間が進んだ受理ステップの数 |
| 確定世代 | 時間ステップ・ゼロ時間イベント確定のたびに一度増加する世代 |
| イベントカーソル | 完了したイベント集合または順序位置。予定イベントID・入力版と照合 |
| イベント左右 | 境界到達済みで未適用の左状態／適用済み右状態を区別 |
| 有効荷重集合 | 状態・カーソルと一致する荷重ID集合 |
| 積分履歴世代 | 方式・係数・イベント再初期化方針と対応する履歴の世代 |
| 出力カーソル | 最後に確定したフレームの連番。時刻だけを出力キーにしない |

試行は親状態の確定世代を持ち、確定時に一致を検査する。未収束試行、イベント準備中の候補、出力前の作業領域を通常のチェックポイントとして保存しない。同じ親から作った候補を二度確定しない。イベント試行を破棄しても、左の確定状態・荷重集合・履歴・出力位置は変化しない。

同時刻に複数イベントがある場合の順序と競合規約は別途決める。本契約の単一イベントを、そのまま任意の同時イベントへ一般化しない。

## 3. 積分履歴のイベント再初期化

比較用一般化α法では、有限力の既知不連続で左区間を終了し、右の物理加速度から算法加速度を再初期化して新しい積分区間を始める。これはイベント境界で明示する方式規約であり、通常の保存・再開で算法加速度を再生成する規約ではない。左右の履歴と再初期化方針を識別し、右の履歴へ左の試行履歴を混入しない。

境界後の刻み変更時は同じ方式で新しい刻みに対応する接線を再構築する。既存LUを有効と仮定しない。イベントでの次数・実務時間窓の誤差は、別の時間精度試験で確認する。

## 4. 保存・読込み・出力

境界直前、境界左、境界右、通常の境界後の全てを有効な保存位置として扱う。左からの再開ではイベントを一度適用し、右からの再開では既に完了したイベントを繰り返さない。イベント未適用のまま右区間へ時間を進める操作は拒否する。

モデル・入力・イベント予定・方式版・荷重集合・時計・カーソル・履歴・出力位置を全検査してから状態を返す。チェックサムを作り直した意味的不整合も拒否する。チェックサムは破損検出であり認証ではない。

同じ時刻の左右フレームを識別し、位置・速度の一致と加速度・荷重・反力の不連続を表現できるようにする。確定世代をフレームキーに使う場合、棄却・再開・再読込みで増やしたり重複出力したりしない。保存・出力の実際の永続化失敗とファイルシステム耐久性は別の障害試験を要する。

## 5. 時刻表現と決定

限定試験は整数tickでイベント境界を正確に表す。これは製品の時刻型を採用したものではない。一般の入力時刻について、浮動小数点比較・時刻整列・最小刻み・既存時刻との重複判定は別途設計する。

- EVENT-D01：既知イベントで刻みを分割し、左状態到達とイベント適用を別の確定操作にする。
- EVENT-D02：受理ステップ・確定世代・イベントカーソル・出力カーソルを区別し、親世代と荷重・履歴の整合を検査する。
- EVENT-D03：方式別イベント再初期化を明示し、境界左右の保存・再開でイベントを一度だけ適用する。

[限定試験](records/q9-event-transaction-experiment.md) の検証範囲を超えて、製品時刻型・連成イベント・障害耐性を保証しない。
