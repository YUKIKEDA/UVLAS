## 1. 文書の関係と進め方

製品の対応範囲は `product-requirements.md`、決定履歴は `project-start.md`、性能試験は `performance-plan.md`、公開参照候補は `verification-resources.md` に置く。現在の作業順と開始判定は [実装前設計計画](preimplementation-plan.md) を優先する。本書の依存欄は概略であり、実装を許可する条件ではない。

従来のT02〜T04は設計範囲と完了証拠の指定が不足していたため、[設計決定台帳](../../docs/specs/design-decisions.md) と [契約・不変条件の作成要件](design-contracts-and-invariants.md) に展開した。連成系全体の問題定義から設計を進める。T05等の技術試作には事前の実験仕様を、T06以降の計算本体にはパッケージごとの開始判定を必須とする。内部・公開APIの互換性保証は開始しない。数式、契約、検証仕様を対応付け、結果だけから仕様を逆算しない。

Q27 Bの追加によりT03・T08・T09・T13・T15には、指定初期ひずみを含む材料・平衡・接線・固有特性・再開を含める。要求はMAT-02、設計・解析参照は `initial-strain-design.md`。製造工程解析や外部初期応力場の自動移送を追加したことは意味しない。

T03の進捗として `ancf-3423-formulation.md` に補間・参照写像・ANS/EAS・質量・内力・縮約接線と処理契約を記載し、固定版Chronoソースを照合した。曲面・層別EAS・初期ひずみ・部材接続の採用証拠は未完了で、T03完了やT08の実装開始とは判定しない。

## 3. 最初の着手チケット T01

目的：開発機でC++コードを確実にコンパイル・検証でき、同じ構成をWindowsとLinuxで追跡できるようにする。

入力：製品要求ENV-01/02。着手時点ではWindows環境にCMake、Ninja、Python、Gitと、VCツールを備えるVisual Studio Community・2022 Build Toolsのインストールを確認しており、実際のC++コンパイルは未確認だった。実施結果は本書の実施状況と検証記録を参照。

実施内容：

1. Visual Studioの開発環境を有効にして、コンパイラ・CMake・Ninja・Pythonの版を記録する。
2. C++20を初期候補として、コアライブラリ、CLI、テストを別ターゲットにした最小CMake構成を作る。両OSのコンパイラで必要な機能を確認し採否を記録する。
3. Configure/Build/TestのPresetを整え、ローカル固有の絶対パスを共有設定に入れない。
4. DebugとReleaseで実際にビルド・試験を行い、失敗が終了コードに反映されることを確認する。
5. Linuxで同じソースを確認する実行環境を確保する。未実行なら未確認と記録し、Windows成功だけでENV-02完了としない。
6. 依存は必要なものから版を固定して追加する。数値依存の採否はT05で実際の解法要件を確認する。

成果物：最小CMake構成、Presets、最小CLIと試験ターゲット、ビルド手順、版・実行結果の記録。ソルバーの物理機能や公開APIの実装はこのチケットの完了条件に含めない。

受入：クリーンなビルドディレクトリから同一手順で構成・ビルド・試験できる。Debug/Releaseを区別し、少なくともWindowsの実行記録がある。Linux確認を含めてT01全体の完了とする。既存ファイルの破壊、グローバル環境の恒久変更、ソフトウェアの無断インストールを前提にしない。
