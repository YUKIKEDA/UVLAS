# 証拠とレビュー所見

## 最初に主張を分解する

「同じ離散式に合う」「独立解に近い」「数値誤差が予算内」「実験と不確かさ込みで合う」「実務で使える」「規模・時間内で完了する」を別に扱う。証拠がどの主張に届くかを確認し、近い言葉に読み替えない。

## 試験の監査

入力・生成元・版・観測・基準量・閾値・実行条件・未達・修正版の関係を追う。反例が失敗すること自体が正しいtestもあるため、過去resultの`passed=false`を一律消す運用にしない。

期待値の生成経路を調べる。主実装と同じ剛性・同じ荷重関数・同じ核式を共有する比較は共通欠陥に弱い。解析解、独立体積／面力、別離散化、直接全系、別時間／周波数経路、精密評価から、今回の欠陥を検出できるものを選ぶ。独立コードに残る有限格子・コア・観測差を明記する。

数値予算は空間・時間・求積・核・後流・求解・固有抽出・縮約・入力変換の**合計**。全項へ同じ全体予算を配らない。非単調系列へ機械的外挿をしない。各観測を別に評価し、合力の合格で局所stress・ねじれ・位相を代替しない。

実験のsampling rateや計算コード間のばらつきは測定不確かさではない。センサー位置・軸・較正・同期・物性・支持・構成重量の不足を推測で補って判定しない。校正に使った点と独立validationを分ける。未知の不確かさを0にしない。

## Hash照合ツール

Python標準ライブラリだけを使う。例えば対象checkoutをrootに指定する。

```text
python scripts/check_evidence_manifest.py --root PROJECT_ROOT --manifest docs/verification/result.json
```

対応する参照は、トップレベル` sources / artifacts / immutable / status_sync_source `の`相対パス → SHA256`辞書、および旧形式の`artifact: {artifact: path, artifact_sha256: hash}`。参照するJSONも同じschemaで再帰照合し、循環参照を止める。生データartifactのJSON本文は再帰解釈しない。source側JSONを科学的result以外のschemaとして使う場合は、その違いを理解して適用する。

`--output relative/report.json`はroot内の新規ファイルへ保存する。既存ファイルを上書きしない。既定はstdout。`--max-files`で参照数上限、`--max-json-bytes`でJSON解析サイズ上限を指定できる。root外・不正hash・不正schema・欠落・改変は非zero終了。ソースを実行せず、ネットワークも使わない。

出力`integrity_passed`は指定された参照鎖のbyte一致だけ。元manifestの科学的`passed`／`all_checks_pass`は参考欄へそのまま残す。`scientific_acceptance`は常に`not_evaluated`。完全な依存記録、未記録ファイル、期待値の正しさ、実際にそのソースで実行したか、任意時点の改変防止は証明しない。並行変更中のcheckoutでは整合したsnapshotで再検査する。

## 所見の書式

```text
優先度・短い題名:
版・file/lineまたは式／契約ID:
発生する入力・状態・時刻:
実装の現在の挙動と必要な挙動:
破る不変条件と、結果／再開／性能への影響:
再現・独立参照・実行した検査:
必要な修正と合格を確認する検査:
不確実な点:
```

停止相当は、誤った物理結果を正常とする、状態を破損する、必須精度／範囲を黙って下げる等。影響条件を示し、推測だけで最重大としない。軽微な文体や命名と同列に並べない。仕様を守ると矛盾する場合は「仕様欠陥」とし、相反する箇所・最小反例・必要な改訂を示す。

結論は`対象gateを通せる / 修正まで保留 / 証拠不足で判定不能`等に適用範囲を添える。検査できなかった大規模性能・実験認定を、コードの見た目から合格にしない。
