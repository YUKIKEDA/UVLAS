# ソルバーR&D

成果は、採用できる方式、成立範囲を持つ棄却判断、または次の判断を可能にする原因識別。試験数・資料数・学習量を製品目的の代わりにしない。

## 進める

1. 対象用途、観測量、変えられない要求、現候補の未達、今回閉じる判断を抽出する。ユーザー決定と仮説を別記する。既知の回答を再質問しない。
2. 未達を「モデル・近似空間・離散化・求積／核評価・求解精度・観測／比較条件」に分ける。まず保存済みの解・行列・場から識別できることを調べる。
3. 次の実験では、対立する説明が異なる予測を出す最小問題を選ぶ。何が変わらなければ以前の不採用と同じ結果になるか説明できない案を、新候補として数えない。
4. 実行前に入力、参照、観測、閾値、資源枠、結果別の次行動を短く固定する。[実験・原因診断](references/experiments.md)を使う。探索的実行ならそう明記し、結果を見た後の基準を事前基準と呼ばない。
5. 成功だけでなく負対照・不成立・予算超過を保持する。閾値、比較する問題、観測、参照を変える場合は別版にし、元の未達を残す。
6. 採用／棄却／未解決、証拠の範囲、残る誤差群、次の決定を記録する。自律的に採否まで進み、ユーザー判断が必要な変更だけまとめて質問する。

## 堂々巡りを防ぐ

- 研究へ入る前に、既存方式が何を満たせず、独自案がどの条件を変えるのかを示す。独自研究も既存方式への回帰も、それ自体を解決としない。
- 原因を変えない細分化は、漸近性の検査や精度切り分けとして必要な場合に限る。必要な計算量が資源内に収まる見積もりと終了条件を置く。
- 重要な未解決を残して別分野を進めても、重要問題が解消したと報告しない。独立作業は進めてよいが、依存する最終判断は開いたままにする。
- 「不合格→原因仮説→識別証拠→変える条件→次の合否」の連鎖が切れたら、追加計算前に整理する。[研究制御](references/research-control.md)を読む。
- 対象方式を実装するための決定的な試作と、製品実装後の網羅試験・実務受入を区別する。全製品を別言語で先に完成させることを開始条件にしない。

## 返すもの

今回の判断と根拠、未達を保った記録、方式の適用域、残る判断、更新した全体の現在地。見通しは未解決の仮説・必要実験・依存で説明し、文書数や完了段階数から製品完成率を作らない。

数値閾値、要素・言語・時間法は対象プロジェクトの採用仕様から取得する。このskillはUVLMやANCFの採用を強制しない。
