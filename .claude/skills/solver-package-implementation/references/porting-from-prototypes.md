# 試作から製品へ

研究試作は、方式が成り立つことを示すために書かれている。製品が守る契約を満たすようには書かれていない。

## 移すもの

- 式と、その導出が合っていることを示した数値。
- 独立参照として使える入力と結果。凍結された版を、ハッシュを添えて試験のfixtureにする。
- 負対照と、過去に未達だった条件。未達が直ったことを回帰として確かめる。
- 閾値、反復上限、資源枠の初期値。出典を付けて移す。

## 移さないもの

- 全体を密に持つ参照用の実装（密なnullspace、密な平方根、全状態の密行列）。小規模の照合にだけ使う。
- グローバル変数の差し替えで条件を切り替える構造。
- 例外やassertで止める失敗処理。製品では区別された失敗を返す。
- 試作の言語や浮動小数点設定に依存した挙動。製品の設定で同じ結果になることを確かめる。
- 旧い候補や、採用されなかった時間法・初期化。現在の採用仕様と追加規約の優先関係を先に確かめる。

## 確かめること

- 試作が通ったことは、製品の試験が通ったことではない。製品の経路で同じ参照を満たすことを別に示す。
- 試作と製品が同じ誤りを共有していないか。参照が試作と同じコードから作られているなら、独立な参照を一つ足す。
- 試作の結果を使うとき、その結果がどの版の入力・ソースから出たかを辿れること。辿れない数値をfixtureにしない。
- 試作の合成問題（規則的な疎行列、小さい格子）で測った時間とメモリを、製品規模の性能の証拠にしない。

## 記録

fixtureごとに、元の記録の識別子とハッシュ、移植時に変えた点（単位、成分順、精度）を残す。元の記録は書き換えない。差が出たら、試作の欠陥か、製品の欠陥か、仕様の欠陥かを分けて報告する。
